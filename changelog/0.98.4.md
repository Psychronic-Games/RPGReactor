# RPG Reactor 0.98.4 - 2026-08-31

0.98.3 let you rig and animate 3D models inside the editor; 0.98.4 puts them in the world and makes the world behave. Height is a real coordinate for every event and prop; placed models get ghost previews, undo, a transform card, mesh-accurate collision, and a passage view; Effekseer effects and video surfaces live inside the 3D scene at true depth; Scoped Wait and queued model animations let events act without freezing the player; Show Text edits whole conversations with a live in-window miniature; a new import optimizer shrinks GLB models with no visible quality change (the bundled demo went 469MB to 168MB); fullscreen renders 3D at native resolution while UI stays smooth; and a stack of community-requested database features landed alongside a weekend of release-hardening fixes. Built on PixiJS 8 for 2D and Three.js for 3D.

### Fixed
- **Old installs launch again, and can never be bricked this way twice.** Every build ever shipped shared one Chromium profile (the manifest name `rpg-reactor`), and Chromium migrates that profile forward only — so after any newer-runtime build ran once, every older-runtime build after it died on a fatal profile-schema check with exit code 0 and no window, while working perfectly on clean machines. Shipped editor builds now start a brand-new profile every release (`rpg-reactor-0.98.4-nw0107`), so no stale profile state of any kind can eat a launch again — which also self-heals every currently broken install (preferences re-seed once per release until the file-backed settings store lands), and the packager refuses to ship a runtime older than the newest ever shipped. Deployed games get the same protection: a game's profile is scoped to the runtime it bundles, so shipping an update with a different runtime can never brick a player's install — desktop saves and config are files in the game folder and are untouched.
- **The Windows editor package launches.** Every Windows package since 0.95.0 carried a stray file literally named `nul` (a shell-redirect accident in the Demo's data folder). Windows reserves that name for the null device, so NW.js's payload self-extraction died on it and the editor exited with no window and no error — while Wine, which reserves nothing, ran the same build fine. The file is gone, the packager now refuses any Windows-unsafe file name (reserved device names, `<>:"|?*`, trailing dots or spaces) with a loud list of offenders, and a repo test keeps tracked files and packaging inputs clean.
- Resizing a 3D game no longer blinks the ground out for a frame or logs a spurious "destroy() leak" warning (runtime `20260830.36`): the old render-pass textures were destroyed the instant a resize rebuilt them, one render ahead of the sprites that still showed them — they now retire two frames later, after every pass sprite has rebuilt.
- Browser playtests run at full speed (runtime `20260830.35`): the web editor's playtest overlay used to leave the editor's own canvas and 3D view rendering behind the game, burning the same GPU — both now sleep until the overlay closes. Native-resolution 3D also drops multisampling from 4x to 2x once the display scale reaches 2x (the pixels already quadrupled there), and a project can trade the sharp enlargement back for frame rate with `Graphics.maxCanvasPixelRatio = 1`.
- Browser games launch scaled to their window (runtime `20260830.34`): stretch mode defaulted on only for desktop and mobile builds, so a web playtest (itch embeds included) opened at native game size until someone found F3. It now fills the window from the first frame everywhere; F3 still toggles 1:1, F4 fullscreen — both stay sharp through the new native-resolution scaling.
- The web editor's console stays clean through a playtest (runtime `20260830.33`): video surfaces no longer report a red `AbortError` for every scene switch (an aborted `play()` is teardown racing playback, not a failure), promise rejections routed through `SceneManager.onError` no longer print `undefined undefined` under themselves, and the map view's Effekseer effect preview no longer errors on the web — the first attempt warms the effects folder into the sync cache, the effect plays as soon as it lands, and its textures encode correctly (the web host returns plain byte arrays, whose `toString` produced comma-joined decimals instead of base64 — every texture data URL was `ERR_INVALID_URL`). (A single BGM 404 per track can still appear on web: audio references are stored extensionless and the browser probes formats in order — the request after the 404 is the one that plays.)
- Opening a project while another was already open could show the new project's first map black until switching away and back (GitHub testing report): the switch never disabled the previous project's 3D view the way closing does — three.js kept the shared canvas while the new map loaded — and the 3D camera kept the old project's framing key and orbit, aiming at the previous map's last-viewed spot. The switch now starts from a cold 3D viewport, re-frames, and clears the cross-project event-model preview cache (two projects sharing a model name showed the first one's mesh).
- Enemy action Target State conditions could never fire on a skill whose scope a plugin rewrote to a `<Target: ...>` string (GitHub #33): candidates were grouped by numeric scope lists, so those skills silently had none. Candidates are now grouped by asking a probe `Game_Action`'s own isFor* predicates, which inherit any plugin redefinition; numeric scopes group exactly as before.
- Action ratings are 1–9, as RPG Maker authors them, not 1–10 (GitHub #33): label, input cap, and clamp across all 17 locales.
- Resizing or fullscreening a game with a full-screen filter running (Haven's encounter Pixelate, any MV/MZ transition shader) logged `[BindGroup] a 'textureSource' was destroyed while still bound to a shader` pairs: the texture-pool shim destroyed a stale-sized pooled texture mid-render while last frame's filter still held it in a bind group. The stale texture now retires quietly — out of circulation at once, destroyed two frames later when nothing references it (runtime `20260830.31`).
- Toggling fullscreen (F4) while a screen tint or other filter ran could freeze the game with `Cannot read properties of null (reading '_resolution')`: PIXI v8's filter stack keeps entries whose input texture died with the old render targets, and every later frame crashed on them. `pixi_compat.js` null-guards `FilterSystem._findFilterResolution` so a dead entry falls back to the root resolution (runtime `20260830.30`).
- Clicking beside a dialog no longer closes it — anywhere. The event editor discarded a whole page of in-progress work on an accidental backdrop click, and a hundred other dialogs shared the gesture; every editor, picker and command dialog now closes only through its own buttons. The plain confirm/alert boxes keep click-away-to-cancel, since they hold nothing to lose. A test keeps the pattern from creeping back.
- The message overflow marks are now pixel-identical to the game, proven inside the running engine: the punctuation codes (\. \| \! \> \< \^ \$) measured as drawn glyphs and pushed the mark a whole word early on pause-heavy lines. A code-laden sample now measures 1300px in both the game renderer and the editor scanner, overflowing at the same character.
- The message overflow marks now use MZ's exact window arithmetic, verified against the running game: box width is the UI area minus its 8px margin, window padding is 12 a side, and text starts 4px in (164px beside a face) — plus the measurement font is force-quoted so the project font can't silently fall back to a wider one.
- Editing a multi-box message run is consistent from any box: double-clicking the second or third box used to open a run missing its earlier boxes (the collector only walked forward) while always landing on the first box. The whole conversation now opens wherever it's clicked, on the box that was actually hit, and saves replace the run from its true start.
- The Show Text editor now marks overflow the way the game actually draws: instead of one yellow ruler column, each line is measured with the project's font and resolution — escape codes cost nothing, icons cost their pixels, actor/currency codes measure as what they'll say — and only the characters that genuinely won't fit in the message window are highlighted (tooltip shows the pixel excess).
- Touching a second event while another's background wait holds no longer freezes you until the first finishes: the waiting script parks onto its own runner (carried in saves) and keeps going on the side, the map interpreter is handed over fresh, and the new event runs — and locks — purely on its own merits. Touch the tank, walk away, poke the plant monster: each behaves as if the other didn't exist.
- Clicking a 3D-previewed event model no longer makes every event outline and label vanish until a restart — the selection highlighter crashed on the model's material-less root. Previewed models are now properly clickable: the click selects their event (box-picked, cheap on heavy meshes) and the drag arrows mark the selection.
- Deleting or editing an event in the 3D view no longer makes every model on the map blink and reset — the view diffs per event and rebuilds only what actually changed. And with a 3D map object selected, the **Delete** key now deletes that prop (undoable with Ctrl+Z) instead of asking to delete the whole map.
- The background-wait freedom held a trap: walking into (or pressing action on) an event whose script was still holding re-armed it every frame, and that stuck flag froze the player after all — live-diagnosed with a stack trace on the Demo tank. An event whose own script is running can no longer be started again.
- Play Model Animation's *Wait for Completion* no longer freezes the player either — watching a model animate is background work, in line with Scoped Wait; freezing on purpose is what the stock Wait command is for. (Verified end-to-end: walking to the Demo tank and triggering its full sequence leaves the player free.)
- Scoped Wait's switch and variable are chosen from the real picker (names, not raw numbers), the dialog's rows line up on one grid, and the command moved to a new **Game Flow** category in the picker — the future home of flow tools like the quest system.
- Scoped Wait also gets a "This event keeps moving" toggle (default on): the waiting event resumes its own route during the hold, or stands locked the classic way when unchecked.
- Scoped Wait grows two more conditions: hold until a **switch** flips (ON/OFF) or a **variable** compares true (≥ > = < ≤ ≠) — still a background wait, so it doubles as "resume this event when X happens" without freezing anyone; those two carry no time cap.
- **Scoped Wait** replaces Wait for 3D and becomes a general tool: a *background* wait — the player keeps moving while it holds, and the waiting event resumes its own route. Watch a target's last actions (animation queue, forced move route) for This Event / Player / a specific event / Everything, or hold for a custom duration in frames. Events saved with the short-lived Wait for 3D keep working.
- New event command **Wait for 3D**: hold the event until model animations finish — this event's, the player's, one event's, or everything on the map. Pairs with the queueing Play Model Animation: fire a sequence, keep the player free, and wait only where the script actually needs the sync.
- Play Model Animation commands now queue: several in a row play one after another on the model, so an event can fire a whole sequence and end immediately — no Wait commands between them, and the player is never frozen while an object goes through its motions. A repeating play yields to the next queued one after its current cycle; playing an empty name stops everything.
- Animation flash timings on Effekseer animations now offer all three choices — Target, **Screen** and **Hide Target** were greyed out before (the scope rides the saved timing and the runtime honours it). **Play Model Animation** gains a *Wait for Completion* checkbox: chained commands play one after another; a repeating animation releases the wait after its first full cycle, and a name the model doesn't have can't hang the game.
- Big models can turn like they drive: a turning model event used to reserve a full disc of its corner radius — a nineteen-tile tank couldn't face a new direction with anything standing ten tiles off its bow. The turn now blocks only the arc the body actually sweeps through (sampled against the real mesh footprint), and things vertically clear of the model — a wall light overhead — no longer block it at all.
- Turning the 3D view off no longer leaves the 2D map showing a cropped corner until a manual zoom — the renderer re-crops and redraws from the live layout automatically.
- Reactor route steps in the event command list now say what they do (Rise, Face Ceiling, Rotate: 90°…) instead of showing the marker script, and the Set Movement Route dialog spreads them across its columns — vertical steps under the moves, poses under the turns — instead of piling them all into the last one.
- A placed model's chosen animation now plays whatever its "Play when" says, and its **Repeat** checkbox actually loops it — in game and in the map editor. An animation authored as Always used to extend once and freeze when a placement picked it, because the placement fired it as an action no rule answered to. Keyframes are no longer an on-demand-only feature (an Always timeline loops on its own), a video placed on the whole model is claimed by a part later carved around it, and deleting a part hands its effects back to the model without moving them.
- The whole model is a part from the moment it's imported: the 3D Models parts list opens with a **Whole model** entry — pose it, animate it, anchor effects to it, no triangle-carving required (carved parts are for pieces that move on their own). And a whole-model pose now carries its effects with it: an effect anchored to the model at large rides the animation root, so a video on a leaning console leans too.
- Two more reasons a part-anchored video could refuse to track, both fixed: a piece carved where two parts overlap is named after only one of them, so the anchor lookup could miss the binding entirely (it now finds pieces through their owner list); and effects saved before anchors bound to parts are quietly rebound, on selection, to the part that contains their point — the screen claims the video sitting on it.
- Placing an effect anchor in the 3D Models editor now binds it to the part you click — a video placed on a screen rides the screen. Anchors used to stay bound to the model origin unless a dropdown was changed by hand, so nothing ever tracked a moving part; switching the anchor part in that dropdown now keeps the dot in place instead of jumping.
- A video surface anchored to a model part now turns with that part — a screen on a swinging monitor arm keeps its movie on the glass in game, in the map view and in the database preview (the plane only followed the anchor point before, never the part's rotation). Renaming a part now carries the effects anchored to it (a renamed screen's video silently fell back to the model origin). On the map, a facing-turned model's pose rings now sit on the axes the drag will actually rotate.
- Database 3D Models editor: selecting a video effect now shows the movie on its surface immediately (no Play press) and keeps playing smoothly — it counted as idle before and throttled to a slideshow; clicking the model no longer dismisses the effect's placement card (a whole-object part had made every click a dismissal, which read as the offset/size panel going missing); the database section is named **3D Models**.
- Light pools and beams now lie flat on the ground as real 3D shapes instead of camera-facing billboards — no more glow stickers hanging in the air or floating onto the wall you face; a flashlight is a wedge of light along the floor. Move routes gain **Face Ceiling**, **Face Ground**, **Stand Up** and **Rotate…** — lie a character in bed or flat on the floor, or turn them to any angle; sprites rotate on screen, models fall onto their back or face and roll the same way.
- RaveLighting in 3D: flashlights and beams pointed mirrored east-west (the shim fed the plugin's clockwise angle straight into the scene's east-positive aim), and lights glowed through walls. Beams now stop at the first wall they hit and a lamp in the next room stays there — a cheap height-aware march over map cells, no raycasts (`Reactor3D.LIGHT_OCCLUSION = false` restores the old glow-through look).
- The selected 3D map model now has drag arrows like events (slide it along X or Y, lift it with the vertical arrow), and the transform card's first tab says **Coordinates** — it is the model's place on the map, not an offset.
- Facing dots in the model picker now snap to the model's nearest side (within 15 degrees), so "this side is Left" comes out exactly sideways instead of baking in the small angle of the click; ring rotation in the picker no longer stutters on heavy models; and editing an event's model updates the 3D view immediately instead of waiting for a restart.
- **Height is a real coordinate in 3D maps.** Every event and prop has a Z in tiles: the Event Editor's Position row is now editable X/Y/Z; events stand at their height in the 3D view and in play (billboards and models alike); the selected event grows drag arrows in the 3D view for X, Y (height) and Z; the grid draws a second plane at the selection's level with its column corners; move routes gain **Rise**, **Descend** and **Set Height…** (smooth, waitable, saved as guarded Script steps RPG Maker ignores); collision is by vertical overlap, so a scaffold overhead blocks nobody and a raised model casts no ground footprint on the passage view. On a flat map an event's height is kept and does nothing.
- **The placement ghost moves smoothly.** It followed the cursor at the prop-picking throttle's 30 Hz while the view drew at 60; the pick stays throttled, the ghost does not.
- **The placement ghost no longer flickers in 3D.** The flat map's hover handler, still hearing the pointer under the 3D view, hid the ghost whenever the raw cursor fell on a 2D prop sprite; it now leaves the ghost to the 3D view while that is up.
- **A transform card in the 3D-M panel.** Offset (X/Y on the map, Z lift), Rotate (yaw/pitch/roll) and Scale (one Size, or per-axis X/Y/Z with Proportional off) as sliders with a number beside each; a drag moves the selected prop live on the map and in 3D and is one Undo step. Props can now be stretched per axis (`stretch` in the sidecar, used in play, in the editor and by collision).
- **Placing a 3D prop can be undone, and previewed.** Prop edits share the map's Undo/Redo (toolbar and Ctrl+Z), so a misplaced model steps back like a painted tile; with a model chosen, a half-seen copy follows the cursor over the ground in 3D and over the tile on the flat map, showing what a click will place.
- **New event command: Transform 3D Model** (3D section). Pick a model event, the player, or a placed prop; give an offset in tiles, a turn in degrees, and a scale (one, or per axis); ease there over a number of frames, optionally waiting. Laid over the model's placed pose, carried in the save, and the game's collision stays where the model was placed.
- **Dropdowns show the value they hold.** The editor's themed dropdowns draw their own label and refreshed it only when you picked something; a value set by the editor itself (the 3D-M panel showing a selected prop's Facing, Animation or Effect, and every other panel that fills a dropdown from data) left the old label on screen, so a prop facing right read "Down". The label now follows the value wherever it is set.
- **The 3D-M tool works again after a visit to the Event tool.** Leaving event mode with the 3D-M tab still selected now re-arms the props tool (it is dropped on the way in so the Event tool owns the pointer); before, props could not be clicked until the tab was re-selected.
- **A freely placed prop blocks exactly what the editor shows.** In play, a model's footprint was tested from two centres, its real position and its rounded tile: right for an event mid-step, wrong for a prop standing still between tiles, which came out half a tile wider on one side than the editor's red squares (the Demo's left console kept the player a tile away). A stationary character now blocks only from where it really is.
- **The Passage toggle no longer freezes the editor.** A model's footprint was traced triangle by triangle through a hash set: three million triangles on the Demo reactor, a two-to-three second stall. A dense model's outline is now read from a sample of its vertices into a byte grid (the same footprint, 4 ms instead of 260 ms on a three-million-triangle mesh); low-poly models keep the exact triangle trace.
- **Passage marks in the 3D view and for model events.** The Passage toggle now draws in the 3D view too (X marks and red edges on the ground, red under model footprints), events whose page carries a 3D model show their footprint like props do, and passability edited in Database → Tilesets redraws the marks when you return to the map. Model bindings in the database say "Model size" rather than "(tiles)".
- **A Passage toggle on the map header.** Like RPG Maker's passage view: an X on every cell nothing can walk, a red edge on a side that cannot be crossed, and red under the tiles a placed 3D model blocks, read exactly the way the game reads them (layers top down, star tiles skipped, bare room floor walkable), redrawn as you paint or move props.
- **Bare floor in a 3D room is walkable.** RPG Maker treats a cell with no tile as impassable; in a room the parallax plane is the floor, so a model standing on unpainted floor was ringed by a room's worth of invisible wall. The Demo's reactor sat in such a ring.
- **The Event tool no longer places 3D props.** With the 3D-M tab's model chosen, switching to the Event tool left the props tool holding the pointer, so a click placed a model instead of selecting an event; each tool now takes the pointer from the other. Editing a prop's Size no longer stalls the editor: the footprint mask is built once per pose and shared by the 3D view and the flat map, with numeric cell keys (a string per sample was most of the build on a three-million-triangle model). The 3D-M panel's Size label no longer says "(tiles)".
- **3D model collision matches the model.** A placed model blocked every tile within a third of a tile of its mesh, so a console 1.6 tiles deep blocked a 3×3 square and the player was held a whole tile away from everything (the "invisible walls"); a box's vertical walls also leaked a quarter tile past the model. A tile is now blocked when the mesh covers its middle or at least half of it, so a long car blocks its long footprint and you can stand beside a console. The 3D-M panel has one **Size** (the model's longest side in tiles; an old prop's Scale folds into it), and the selected prop's blocked tiles are drawn in red, in the 3D view and on the flat map, so the footprint is seen, not guessed.
- **Smoother 3D previews.** The Database 3D preview and in-scene effects looked at their own pixels every ten frames to learn where an effect's picture ends and how far it reaches; that readback stalls the GPU. It now stops once learned (the first two plays; a settled reach checks a third as often).
- **Model effect and rule edits reach the map's 3D view at once.** Saving a model in Database → 3D (an effect's trigger, its anchor, a rule) rebuilds the map view's placed copies of that model; they kept the sidecar they were loaded with until the editor was reopened. Placing more of the same model keeps the panel's chosen Animation and Effect (re-picking the model reset them to none), and the Effect list marks the ones that play on their own, e.g. `Animated Screen (always)`.
- **Editing a placed 3D prop transforms it in place.** Size, Scale, Facing, pitch/yaw/roll, Lift and position edits in the 3D-M panel now re-pose the instance already in the 3D view (its effect keeps playing and follows), instead of rebuilding every prop on each change; only a new, removed or re-modelled prop, or a changed animation/effect, rebuilds.
- **Editing a 3D prop's Size or Scale no longer whites out the editor.** Each edit rebuilds the prop's effect preview, and the old preview kept its WebGL context until the browser got around to collecting it; sixteen edits hit Chromium's context limit, the oldest live contexts were evicted, and the map's 3D view (and the whole screen) went white with "Too many active WebGL contexts". A disposed preview now hands its context back immediately.
- **Model effects are as sharp in play and in the map's 3D view as in the database preview.** The game drew an Effekseer effect anchored on a model at half the screen's resolution and stretched it over the whole screen; the map editor's 3D view drew it into a 512-pixel square. Now the game draws only the box the effect actually fills, at full resolution (it learns the effect's reach from what it draws, in world units, so the box stays right as the camera turns; only a screen-filling effect is drawn smaller, within the same pixel budget as before), and the map view draws it at the view's own resolution, from the same frame as the view. Effects on models track their anchor through camera moves as they did.
- **Repeating effects no longer pause between plays.** A looping model effect (Always, Repeat), the map view's preview and the Animations page's Repeat all waited for the effect's last invisible particle to die (and the Animations page a further 100 ms) before starting over, a 1–2 s dark gap. They now start the next play where the picture ended, learned from the play itself, so a loop runs continuously.
- **A picked autotile piece is stamped as picked.** Right-clicking one autotile cell selects its kind for ordinary painting (re-shaped as it is placed) and now also remembers the exact piece, so Shift+click stamps that corner verbatim, as RPG Maker does; before, Shift+click stamped the kind's plain centre.
- **Conditional Branch looks like RPG Maker's.** The dialog is now the familiar four numbered tabs, every condition on screen as a radio row with only the chosen one's controls live, switches and variables shown as `0001 Name` buttons that open the picker, Timer as minutes and seconds, Include Equipment under Weapon and Armor, and Create Else Branch in the footer. Reactor's own input conditions (keyboard held/released, mouse buttons, wheel, pointer position) moved to a fifth **Reactor** tab and still save as the same Script condition RPG Maker runs. Opening an existing branch lands on its tab with its row chosen; OK on an untouched branch changes nothing on disk.
- **Plugins that write `filter.uniforms` on the PIXI 8 runtime no longer crash** (GitHub #28). `ColorFilter` is a `ColorMatrixFilter` on PIXI 8 and had no `uniforms`; the MZ-era idiom `filter.uniforms.colorTone[i] = x` (six of VisuMZ_4_EncounterEffects' ten battle transitions) threw. A `uniforms` view now writes through to the colour matrix.
- **The 3D view orders a model map by depth, everywhere.** On a map with models, the editor's 3D view (and the game) draw star tiles, above-characters screens and model effects under one depth buffer, so a screen or an effect behind the reactor tower stays behind it as you rotate; the 2D "upper layer" convention still applies to maps of flat sprites.
- **Model effects sit inside the 3D world.** An Effekseer effect anchored on a model is now drawn from the 3D camera at its world anchor and placed in the scene at the anchor's depth, so the tower's struts, a wall or a character standing in front hide it and it tracks the model exactly as it moves — instead of a flat overlay painted over everything from last frame's camera.
- **Show Text edits whole conversations, with the text-code menu and a real preview** (GitHub #29). The dialog edits a run of consecutive message boxes as a strip (add, remove, reorder; no more silent four-line truncation — overflow becomes more boxes, and it says how many before OK), right-click on the text or name gives RPG Maker's Cut/Copy/Paste/Select All/Insert Color/Insert Icon/Insert Control Character/Plugin Help menu, the preview is drawn with the project's own windowskin colours, and the code reference lists what applies: vanilla codes, VisuStella MessageCore's when it is enabled, and the project's own custom codes. Troop battle events can open Show Text at last. Opening and OK-ing an untouched message changes nothing on disk.
- **Text codes on database descriptions and messages** (GitHub #30). Skill/Item/Weapon/Armor descriptions and Skill/State messages carry the same right-click menu and a collapsed reference panel listing exactly what a help window or battle-log line honours, with the `%1`/`%2` placeholders each field takes. Skill Message 3 and 4 now mean something: 3 is shown when the skill connects, 4 when it misses or has no effect.
- **Grow reaches Max TP and can roll a range; Change Parameter too** (GitHub #15). The Grow effect lists Max TP as a ninth target (its own accumulator, so actor stats are untouched) and a Random row draws the amount between two ends; the Change Parameter command gains Max TP and a Random operand, rolled once for everyone it changes.
- **Add State can set its own duration** (GitHub #16). An Add State effect's Duration row overrides the state's Min/Max Turns for that skill or item, fixed or as a range; effects from RPG Maker keep the state's default, and a state that is never removed automatically says so instead of offering the override.
- **Enemies: Max TP, steadier drop slots, boxes sized to their numbers** (GitHub #31). Each enemy can have its own Max TP (a row under Max MP; unset enemies keep the engine's 100), drop slots sit on two fixed rows with a live chance readout beside `1 / X`, and parameter boxes size to their digits.
- **Referenced by** (GitHub #23). Right-click any database entry → Referenced by lists every other database record that points at it — actor classes and equipment, class learnings, skill/item animations and effects, traits, enemy actions and drops, troop members, page conditions and event commands, common events, the starting party — grouped by section, each row opening the record. Notes and map events are out of scope.
- **Plugin command file pickers list only what the folder holds** (GitHub #7). A `@dir img/…` argument browses images, `audio/…` audio, `movies` videos; a folder-less argument still lists everything.
- **Enemy actions can require a state the user or a target does *not* have** (GitHub #32). User Lacks State and Target Lacks State join the action condition checklist as rows of their own, so "enraged but not silenced" is one action.
- **Play Model Animation picks from the model's own actions.** The animation is a dropdown of what the target's model declares (the event's bound model, or the party leader's for Player), updating as the target changes, instead of a typed name.
- **Preview Event and the 3D view.** A model preview chosen while editing in 3D shows immediately (it used to wait for the next project open), and each map now remembers whether it is edited in 3D: reopen the project and a 3D map comes back in 3D, switch to a map left in 2D and the view follows.

### Added
- **3D maps open in 3D.** A map authored in 3D (its sidecar says so) now opens in the 3D editor view the first time it is visited — the browser Demo's first impression is its room, not the flat projection. The per-map memory still wins: turn 3D off and it stays off for that map.
- **Live message miniature.** The Show Text editor draws the box being edited right under the text field — windowskin, face, name box, colours and icons resolved, in the project's own font and resolution. It follows the caret: with more lines than one box holds, the box under the cursor is the one shown, updating as you type.
- **The game stays sharp (runtime `20260830.29`).** Two blur sources gone. The adaptive resolution controller — which dropped the 3D render scale under load and upscaled the result, a blur layer that lingered until things calmed down — is now opt-in (`Reactor3D.adaptiveResolution = true`) instead of always on. And fullscreen no longer stretches the finished frame through the browser's bilinear filter: the canvas backing store renders at the on-screen size (`Graphics.canvasPixelRatio`), so 3D geometry comes out native-sharp while windows, text and pictures keep their smooth enlargement. Shrinking below native is unchanged.
- **3D models get smaller on import.** Importing a GLB now offers Optimize (recommended): textures capped at 2K, skin weights packed to 16-bit, unused tangent data dropped, duplicate vertices welded — no visible change — or an aggressive mode that also simplifies the mesh. Cancel still aborts, Import as-is keeps every byte. The Demo's own six big models went 469MB → 168MB this way.
- **Video effects keep their size on the model.** A video surface effect's width and height are fractions of the model's size (0.3 = a screen a third as wide as the model), so it is the same size relative to the model in the database, the map editor and the game, and the scale slider works on it; older pixel values are converted on load.
- **Effects on models are drawn at the world's scale.** An effect anchored on a model now shrinks and grows with it in play (it played at flat pixel size, so a reactor's core covered the screen) and turns with the model; the database and map editors preview it at the same size the game draws.

Sprite cells honor their blend mode and head/center/feet/screen anchor for drawing, picking, and dropped coordinates; static previews refresh after frame or timing edits, strips remain pixel-crisp, and a deliberate zero SE volume is preserved.
- **Plugin schemas and MZ command blocks are handled end to end.** GitHub issues #18 and #22 now share annotation parsing, typed widgets, and complex-value encoding across Plugin Manager parameters, nested structs, and plugin command arguments. Choice controls, all 19 database/System reference types and their array forms, colors, authored Boolean labels, multiline values, nested structs, and `img/...` file fields preserve RPG Maker's string/JSON storage. Image fields use the recursive folder browser with a dimensioned preview on desktop and Web, including encrypted assets. MZ commands save readable code-657 argument rows in declaration order, preserve unknown authored rows when metadata is partial, and treat each 357/657 block atomically during edit, insert, copy, cut, delete, and paste on maps, Common Events, and Troops. Malformed complex values remain raw-editable, Cancel is non-destructive, and omitted Boolean/number values materialize as the values shown by their controls.
- **Desktop asset URLs preserve every filename character.** From GitHub issue #21: the central desktop asset resolver now produces standards-compliant `file:` URLs for POSIX, Windows drive, and UNC paths. Character, face, battler, tileset, database-icon, event-face, and shared IconSet previews route through it, so spaces, `#`, `%`, `?`, and Unicode are escaped without changing encrypted `data:` URLs or the Web editor host resolver.
- **Asset pickers show the project's real folder tree.** GitHub issue #20 adds one arbitrary-depth folder model to the shared searchable browser and Audio Picker. Folders sort before loose files, start collapsed except along the current selection, count all descendants, filter without empty branches, and expose accessible mouse and keyboard controls. Rows display basenames while preserving complete relative paths. Character, tileset, generic database image, title image, model, and message-face pickers opt into the same tree; flat directories retain their letter-section layout.
- **Scaled PIXI 8 windows clip once, not scale-squared.** From GitHub issue #19: filter rectangles now round-trip both position and dimensions through the client area's transform. Half-scale windows no longer clip to one quarter of their intended area; plugin-provided world-size rectangles, stock-style unscaled rectangles, reflected/rotated transforms, and zero scale remain finite and safe.
- **User Interfaces editor UX.** A single compact toolbar now holds only Name, Presentation, the searchable Custom-default Use As combobox, Interface Settings, and Playtest. Interface behavior, transitions, and notes live in the Inspector, which starts in Interface Settings, switches to the selected layer, and becomes a contained drawer at intermediate widths instead of adding a row below the workspace. Practical desktop widths show Layers + Layout + Inspector in one row; every layout uses the remaining bounded height. Layers remain Back -> Front with subtree-safe reorder/reparent, concise accessible order controls, and a reachable Game Reference tray with explicit front-appending imports.
- **Browser saves and Reactor sidecars protect authored work.** Normal Web-editor Save now waits for IndexedDB to finish before reporting success; quota and transaction failures keep the project dirty and produce an error instead of reverting silently after reload. Reactor's 3D database, map, tileset, model, and rig sidecars now use atomic desktop writes, and malformed or unreadable sidecars are preserved rather than treated as empty data that the next edit may replace.

- **The User Interfaces tab fits the screen, and a capture is a reference, not a save.** From owner passes on Windows and Linux NW.js. The workspace takes the height the window has and the canvas scales to fit both ways; interface-level fields are in the independently scrolling Inspector rather than consuming the top of the editor. Pressing Delete after clicking a node or a captured window no longer clears the *database record*. A capture is scoped to the open record, has an explicit **Clear** action, never saves the project, and **Add Box** uses the captured window's rectangle and skin opacity.
- **Less for a weak GPU to do.** Four changes aimed at what hurts integrated graphics. Every window clipped its contents with a filter, which is a render-to-texture pass per window per frame; on PIXI 8 windows now clip with a stencil rectangle instead (same picture, one fewer full pass per window). Character billboards on 3D maps read one shared texture of their sprite sheet and pick the frame with texture offsets, instead of copying every frame change into a canvas and uploading it. The world's meshes are frozen once built so three.js stops recomposing their matrices every frame. Model textures larger than 2048 pixels are resampled down at load (`Reactor3D.maxTextureSize`): a car or a character that is a few hundred pixels tall on screen does not need a 4K sheet in video memory.
- **Less garbage per frame in 3D games.** A heap profile of the Demo showed 250 MB allocated in eight seconds of walking, most of it objects made and thrown away every frame, which is what turns into stutter on machines with less headroom. The biggest: three.js rebuilding shader parameters every frame for double-sided transparent materials it draws twice (the world's flat tiles and billboards now draw in one pass, identical picture; additive lights keep both), event notes re-parsed by regex every frame for every character, sidecar model specs re-validated every frame, `Point`s and `Rectangle`s built through the ES5-to-ES6 bridge (now plain field writes on PIXI 8), the window cursor and filter measures creating rectangles and points every frame, per-sprite projection scratch vectors, and the hidden 2D tilemap still painting tiles under a 3D map. A second pass pooled the per-rule vector math behind model animations, made sprites move their texture frame instead of building a new texture every animation step (walk cycles, window cursors, pause signs), reused projection records, and stopped the bundled EventCustomizer plugin rebuilding the whole event list twice per event per frame. Down to 146 MB over the same eight seconds, with the map pixel-identical.
- **3D scales itself down on machines that cannot keep up, and idle previews stop burning the GPU.** The 3D passes now render at an adaptive resolution: a game averaging under 45 fps drops the 3D to three quarters, then half, of the screen size (with less antialiasing to match) within about a second, and climbs back a step at a time once it holds 57 fps for five seconds. The 2D layer, text, and windows stay sharp throughout; only the 3D picture softens. `Reactor3D.renderScale` caps it (or fixes it, with `Reactor3D.adaptiveResolution = false`). The bundled RaveLighting plugin draws its light overlay at half resolution and only redraws when a light or the tone actually changed (animated lights at 30 Hz), eight times less upload traffic. In the editor, the Database 3D preview, the model picker, and the 3D map view repaint ten times a second while nothing moves instead of at the full refresh rate; orbiting, flying, editing, and animated models keep the full rate.
- **3D maps no longer copy their picture into the game every frame.** The 3D view used to be rendered on a second canvas and then, up to three times a frame, drawn onto a 2D canvas and uploaded to the game renderer as a full-screen texture. Now three.js renders with the game renderer's own WebGL context into render targets, and the game samples those textures directly: no copies, no uploads, the same pixels (verified identical against the old path). Weak GPUs feel this most. 3D battlers take the same route: each rendered into its own target on the game context instead of a private renderer copied through a canvas every frame, and the target is freed with the sprite. The old path stays available with `?r3dcopy` on the URL or `Reactor3D.useSharedContext = false`, and is used automatically when the renderer is not WebGL2.
- **3D models no longer hitch the game as they step into view or a battle opens.** Profiled in the Demo with a frame-gap probe and a CPU sampler while walking and starting a battle, three costs were landing on the main thread every time a model instance was created: cloning a template ran its textures through JSON (three's `Object3D.copy` serialises `userData`, and a texture's `toJSON` encodes its whole image to a data URL) for up to half a second per character; three's renderer then ran every vertex of a skinned mesh through its bones on the CPU to get a bounding sphere for depth sorting, another third of a second on a 600k-vertex character; and the ES5-to-ES6 bridge behind every `new Point()` and `new Rectangle()` discovered the class by throwing and catching an exception, hundreds of times a frame. Textures now stay out of the copy and are shared by reference, skinned instances get their bounds from the shared rest geometry up front, and the bridge learns each class once. Measured over eight seconds of walking: main-thread stalls fell from 1.5 s (worst 1.2 s) to 0.3 s (worst 0.2 s); the first three seconds of a battle from 1.1 s (worst 0.7 s) to 0.13 s (worst 0.06 s). The Database 3D preview also says **Loading model…** while a model builds.
- **The Database 3D preview no longer stutters while you orbit and zoom a freshly opened model.** Two things were fighting the frame on the main thread. Hovering the pointer over the model raycast the entire mesh (about 350 ms on a 600k-triangle character) every third of a second for as long as the mouse moved, which is exactly when you are about to drag or zoom; and every other model in the list was loaded and rendered for its 64 px thumbnail, twice, right under the first seconds of interaction. Hover picking now waits until the pointer rests and the camera settles, and skips hovering entirely above 150k triangles (clicks still pick). Thumbnails wait for the preview to sit idle before touching the main thread, render once instead of twice when the worker has already decoded the textures, and are cached per machine so a project's list never renders them again. Measured on the Demo's 596k-triangle character over eight seconds of orbit, zoom, and hover: main-thread blocking fell from about nine seconds in 350 ms chunks to none at all with a warm cache.
- **The Plugin Manager picks icons and audio files instead of asking you to type numbers and filenames.** From a GitHub report surveying a 260-plugin project: `@type icon` parameters were plain text boxes everywhere (56 declarations in that project, 22 inside structs), and audio `@type file[]` pools (237 there, almost all inside structs) were edited one element at a time in a bare text area. An `@type icon` parameter now shows the icon, its index, and a **Change...** button that opens the same IconSet picker the database uses, at the top level, inside structs, in `icon[]` arrays, and as a plugin command argument. A `@type file` under `audio/...` gets a **Browse...** button that opens the editor's audio picker with playback, at every level too; `+ Add Element` on an audio `file[]` opens the picker directly, and a file in a nested folder inserts as `battle/hits/sword1`, exactly what the runtime resolves. Non-audio folders keep a dropdown of their files. Values are still written as strings, so `plugins.js` keeps its shape. The IconSet picker itself is now one shared module: a project missing `img/system/IconSet.png` reports it instead of opening an empty grid, paths with spaces or `#` load, and a click past the sheet no longer selects an out-of-range index.
- **New Project is an editor dialog with a template choice, the Forge icon is an anvil, and empty-list right-clicks stay in the editor.** From a GitHub feedback round-up. New Project no longer opens the browser's plain `prompt()`: a themed dialog asks for the name (validated inline, so a bad name is corrected in place) and whether to seed the project from the **Reactor One demo** or start a **Blank project** (an empty database and one map, no sample assets); the folder chooser follows as before. - **Encounter and battle transition shaders land where they aim.** Two more PIXI 8 regressions from the same user's follow-up reports, both in filters plugins ship. First, a plugin that sets a filter's vec2 uniform by component (`filter.center.x = …`, the way VisuStella's Warp, Spiral, Twirl, Glitch, and Pixel encounter effects and ActSeqImpact's zoom focus do) wrote to a property PIXI 8 never reads, so the effect centred on the screen's top-left corner. The uniform now answers to both `.x/.y` and `[0]/[1]` whatever object it holds, and keeps the plugin's own object so a point held and moved later still steers the effect. Second, PIXI 8 rounds every full-screen filter texture up to a power of two, so a hand-written shader that hardcodes 0.5 as the screen centre (irises, shatters, wipes) drifted down and to the right. The texture pool once again hands a full-screen filter an exactly sized texture, as PIXI 5 did, so those shaders are centred without edits. Both verified pixel-for-pixel in the live runtime.
- **Effekseer animations show again in VisuStella battles, and two more PIXI 8 gaps close from a user's debug report.** A GitHub user traced two silent failures in their VisuStella project to the same class of bug: a PIXI v5 call whose meaning changed in v8, thrown inside a code path that discarded the error. First, every Effekseer battle animation was invisible while its sounds and flashes still fired: VisuStella CoreEngine projects each battler with the v5 `sprite.updateTransform()` idiom, which throws on v8, and the Effekseer draw swallowed the throw every frame. The v5 call now works on sprites (windows and tilemaps keep the v8 behavior so their plugin chains are unchanged), and the draw reports its first failure instead of hiding it. Second, the heat-distortion filter (DA_HeatDistortion, Global mode and every battle) crashed on draw because PIXI 8 leaves an unset `float x[N]` shader uniform as the number 0 instead of an array; the compat layer now seeds scalar float and int array uniforms itself, so the plugin runs unmodified.
- **The Audio Player loops where the game does.** The player looped every track end-to-start, ignoring the LOOPSTART/LOOPLENGTH tags the game runtime honours, so a song with an intro replayed its intro on every pass in the editor and only looped correctly once deployed. Seeking past the loop end plays the tail out and wraps from the end of the file; the Loop button still switches looping off entirely.
