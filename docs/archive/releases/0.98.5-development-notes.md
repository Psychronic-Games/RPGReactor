0.98.4 put models in the world; 0.98.5 lights that world and makes it run.

Maps carry their own lights — placed with a visual Lighting tool, no plugin and no note tags — and in 3D every surface is lit per pixel by its distance from each source in three dimensions, with each light standing in the world as a body a wall can hide and casting shadows from the shape of whatever stands in it. Alongside that, a long profiling pass took the bundled Demo's start map from 2.4 frames a second to a steady 58–60 on an integrated laptop GPU without turning anything off. Media surfaces accept still images as well as video, and a stack of database and editor fixes landed around both.

- **Live props and lights in the 2D map editor.** Placed model animations, repeat sequences, playback speed and attached lights preview during normal editing. Lighting remains visible after closing its tool, with the game's flat ambient/glow treatment. Floor lighting draws beneath the model layer, so overlapping lights do not depend on prop order. Retained GPU textures avoid canvas uploads and duplicate pose redraws; map and view changes cleanly pause or release previews.

- **Smoother flat lighting, attached media and prop shadows.** The 2D editor previews database animation and video/image effects on placed models. Ground illumination uses 3D source position, height, pitch and falloff, with full shader precision and cached prop shadows that mask only their own light. Hidden media pauses; static shadows and flicker reuse their GPU masks.

- **Closer and lighter 2D lighting previews.** Downward spots form floor pools instead of sideways fans. Shadow passes crop to the lit area, skip irrelevant casters and empty pools, and safely replace growing masks. Model textures follow zoom/device resolution with antialiasing; pose/media updates stop at the existing 60 Hz presentation rate. Flat model lighting is isolated from database/3D preview state. GPU pixel comparisons and animated NW.js profiles cover both NVIDIA and AMD integrated graphics.

### Added
- **Model eyes and speech.** Face points designate eyes, mouth and lips. First-person uses model eye height and shows the body/followers. Speak 3D Dialogue plays voice clips with waveform-driven mouth movement and optional dialogue.
- **Prop playback across both map modes.** Animations and carried lights survive menu return. Props have an animation speed percentage and an event command to change it during play. The 2D path includes animated props, corrected ambient/translucent lights and direct GPU model textures to avoid per-frame canvas copies. Animated sprite bounds grow to prevent clipping, and raised models sort by height-aware depth.

- **3D effect menus work in empty space, and light previews flicker.** Right-click the effects section's blank space or header to paste, including on models with no effects. Point, spot and laser effects now preview flicker/pulse in both the database and map editor using the game's light animation.
- **Copy and paste 3D model animations and effects.** The right-hand database lists support Ctrl/Cmd+C/V and right-click Edit, Copy, Paste, Duplicate and Delete. Copies retain working settings, receive unique names and open for editing; animation copies include their referenced named effects.
- **A 3D model can carry a light as one of its effects.** Database › 3D Models › Effects gains a **Light** type beside Animation and Media Surface: a point, spot or laser anchored to the model's origin, a part or a bone, with colour, intensity, reach, cone or beam width, direction, tilt, flicker and the usual switches. It rides the anchor, so a lamp on a turret turns with the turret and a headlight on a vehicle drives with it. Play when Always, Moving, Walking, Dashing or Idle keeps it on in that state; on demand, a rule or Play 3D Effect fires it for a set number of frames, or toggles it. The database preview shows the body at its anchor, and models placed on a map light the editor's 3D view.
- **Lights answer to event commands, and one of them is a laser.** Three commands under the Reactor tab's new Lighting section: *Switch Light* turns a light or a whole tag on, off or over; *Transform Light* eases any of a light's position, height, direction, tilt, reach, cone, beam width, intensity and colour to new values over a duration, or resets it to what the map authored; *Change Ambient Light* does the same for the map's darkness. The same is scriptable from `Reactor3D.switchLight`, `transformLight` and `setMapAmbient`, and a save keeps every override. A new **laser beam** light type is a constant-width cylinder of light, aimed like a spot and riding whatever it is attached to, drawn as a beam in the world and as a bar in 2D, and it stops where it lands, leaving a bright dot and a small pool of light on the surface it hits, a wall, the floor or a placed model.
- **The Lighting panel is rebuilt.** Cards with the accent-strip header the rest of the editor wears; a selected light's card carries its **ID** (editable, and what commands address), its type, and titled groups for the light, its position as X, Y and height sliders, its rotation, its animation and its grouping, with the actions in a footer. Tags are a dropdown of every tag on the map plus *New tag…*, not a free field. In the 3D view the selected light wears the same rings and arrows a prop does: drag the green ring to turn it, the red ring to tilt it, an arrow to slide it. Colours open the editor's own themed picker, which stays inside the window instead of the system dialog that landed half off screen.
- **A placed 3D model plays several effects at once and several animations in order.** The 3D-M tab's Animation and Effect dropdowns are checkbox lists: tick every effect the placement should run, and tick animations to play one after another in the model's order, with Repeat looping the whole run, in the game and in the map view alike. A light effect on a placed model also grows with the model now, so a screen glow authored on the database's two-tile preview lights the floor from a nine-tile arm instead of stopping three tiles out, and the database previews a light beside a movie or animation that is also set to Always.
- **The Troops tab previews the battle UI (PR #43).** A *Show Battle UI* toggle on the Battle Preview draws the status and command windows, the turn-order bar or battle log, and the sideview party over the troop at the project's own resolution and layout, read from its enabled plugins, so an enemy the status window will cover is visible as such before a battle test.
- **A plugin compatibility audit.** Two maintainer tools read a project's enabled plugins against the runtime and a stock MV corescript, list every MV API the compatibility layer does not yet supply, and confirm each one against the running game, so gaps are found before a playtest walks into them.
- **Animated GIFs and APNGs play frame by frame (PR #41).** Both formats are decoded by Reactor and stepped on its own clock, so an animated picture, character or media surface animates wherever it is drawn instead of only where the browser happened to paint it.
- **A read-only battle event feed for plugins (PR #42).** `ReactorEvents` publishes battle start and end, turns, actions and their results, so a plugin that only observes combat can subscribe instead of wrapping the engine method where it happens.
- **Playtest checkpoints.** In a playtest the game saves a checkpoint after every battle and every map transfer, and F9 on the title screen resumes the latest one; the title art itself stays the game's, with no line about it. A long unbroken intro no longer has to be replayed to reach the point where something broke. Checkpoints live in save slot 99, never in a player's slots, and only exist while testing.
- **A map's music can be a sequence: tracks, silences and palettes in order, repeating (GitHub #11).** Map Properties gains *Play a sequence instead of one track*. A track plays to its true end, a silence holds the map quiet for a set number of seconds, and a palette is a generative bed: every layer sounds at once, each drawing at random from its own pool of tracks and silences, for a duration and then a fade-out. Loop points are ignored inside a sequence, a one-track sequence is the ordinary looping BGM, battles, vehicles, Save/Replay BGM and save files all bring the sequence back, and an ME ducks it rather than playing over it.
- **Map Properties keeps every field a map file carries.** OK used to write only the fields the form knows, so a field a plugin or a newer Reactor added to the map file was silently dropped. Existing fields are carried through and the form's own overwrite them.
- **A quest system (GitHub #9).** Database › Quests authors quests with objectives, rewards and the rules that make them appear and complete; the game gains a Quests menu and log with tracking; four event commands and a script API drive it; and an importer brings VisuStella Quest System quests across intact.
- **A skill or item can carry several elements (GitHub #17).** The Element dropdown on Skills and Items opens a checklist; the first ticked element is what an element-unaware plugin sees, the data keeps its shape so existing entries are untouched, the runtime takes the highest rate among them, and VisuStella's Element Status Core rulings see the native list.

- **Selecting a model in the 3D database shows what it costs to draw.** Triangles with a plain weight band, vertices, draw calls, textures, file size, bones and animations — and, next to the numbers that matter, what they mean and what to do about them, so it is obvious which model is making a map slow rather than a guess. Pointed at the bundled Demo it immediately found the two props that dominated it.
- **Reducing a model keeps the parts carved out of it.** Parts are stored as triangle ranges, which no longer survive a mesh being reduced — so they are re-derived from the reduced surface instead, letting a model with moving parts be optimized like any other. The result is checked to load before it replaces anything, and the original is kept beside it.
- **Any model in a project can be optimized, not just one being imported.** The 3D database's model list has an **Optimize** action that puts the selected model through the same shrink the import dialog offers — for models copied in by hand, taken from an asset pack, or imported before the optimizer could reduce a mesh. The original is kept beside the file, distance levels are rebuilt, and declining changes nothing.
- **Model reduction handles characters, and no longer punches holes in models.** Importing a heavy model can now cut it by edge collapse rather than a weld grid, keeping the skinning so animated characters can be reduced at all. Models exported with UV seams store the seam vertices twice, which reads as a torn surface to anything working on the index buffer — so both reducers had been letting every seam drift open, scattering pinholes across the whole model. Seam vertices are now pinned in place and the mesh reduces around them: a character cut to a quarter of its triangles comes out as watertight as the model it came from. The bundled Demo's three actors went from 1.45 million triangles to 362,000, and 58.2 MB to 22.6 MB, with every animation and bone intact.
- **Maps carry their own lights, and 3D lights them in volume.** A `reactor3d.lights` array in the map sidecar holds point and spot lights with colour, intensity, reach, height, aim, flicker, pulse, tags, on/off state and attachment to an event or the player — no plugin, no note tags, and placing a light is the whole opt-in. In 3D every map material takes those lights as shader uniforms and lights every pixel by its distance from each source: a point light is a sphere that falls on the floor below it, the wall beside it and the ceiling above; a spotlight is a cone with a yaw *and* a pitch. Each source also stands in the world as a glowing body drawn inside the world's own pass, so a wall hides the lamp behind it. 2D maps get a matching flat compositor.
- **Lights cast shadows from model and character geometry.** Assigned lights project silhouettes onto lit surfaces, including the room floor. Static props and moving characters use separate cached atlas rows; movement, light changes, triangle limits, and per-frame work budgets determine what is refreshed. The latest full/weak moving-caster budgets are 600,000/200,000 triangles.
- **More lights can cast through shared shadow atlases.** Casting lights previously consumed two samplers each. Static and moving casters now share two depth atlases in total: full quality has eight light rows and three dynamic rows, weak quality four and two. Rows prioritize light incident on the player and are cached and refreshed within per-frame budgets. Lights without an assigned row still illuminate surfaces but do not cast atlas shadows; the budget is not unlimited.
- **A light on a model no longer stands in that model's own shadow, and the lights that actually shine on the player are the ones that shadow them.** A screen glow anchored on a monitor arm had the arm's own geometry at its origin, so in the game every glow landed in its carrier's shadow and the room fell to ambient while the editor, which never animates the arm, showed it lit. A model's light now ignores the model it rides. The rows that draw characters go to the lights landing the most light on the player instead of the nearest ones, so a screen shining down on the party shadows it before the torch in their hand lighting the floor, and the moving-caster budget is sized for what a row now costs, so a reduced character casts on a weak GPU too.
- **The Lighting tool.** A toolbar tool opens a live panel over the map: drag lights out of a tray of presets, click to place, drag to move, pull handles to shape reach and aim, and tune colour, intensity, height, cone angle, flicker, pulse, tags and attachment with full undo. An ambient bar with Day/Dusk/Night/Indoor presets previews the whole map at any darkness, and the 3D view runs the game's own compositor, so what you place is what ships.
- **The runtime supports authored distance levels.** Geometry-only levels can replace a model's geometry as it recedes. Automatic creation of separate level files was introduced during this cycle and then disabled in both import presets to avoid shipping duplicate geometry; Optimize now focuses on reducing the base model. Existing LOD files remain supported. Deriving and caching levels in memory is still planned.
- **Surfaces show still images as well as videos.** The Show/Transform/Stop commands and the 3D Models media effect accept PNG/JPG/WEBP from `img/pictures` alongside WebM/MP4 — a sticker on a model, a poster on a wall, a billboard with custom art. The commands are now named **Show / Transform / Stop Media Surface**.
- **Sound effects gained variants, random pitch and their own recovery slots.** Variants and random pitch apply to every sound effect rather than only the 24 system slots, MP and TP recovery can have their own sounds, and an animation preview plays the variant and the rolled pitch exactly as the game will.

### Fixed
- **Switching database models clears the previous model's preview.** Animations, media, lights and preview sounds stop before the next model loads; rapid selections cannot let an older load overwrite the latest model or its clip list.
- **Overlapping lights no longer repeatedly trade shadows through near ties or authored flicker.** Shadow priorities remain stable, and moving lights refresh their static and character shadow maps together so the character shadow does not disappear between updates. Existing quality settings and frame budgets are preserved.
- **Spotlights avoid shadow calculations outside their cones.** Zero-contribution pixels skip the shadow atlases, and model effect anchors avoid updating the same transforms twice. A frozen Demo view used roughly 19% less GPU rendering time at full quality on an AMD integrated GPU, with identical pixels. [Measurements and limits](../../PERFORMANCE.md).
- **A hand-edited MV corescript's contracts live in the compatibility layer (runtime revision `20260904.2`).** Some released MV games ship edited core scripts and plugins that assume the edits. The Braver corpus needed seven: a battle-prep scene shell, an action result that remembers its target, a skill note tag that ignores a sealed skill type, an overridable enemy drop reducer with per-drop rates, familiar troops that do not keep a battle going, null-safe event pages, and a Battle Processing command that takes a troop id. All seven are now additive shims in the MV layer rather than a project plugin, so any project on the same corescript gets them, and a stock game sees stock behaviour. The target reference is stored where a save cannot follow it, which the original corescript left for a plugin to clear by hand.
- **Battle Test launches a battle again (PR #43).** It started the game with `btest` alone, which is not a playtest, so any plugin that declares its classes only in test mode crashed the boot; it launches as `test&btest` on every host. The dialog also refuses an all-(None) party, and a database section the editor had not loaded no longer fails the whole test-data write.
- **An MV game over runs, and the room after an autosave is no longer black (runtime revision `20260904.1`).** MV scenes faded through a sprite plugins read and write directly; MZ fades through a colour filter, so under Reactor the sprite was missing (SRD_GameOverCore crashed reading its opacity) or, once supplied, a real black sprite nothing ever lifted (BraverAutosave's notice left every map after a transfer dark). The scene's fade sprite is now a handle on the filter's own opacity, and a menu-base update run on a plain scene no longer looks for page buttons it never had.
- **A large MV plugin set boots, fights and talks under Reactor (runtime revision `20260903.18`).** Running the Braver corpus, some 250 MV plugins, surfaced twenty-four compatibility contracts: MV's single-target animation setup, MV's phase-based battle input, custom blend modes and v4 filters on PIXI 8, front-view actor sprites and the battle spriteset's first update, plugin helpers on animation sprites, a batch of MV window and graphics APIs the audit found, a states array that MZ's trait lookup mutated in place, PIXI v4's texture manager, MZ status windows built the MV way, MV's name-entry window constructors, MV's Bitmap backing fields, its save-file functions, its frame clock, message sub-windows outside a message scene, missing window opacity and font size in older data, `Bitmap.bltImage`, borrowed picture containers, PIXI base classes called the ES5 way, a lighting plugin's multiply blend that PIXI 8 honoured alpha on (rooms lit as authored now, dark with lamp pools), and a message plugin's name box that Reactor kept forcing open beside unnamed lines. All are handled in the compatibility layers, none in plugin files.
- **Yanfly's quest journal opens in an MV game (runtime revision `20260903.4`).** MV scrolled selectable windows a row at a time and MZ dropped those methods; the compatibility layer supplies them, and its own mouse-wheel handler had been calling them all along.
- **Quests import from Yanfly and GS as well as VisuStella.** The Quests tab's Import button opens a picker listing every quest system the importer knows, with how many quests this project holds in each; Yanfly Quest Journal's numbered slots and GS_QuestSystem's data file come across with the same care as VisuStella's parameters.
- **LeTBS battle animations no longer crash an MV game (runtime revision `20260903.3`).** The 3D scale wrapper on animation sprites looked its wrapped method up on the instance, and an MV plugin's own animation sprite has no such member.
- **Reactor's quests live in their own file and global (`data/ReactorQuests.json`, `$dataReactorQuests`, runtime revision `20260903.2`).** The quest system shipped yesterday as `data/Quests.json` and `$dataQuests`, which are also what YEP_QuestJournal and GS_QuestSystem use: an MV project with either crashed on its first quest command, and the editor rewrote the plugin's file with Reactor fields merged in. Nothing released used the old names.
- **An MV game with Yanfly's Core Engine runs at the resolution the plugin sets, so fullscreen fills the display.** An MV project carries no screen size of its own, and the 816x624 the editor writes in for it was overriding the plugin's 1280x720: the window opened small and F4 left a pillarboxed picture. F2 also crashed under a plugin that replaces the key handler with MV's name for the FPS toggle. Both are handled in the MV compatibility layer, and the scaling toast that a playtest drew after every resize is gone (runtime revision `20260903.1`).
- **Fullscreen defaults to a game-resolution 3D world.** World passes use nearest enlargement with MSAA off by default, while the main canvas/UI follows its GPU-tier resolution policy. `Reactor3D.maxPassPixelRatio`, `renderTargetSamples`, and `Graphics.upscaleFilter` remain script-adjustable. Pass textures are nearest-sampled from creation, and the scaling report goes to `console.debug`; the temporary on-screen toast was removed. The owner's reported softness remains a reproduction follow-up despite sharp harness captures.
- **A model's Effekseer effect previews sharp and in place at any zoom, loops without a gap, and two previews no longer break each other.** The 3D database now draws an effect from its own camera at the view's resolution, the loop restarts the moment the picture ends, and each Effekseer preview layer makes its own context current before drawing — which is what "object does not belong to this context" was.
- **3D model thumbnails come back**, waiting for textures before they draw and never caching an empty picture; **Optimize** opens its dialog from the 3D database and sits with the cost panel of the model it acts on.
- **3D models draw again on Linux and macOS.** A shadow sampler with no depth map behind it was bound to an empty colour texture, which OpenGL rejects at draw time where Direct3D lets it through — so on a map with fewer casting lights than shadow slots, every lit surface was drawn as nothing, and the editor's 3D database preview and model pickers, which draw the same materials from their own renderers, were handed maps from another context and lost everything too. Every slot now carries a real depth map from the start, and only the renderer that owns the maps compiles the shadow variant.
- **The player's own shadow comes first.** The moving-caster budget was measured from the camera, which in third person put the follower ahead of the player; it now measures from the player, and a capable GPU fits a party of two reduced characters.

- **Saving a project inside Dropbox, OneDrive or iCloud no longer loses the save to a passing file scan.** Playtesting from a synced folder failed with *"not all the database files could be saved"* and an `EPERM: operation not permitted, rename` out of `System.json` — the file the editor rewrites on every save, and so the one a sync client is most often busy uploading. Nothing was wrong with the write: Windows refuses to rename a file while another program holds it open, and sync clients, antivirus scanners and the search indexer all open a file the instant it appears or changes. The rename is retried for up to two seconds now, which absorbs a scan that would have finished microseconds later; a file still held after that fails safely with the previous version intact and says a program is holding it, rather than reporting a bare permissions error. Every project write goes through the same helper, so maps, database, plugins and the project file all gain it.
- **A light carried by a character swings with the model instead of snapping between compass points.** A spotlight attached to a character followed that character's facing, which changes between four discrete headings in a single frame, while the model beside it turns smoothly over about a quarter second — so a torch on the player jumped left, up, right, down while its owner turned. The carried light now follows the heading the model is actually drawn at.
- **A 3D map runs at sixty frames on an integrated GPU (runtime revision `20260902.1`).** The bundled Demo's start map ran at **2.4 frames a second** on a Ryzen laptop's integrated Radeon — a machine that should never have struggled with it — and that revision measured **58 to 60 across the whole map**, measured at seven positions, with the slowest frame in four hundred under 19 ms where it used to be 1.6 seconds. That measurement predates the latest atlas, budget, and resolution changes; it is not a performance guarantee for the current revision. Seven faults, every one of them invisible on the hardware the engine was being developed on: integrated AMD graphics were never recognised as integrated, so every Ryzen laptop and AMD handheld was given full-power settings; the entire 3D scene was drawn twice for each frame shown, because the engine's catch-up loop re-ran the renderer as well as the game logic and so made a slow frame slower; models never dropped to their distance levels, because the switch was a multiple of the model's own size and a large model could never be far enough away; moving models cast shadows at full resolution every frame with no budget and no check for whether anything had moved; skinned-character culling was investigated, then reverted when animated poses disappeared; an anchored effect that drew nothing still paid a full cross-context pixel copy every frame; and the check that measures an effect's reach reads pixels back off the GPU, which costs ten milliseconds on a discrete card and four times that on an integrated one.
- **Resolution policy was measured and revised during the cycle.** An early native-resolution/no-MSAA experiment outperformed the old blurred path on its test workload. The later game-resolution/nearest policy above is the current default; the earlier native-resolution result is historical.
- **A room's parallax floor takes the lights, and so takes shadows.** The picture a map stands on was shaded by ambient alone, so no light field and no shadow ever reached the one surface most of them should have landed on.
- **A frame can carry more than one sound effect again.** Database › Animations built its timing list keyed on the frame number, so a second sound on a frame was invisible — and worse, editing or removing the row it did show deleted the other one. Rows are now built per stored entry.
- **A vehicle shows the sprite it uses.** System 1 listed a filename and collected the character index through a prompt asking for a number 0–7, after the image dialog had closed. Each row now draws its own cell and **Change** opens the same cell grid every other character graphic uses.
- **Element and skill-type names show their icon rather than its code**, an icon can be put into a name without knowing the syntax or counting cells, and every surface that plays an animation offers the same backdrop swatches and remembers the same choice.
- Assorted fixes: the troop member enemy picker knows about editor names; a plugin's animation parameter names the picker it opens; the bottom row of a scrolled list keeps a full-height cursor; an enemy parameter box grows away from its label; holding a number field's arrow keeps stepping; and launching the Windows editor no longer leaves a console window open behind it.
