# Application audit — 2026-09-06

This pass samples the application's major workflows and reviews their data ownership and persistence paths. It is a workflow audit, not a claim that every line, plugin combination, asset, or platform has been exhaustively tested. Unfinished construction is kept separate from defects in existing behavior. All mutation tests use disposable projects; authored projects and plugin lists are preserved.

## Confirmed defects

Each finding below was reproduced by a failing regression test before its fix. The initial nine failures are recorded in `/tmp/rr-app-audit-repros.log`.

| ID | Finding and trigger | Fix | Status |
|---|---|---|---|
| APP-01 | Copy/paste dropped event elevation and preview-page selection; deleting events left those settings under reusable IDs. | Carry placement metadata in the event clipboard, remove it on deletion, and restore it through undo/redo. Older clipboard payloads default to ground level with no preview. | Fixed; verified |
| APP-02 | Undo/redo restored cloned event data but left selection pointing at a detached object and old coordinates. Subsequent edits could affect the wrong object. | Rebind selection and tile coordinates to the restored event. | Fixed; verified |
| APP-03 | Saving a flat map with only event elevation deleted its sidecar, losing that elevation on reopen. | Count nonzero event elevations as authored sidecar data. | Fixed; verified |
| APP-04 | Copying an unopened map omitted its sidecar. Copying a loaded map pasted 3D settings into the ordinary map JSON instead of a sidecar. | Read and validate unopened-map sidecars, retain unsaved loaded-map settings, and write copied settings beside the copied map. | Fixed; verified |
| APP-05 | Map paste reported success after a rejected MapInfos save and left incomplete map files. | Roll back incomplete map/sidecar files and metadata, report failure, and retain existing clipboard content for retry. Allocate IDs after asynchronous work and protect orphaned files from overwrite. | Fixed; verified |
| APP-06 | Deleting a map left its sidecar on disk, allowing a later map with that ID to inherit old lighting, models, or media. | Delete the matching sidecar with the map after metadata saving succeeds. | Fixed; verified |
| APP-07 | Clipboard reads or dirty-state prompts completing after a project switch could paste into or delete from the next project. | Bind paste/delete to the originating project; reject stale continuations. Serialize map paste and reject stale tileset-import completion. | Fixed; verified |
| APP-08 | Cross-project map paste matched tilesets by name alone, selecting different art or collision flags when names happened to match. | Reuse a tileset only when its full data apart from ID matches. Otherwise import a distinct record. | Fixed; verified |
| APP-09 | A rejected tileset save still modified the database and allowed map paste to continue. | Stage the imported array, propagate save failure, and publish it only after successful persistence in the same project. | Fixed; verified |
| APP-10 | A failed System save during map deletion removed entries from the working map list and mutated starting positions even though deletion could not finish. Rollback could also leave the database's MapInfos alias stale. | Stage System repairs, wait before changing the map list, restore metadata aliases on failure, and restore starting positions if the later metadata save fails. Recheck project ownership after pending repairs. | Fixed; verified |

## Boundaries

- Runtime compatibility targets remain MV and MZ. This pass changes editor code only.
- Same-name asset files in separate projects are not automatically copied or reconciled by the map clipboard. Existing asset availability requirements still apply.
- A successfully imported tileset can remain as an unused record if a later map-metadata write fails. The incomplete map is removed; this is not a filesystem transaction spanning every database file.
- Existing authored-data findings remain in [the July audit backlog](AUDIT-BACKLOG-2026-07-25.md): over-16-cell animations and out-of-range tileset flags. No bulk rewrite of those projects is performed.
- Earlier native runtime coverage and its limits are recorded in [the 2D compatibility audit](2D-COMPATIBILITY-AUDIT-2026-09-06.md). Tests rerun in this pass will be identified explicitly rather than counted again from that report.
