# Audit of 2026-11-11: what was found and not fixed

## What this page is

On 2026-11-11, twenty-eight reviewers read through every part of the app: the event commands and the event editor, every Database page, the map editors, the Forge, the importers, the build tools, and the game runtime (game objects, battles, 3D, interfaces, vehicles, online play, and the layer that runs older plugins). They only read code. Then one fixer took each report and fixed what it could.

The fixers' logs count **362 problems fixed**, 68 left, 7 rejected as not real, and 5 they were unsure about. What was fixed is in the [development changelog](../editor/changelog/0.99.5.md) under "Audit of 2026-11-11".

This page holds the rest. It has six parts:

1. **For the owner to decide** (58 questions). The only part the owner needs to answer.
2. **Left for a session with the game on screen** (24 items). Known problems whose fix has to be watched or measured in the running game or editor.
3. **Fixed but least proven** (36 entries). Fixes that are already in, and that the logs themselves flag as the ones to look at first.
4. **Server**. Changes to the online server that are not live yet.
5. **Follow-ups**. Small loose ends.
6. **What was read and what was not**, at the end.

Remove an item when it is done.

### Three things to know when reading

- **Nothing was seen in the running game or editor**, by the reviewers or by the fixers. Every problem comes from reading the code. Every fix was checked by reading it, by checking that the file still parses (`node --check`), and by Node tests. Each fixer ran at most six test files, one at a time.
- **Where the full detail is.** Each reviewer's report is on the desktop in `~/.cache/rr-tests/audit-20261111/<name>.md`. Each fixer's log is in `~/.cache/rr-tests/audit-20261111/fixed/<name>.md`. A note such as "log `rt-battles` 9" at the end of an item means finding 9 of that log.
- **The earlier audit has its own page.** Items of [AUDIT-2026-11-10.md](AUDIT-2026-11-10.md) that are still open stay on that page. They are repeated here only where this audit wrote down an exact fix for one.

### Event commands and the event editor

1. **Advanced Math throws away fractions. Keep these formulas or drop them?**
   Sine, Cosine, Atan2, Divide and Square Root store whole numbers only, so most of their results are useless.
   (a) Give them a multiplier and a rounding choice, and give Atan2 its answer in degrees. (b) Remove these formulas.
   (Log `cmd-leftovers`, message-flow 3.)
   **Recommended:** (a). A sine that can only be 0, 1 or -1 is no use; a multiplier (say 1000) and a rounding choice make all five work. Small.

2. **Should Show Choices allow a single choice?**
   Today it refuses fewer than two, on purpose: a test is named for it. Nobody checked whether RPG Maker MZ accepts one choice. A one-choice command that came from an MZ project is changed when the author presses OK.
   **Recommended:** Allow one. As far as I remember MZ accepts a single choice (not checked against MZ), and the editor should not change a command just because OK was pressed.

3. **Should a new Conditional Branch or Loop contain an empty row, as in MZ?**
   MZ writes an empty row inside each branch and loop body. This editor does not.
   **Recommended:** Yes, write the empty row, so a file made here is shaped like one made in MZ. The game does not need it; this is for plugins and tools that read event lists. Low priority.

4. **Three kinds of loop can be played but not made. Give them a dialog or remove them?**
   The game understands counted loops, "while a variable" loops and range loops. No dialog in the editor creates them.
   (a) Add a dialog. (b) Delete the code and the part of the game that reads it.
   **Recommended:** (a) Add a dialog. "Repeat 5 times" is something authors ask for, and the game already runs it. One dialog with the three kinds.

5. **Start Battle on Map can read a music choice that no dialog can write. Put the Music row back or remove the reader?**
   The Music row was taken out earlier on purpose. A test says "the music is the game's battle BGM, set by Change Battle BGM".
   (a) Put the row back. The test changes and the new words need translating. (b) Remove the reader from the game.
   (`battle-mode-commands.test.cjs`.)
   **Recommended:** (b) Remove the reader. One place sets battle music (Change Battle BGM), which is what was decided when the row came out. If you want "keep the map's music" for battles on the map, say so and it becomes (a).

6. **Should Play 3D Effect offer the map's props as targets?**
   Play Model Animation lists them. Play 3D Effect does not. Whether an effect really plays on a prop's model in the game was not confirmed. The two dialogs are copies of each other that have drifted apart.
   (`PlayModelEffectEditor.js`, `PlayModelAnimationEditor.js`.)
   **Recommended:** Yes, but first play one effect on a prop in the game to confirm it shows. Then both dialogs should take their target list from one place so they cannot drift again.

7. **An event that uses a ground tile as its picture is invisible in a 2D game. Which side changes?**
   The editor lets an author pick a tile from the A1 to A5 sheets as an event's picture. It shows in the editor. In the 2D game nothing is drawn.
   (a) The editor stops offering those tiles, as MZ does. (b) The game learns to draw them.
   (`Sprite_Character.tilesetBitmap` has no sheet for tile numbers 1536 and up.)
   **Recommended:** (a) The editor stops offering those tiles on a 2D map, as MZ does. Small, and it ends an author picking something that will not show.

8. **Should an imported page's comparison sign and timer condition be editable?**
   The Conditions box shows them for imported pages but cannot change them. Making them editable means adding a new control.
   **Recommended:** No. Leave them read-only: only imported pages have them.

9. **Should Enter insert Show Text straight after the command picker opens?**
   Today it does. The search box has the focus, and Enter clicks the first command shown, which is Show Text.
   **Recommended:** Keep it. Show Text is the command used most, and Enter twice to add one is quick. Escape undoes a slip.

10. **Should Show Text's "too long" marks take `\PX[n]` into account?**
    `\PX[n]` moves the text sideways. The marks that warn about text running off the box ignore it. The check is only told the width left after the face picture, so it needs to be told where the text starts too.
    **Recommended:** Yes. A small fix that makes the warning marks true. Low priority.

### Database

11. **Should "Dual Wield" still work when the actor's class has its own slot list?**
    Today the Slot Type "Dual Wield" trait does nothing for such an actor.
    (a) The trait still turns the second slot into a weapon slot. (b) The trait's dialog says that a class's own slot list replaces it.
    Change Equipment's dialog follows the game as it is today. It cannot know about a Dual Wield that comes from equipment or a state.
    (The class's list is `rrEquipSlots`.)
    **Recommended:** (b) Say in the trait's dialog that a class's own slot list replaces it. The class list is the author's exact statement of the slots; a trait quietly changing it would surprise.

12. **An enemy set to "No Disappear" with no Collapse Sound chosen: sound or silence?**
    In a battle on the map it plays the stock collapse sound. In a Classic battle it plays nothing. Which is right?
    **Recommended:** The same in both kinds of battle, and I would pick the stock collapse sound: the enemy still fell, and silence reads as a fault. This one is taste.

14. **Should Vertical Offset work for enemies in a flat battle and for everyone in a Battle Room?**

18. **System 2's Editor Settings card saves three values nothing reads. Remove it or use it?**

19. **Structures: how should the page stop adding empty settings to every file?**

23. **Weapon, "Reserve" on the Action battle screen shows nothing. Remove it or make it work?**

24. **What should the Weapon label's number mean?**

25. **Should every Database list be repaired when the Database opens?**

28. **The game can store "tiles fallen" in a variable, but nothing sets which. Add the field or remove the line?**

## Left for a session with the game on screen

### 3D and shadows

1. **Lamp shadows treat every chunk of a building or bush as if it stood at the map's corner.** So the game cannot tell which lamps a chunk is near, and does more shadow work than it should.
   The fix that was written down: one function, `Shadows._reach(root)`, that returns an object's place and size. It is used in all three places that ask (`_faceMask`, `_staticWithin`, `_changedRoots`). The answer is kept, and thrown away when the object changes.
   Afterwards, look at a point, spot or beam light with Shadow on, in a room built of pieces, with Occlude off and a wall thinner than a cell. Also count how many rows of still shadows are redrawn per frame while walking North Haven.

2. **Redrawing still shadows goes through every still object on the map.** This is the Shadows entry of the 2026-11-10 page. It is done after item 1: sort the still objects into near and far for each row of shadows, hide the far ones during the redraw, and show them again afterwards.
   (`_flushRows`. The whole code is in log `rt-3d-lighting-effects` 6.)
