# Audit of 2026-11-11: what was found and not fixed

Twenty-eight read-only reviews covered every part of the app on 2026-11-11: the event commands and the event editor, every Database page, the map editors, the Forge, the importers, the build tools, and the runtime (game objects, battles, 3D, interfaces, vehicles, online, the compatibility layer). Fixers then took one report each. The logs count 362 findings fixed, 68 left, 7 rejected and 5 unsure. What was fixed is in the [development changelog](../editor/changelog/0.99.5.md) under "Audit of 2026-11-11". This page lists the rest. Remove an item when it is done.

Nothing was seen in the running game or editor, by the reviewers or by the fixers: every finding comes from reading the code, and every fix was checked by reading, by `node --check` and by Node tests (six test files per fixer, one at a time). The reports are in `~/.cache/rr-tests/audit-20261111/<name>.md` and the fix logs in `~/.cache/rr-tests/audit-20261111/fixed/<name>.md` on the desktop; "log `rt-battles` 9" below means finding 9 of that log. Items of [AUDIT-2026-11-10.md](AUDIT-2026-11-10.md) that are still open stay on that page and are not repeated here, except where this audit kept an exact fix for one.

## For the owner to decide

Each of these was left because the fix is a choice, not because it is hard.

**Event commands and the event editor**

1. **Advanced Math loses fractions** (Sine, Cosine, Atan2, Divide, Square Root store whole numbers). Give these formulas a multiplier and rounding (and Atan2 in degrees), or drop them. Log `cmd-leftovers`, message-flow 3.
2. **Show Choices refuses fewer than two choices**, on purpose (a test is named for it). Whether RPG Maker MZ accepts one choice was not checked; a one-choice command from MZ is changed on OK.
3. **A new Conditional Branch or Loop is written without MZ's empty row in each body.** Decide whether this editor's lists should carry it.
4. **Counted, while-variable and range loops** are read by the game and made by no dialog. Give them a dialog, or delete the code and its reader.
5. **Start Battle on Map reads a music choice no dialog can write.** A Music row was taken out earlier on purpose (`battle-mode-commands.test.cjs`: "the music is the game's battle BGM, set by Change Battle BGM"). Put it back (the test changes and the words need translating) or remove the reader.
6. **Play 3D Effect does not list the map's props as targets**, where Play Model Animation does. Whether an effect plays on a prop's model in the game was not confirmed; `PlayModelEffectEditor.js` is a drifting copy of `PlayModelAnimationEditor.js`.
7. **An event made from an A1-A5 palette tile shows in the editor and is invisible in the 2D game** (`Sprite_Character.tilesetBitmap` has no sheet for tile ids 1536 and up). Either the editor stops offering A-layer tiles as event pictures, as MZ does, or the runtime learns to draw them.
8. **The Conditions box shows an imported page's comparison sign and timer condition but cannot change them.** Making them editable is a new control.
9. **Enter straight after opening the command picker inserts Show Text** (the search box has focus and Enter clicks the first command shown).
10. **Show Text's overflow marks ignore `\PX[n]`.** The scan is only given the width left after the face, so it needs the start x passed in.

## Fixed but least proven

All 362 fixes are unseen in the game. These are the ones the logs themselves flag: look at them first.

**They change what a player or author meets**

- **A vehicle the entered 2D map cannot draw now stays parked on the map it was ridden from** and the party arrives on foot. A 3D map whose model file failed to load keeps the vehicle behind too. Traced by reading only.
- **Light Switch states are kept per map.** An old save's states carry no map and are dropped at the next Light Switch command: lights a command had switched are back as authored until the game's events switch them again.
- **Enemy Equipment: an enemy with no `rrEquipment` field now has the default empty slots** (was: no slots), and removing every slot stores `rrEquipment: []`. An enemy whose slots were all removed before gets empty slots back (they change no number). The contributor's test was rewritten; the three hunks revert cleanly if "no field = no slots" is wanted.
- **The Tactical forecast and AI run damage formulas against stand-ins** (about 50 lines above `estimateAction`). Not stopped: a changing method whose name is not on the list, a write inside a callback, a mutating array method on `v`, `this`. A plugin's own `evalDamageFormula` is run as before, unshielded.
