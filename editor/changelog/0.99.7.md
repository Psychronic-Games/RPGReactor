- **Opening a project keeps a newer runtime (pull request 88, Xehanort88).** Opening a project no longer replaces a newer runtime with the editor's older one without asking. The editor used to copy its own runtime into a project's `js/` whenever the two differed, so opening a project in an older install (an earlier release, or a build from an older checkout) quietly downgraded the game. Now, when the project's runtime has a later version, or the same version and a later revision, the editor asks first: **Keep Project Runtime** (the default, and what Enter and Escape choose) or **Replace with Older Runtime**. A project with an older runtime is still updated on open, without a question.

- **Audio: `.opus` files play without being renamed (pull request 87, Xehanort88; merged into runtime 20261117.11).** The game, the editor and Deploy Game take Ogg Opus under the `.opus` extension that `opusenc` and FFmpeg write, beside `.ogg .mp3 .wav .flac .m4a`. The runtime tries it last (`Utils.AUDIO_EXTENSIONS`), so a folder holding both `Theme.ogg` and `Theme.opus` still plays `Theme.ogg`, and a web build's failed request reaches it after `.m4a`. Every audio picker, the Audio Player, the Resource Manager and the music sequence preview list it, and the vehicle sound checks find it. The Resource Manager imports it, as `.opus_` in a project with encrypted audio, and an encrypted `.opus_` previews in the editor as `audio/ogg`. Web builds serve it as `audio/ogg`. Deploy Game encrypts it to `.opus_` with the other sounds and never re-encodes it: like Opus named `.ogg`, it ships as it is. Audio command names also lose a `.flac` or `.opus` extension now, and the Pinnacle GTBS scene's sound check finds `.flac` and `.opus`. Tested in `tests/opus-extension.test.cjs`. RPG Maker MZ asks for `.ogg` only, so a project that must also play there should keep its Opus files named `.ogg` ([guide](../../docs/AUDIO-LOOP-POINTS.md)).

- **Facing mirrors repeat without end (2026-11-17, runtime 20261117.4).** The owner's report: the Demo's Mirror Room (map 2, its four walls `finish: mirror`) did not look like a mirror. Seen in first person (`rr-tests\vk3060\mirror.cjs --face=8|6`, pictures of the window): past the second reflection sky and white blocks, the ceiling bent into arches, and facing north the side walls sky down both sides.
  - **Why.** A mirror with no picture of its own takes the reflection capture: at the depth's end (every slot off), and for a wall only seen in another mirror (slots went to planes on screen only). A point capture bends what is near, and in a room walled with mirrors its walls reflected only the capture itself, which holds the sky.
  - **What.** (1) Past `MIRROR_DEPTH` a mirror shows the last frame's picture of its plane (`Mirrors.feedback`, `MIRROR_FEEDBACK`), so each frame adds a reflection, for no draw more. Those pictures are each mirror's whole one (`renderCovers`, `coverCamera`: the eye reflected in the plane, aimed at the mirror and widened to take all of it in, every chunk on the plane, 512 square, one draw a mirror a frame); the view's own pictures covered only what the view saw, and a deeper reflection read past them (black walls, the owner's second look). A slot holding one is marked 2: read only where drawn, dark past it. (2) Each reflection inside a reflection keeps `MIRROR_BOUNCE_GAIN` (0.88) of the light (`rrMirrorGain`; the view's own mirror keeps all), so the far end fades. (3) A plane seen only in a mirror already taken gets a slot (`seenIn`), and the first two mirrors draw those once more from their own reflected eye (`renderLevel`'s `extras`). (4) The reflection capture sees the mirrors at their whole pictures (`applyCapture`), so a mirror's edges show the room and not the sky.
  - **Seen** (RTX 3060 laptop, Direct3D 11 as the Demo now stands): the room nested in itself down the north wall, five figures down the east-west pair, no sky, no black wall; 137 to 144 frames a second (the frame limit) as before.
