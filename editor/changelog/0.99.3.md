# RPG Reactor 0.99.3 (in development)

Work since 0.99.2. The short version is in the [root changelog](../../changelog/0.99.3.md). Runtime **20261026.2**.

### Added

- **Deployment › Unused Files** (`build-scripts/unused-assets.cjs`). `analyze(project)` lists every asset file (img, audio, movies, effects, 3d, fonts, and plugin files) with whether it is used and why; `prune(copy, analysis)` removes the unused ones from a staging or web copy by path, and a renamed copy (encrypted `.png_`, WAV made OGG) by its path without extension when nothing that ships shares it. A file ships when its name appears whole in the project's text (every `data/` JSON, the plugin list, the code of plugins switched on, the runtime, `index.html`, CSS, `3d/Structures`); when code builds names from a fixed start (`"Face_" + id`, `` `Face_${id}` ``, `Face_%1`, `Face_{id}`); when it belongs to something kept (a model folder whole except working files, a material's `_normal`/`_rough` companions, the UTF-16 texture and model paths inside a kept `.efkefc`); when a switched-on plugin lists its folder (`readdir`); when the playtest record holds it; or when the project's Always include list (`deploy.rpgreactor.json`, globs) matches. `img/system` always ships; `.psd`, `.blend`, `.kra` and other working files never do. Game deploy: a **Don't bundle unused files** box (`unusedFiles` 'all' or 'off' to the worker, which also takes 'web'); pruned in the Web copy before its file index and packing, or in staging before optimization and encryption; the list of files left out is written beside the builds. Editor distribution: `trimWebProject` uses the analyzer (it replaces the hand rules for battle-hud faces, enemies, tilesets and models; audio and fogs are no longer kept whole), the same box, remembered per package type (on for Web until changed; `DeploymentAssetPreferences.distUnusedFilesKey`), and `unusedFiles 'all'` trims the Demo in desktop packages too, `release-editor.cjs --unused-files off|web|all`. Translations: a machine-assisted first pass in 17 languages, flagged for review.
- **Playtest record** (runtime 20261026.1): test play writes every asset it loads to `asset-usage.rpgreactor.json` (never shipped), watched at fetch, XMLHttpRequest, image and media `src`, and `FontFace`; NW.js keeps no resource timing for a game served from its app folder, so the browser's own list is not used.

### Fixed

- **Braver 1.6.5's edited corescript, the rest of it** (runtime 20261026.2, `reactor_mv_compat.js` › `installModdedCorescriptCompatibility`). Its `rpg_managers.js` edits had no port: `DataManager.encode` (SHA-256, which BraverRNG's passcode table and BraverMiscFixes' `processOk` use; the challenge hut's counter on map 388 stopped the game). Added as additive shims, each Braver-gated where it changes stock behaviour: `states()` calls `addPermanentStatesToBattler` when a plugin defines it (BraverPermanentStates had no effect); `canPaySkillMpCost`/`canPaySkillTpCost`, asked by `canPaySkillCost` when a plugin replaces one (BraverMiscFixes' hook was never called); `_skip_canMoveCheck` for `Window_BattleItem.includes`; `Math.trunc` on set/gain HP, MP, TP and `executeDamage`; `paramBase` through `level`; spawn items kept at 0 by `gainItem`; `BattleManager._troopScriptedEvent` when a troop page starts; Scene_Map's `update`/`stop` treat Battle Prep as a battle; party items reach their user last; `battleSkills` cancels back to its list; `_cursorAll` windows take a touch anywhere; `loadWithoutPrefix` data files; F5 follows `ConfigManager.optEnableF5ToReload` except on the error screen. Checked in a copy of the game: wrong and right passcodes at the Codekeeper's counter. Not ported (engine-level, covered by Reactor): the loading error's Ignore buttons, JsonEx path logging, `Graphics.render` skip count.

### Tests and CI

- **CI is green on GitHub again** (red since 2026-09-25). Reproduced first in a clean clone with only tracked files, on Node 22 pinned to four cores with `CI=true`: the whole suite passes there in 25.5 minutes, and a runner does the same work about 3.5 times slower, so the one suite job ran out of its 45 minutes a seventh of the way through. `ci.yml` runs the suite in eight `--test-shard` parts, each with the untracked-output check, beside a short syntax/audit/whitespace job and the GUI job. The outfit preset sweep (one test, 18 minutes of one core) is dealt across `character-3d-model-presets-1..6`. Tests that depended on the runner's speed: raw wall-clock budgets moved to CPU time through `helpers/timing.cjs` (reptile, expression, merfolk, slime, drape, motion library, auto-rig, surface picker, global search, UltraMode7, NaN ray); Tactical pacing tests and the walk test set `AI_BUDGET_MS`/`WALK_SLICE_MS`; the finger-skin worker and the keyboard smoke's dropdowns wait for the state they check; Battle Setup's resting pointer holds the clock; the hull worker asks inside a long wait. `webdriver-client` waits for a script request as long as the script may run. Found partly by GitHub runs and partly by an audit of every time window and budget the tests exercise, checked with the whole suite run as eight one-core shards at once.
