# RPG Reactor 0.98.3 - 2026-08-24

### Added

- **Database > 3D carves model regions into named parts and poses them with a direct-manipulation card.** The preview's tool strip holds Orbit, box Select, and Pivot; the right button or Ctrl always orbits. With Orbit active, hovering any poseable part boxes it and a stationary click opens the edit card — carved parts and reader-named parts (a GLB wheel) alike, picked by raycast through the part ancestry. Select drags a marquee and every triangle the rectangle touches joins the part — a vertex inside the box, the box poking into a big triangle, or an edge crossing all count, where centre-only testing let a visibly covered jaw plate slip away — through the model, so a jaw's far side comes with the near side, with Alt-drag removing (same touch test) and a floating count/Apply/Cancel bar; rules freeze while selecting so the mesh cannot slide out from under the marquee, selection always runs against the uncarved geometry so triangle indices count over the source, and Apply flows straight into posing the new part. The card is the whole editor and never leaves: it docks whenever the model has parts, its header carries a target dropdown (Whole model included) beside undo/redo, its × folds it to a small button, and a **Type** select switches the motion — **Pose** (Rotate / Offset / Scale tabs of color-coded X/Y/Z sliders), **Swing** / **Spin** / **Bob** (axis chips plus degree, speed, per-tile, and amount sliders), or an embedded **Clip** — every control driven on `input` so the model moves live through a synthetic always-on rule in the real engine, while every OTHER ambient animation stands still so nothing fights the hand (explicitly played actions still run; releasing the card resumes them). The numeric rule form on the right is gone — the panel keeps only the Parts and Animations lists, and clicking any animation opens it on the card. The card also carries a logarithmic **Duration** slider (0.1–10 s, the ease period in frames underneath), a **Play when** trigger select, an **At the end** control (Return to rest / **Stay posed**, the pose rule's `hold` flag), **Preview** (plays the pose once via a timed action rule — in-and-out, or in-and-hold for a held pose, the editing hold taking over seamlessly), double-click-to-reset per slider, and **Save as animation** / **Update animation**; an edited animation's saved copy is filtered out of playback so nothing plays twice, and a fresh card always defaults to On demand rather than inheriting the last rule's trigger. The card keeps state: working poses persist per part so reselecting resumes the sliders where they were left (a part with exactly one saved pose opens it for editing), each slider gesture stashes on its first tick and commits one undo step on release, Ctrl+Z / Ctrl+Y (and header arrows) walk a per-part undo/redo trail, and Escape closes the card ahead of the dialog. In the runtime, a held on-demand pose latches: the action eases it in over one period (`modelRuleDuration` is `period`, not `period×2`) and `binding.latch` keeps it there after the action expires — until another held pose claims the same part, which eases the previous one home; transient in-out poses overlay a held pose without releasing it, and the sim bar gains a Reset pose button that clears the latches. A part stores `{ name, pivot, meshes: { meshIndex: [[tri,count],…] } }` in `model.json` (foreign sidecar keys preserved); definitions may overlap, and the carve treats overlap as nesting — triangles are grouped by the exact set of parts claiming them, and each piece carries every claiming name as ancestry, most specific (fewest triangles) first with its own pivot, so a cannon selected inside a turret answers its own rules about its own hinge while riding every turret rule (the previous first-definition-wins partition silently carved such a nested part to zero triangles: no box, dead sliders — found on the real tank, not by the single-mesh tests). In playback, a mesh's contributions compose by that same ancestry rather than rule order — ancestors' turns apply before a child's own motion, so a fired cannon recoils along the turned barrel whether the fire rule sits before the turn in the array or rides at the end of the chain as the card's working copy (authoring-order composition slid the recoil along the model's original axis the moment the orders crossed); `Reactor3D.carveModelParts` splits those triangle groups into sibling meshes at instance time — attributes shared, remainder reindexed, never mutating the template — registered exactly like reader-named parts and carrying the source mesh's ancestry so old rules still match, which is how the same carve serves the editor preview and the running game (`syncCharacterModels` loads one sidecar for rules and parts, stat-ing it on disk first so a model without one logs nothing). Pivots are movable fulcrums for every part, named or carved: `pivots: { "<part>": [x,y,z] }` overrides in `model.json` (model space, converted to mesh-local by `Reactor3D.applyPivotOverrides` after the carve, in the editor and the game sync alike), authored from a Pivot row on the card (bounds presets: center and the six faces), by clicking the model with the Pivot tool, or by grabbing the axes gizmo itself and sliding it in the camera plane — the part re-hinges live on every change. The card's target dropdown retargets the animation being edited (values intact; a deleted part's animation shows its target marked `?` for re-aiming) while viewport clicks keep switching context, and a click on the canvas lets an open dropdown dismiss itself instead of preventDefault pinning the popup open. The new **pose** rule type eases to an authored rotation, translation, and per-axis scale (`resize`, applied about the part pivot; mesh base scale now round-trips through the animation compose) and back as its trigger holds and releases — action poses play in-and-out over `period×2×cycles`, with the blend persisted so a released trigger eases home instead of snapping. Renaming a part renames it in every rule that targets it; a part with no triangles yet says so on the card instead of silently ignoring the sliders. A precision-and-state pass hardened the flow: the marquee is occlusion-aware by default — every projected triangle carries per-corner view depth, a screen-space grid answers "does anything nearer cover this centroid" (`triangleDepthAt`, epsilon-tolerant so coplanar neighbours never self-occlude), and a **Through** toggle in the select bar restores far-side selection; each drag and Clear pushes a selection undo step (select-bar arrow or Ctrl+Z, Escape cancels the mode). Selection-highlight overlays are flagged `__reactorOverlay` and excluded from `carveTargetMeshes`, which had let a full-canvas box count more triangles than the model holds and could shift mesh numbering. Rule suppression no longer filters the playback array — blends and latches key by index, and the re-keying scrambled latched poses — suppressed rules are swapped for inert stand-ins in place; the sim bar's Play for the rule open on the card previews the card's current values instead of hitting a dead slot, and the card's Reset also clears latches so one button always means "model at rest". A fresh card no longer inherits the previous rule's trigger. A polish pass tuned the feel against a real multi-part tank: Preview zeroes its own blend slot and releases held copies of its pose first, so it visibly plays from rest even while the card holds the pose at full strength (a held pose previously had nowhere to go and Preview looked dead); opening an animation releases its latch — the card takes manual control and nothing pops back up on deselect; the card's second button is **Clear** (zero the sliders, undoable) with latch release living on Preview and the sim bar; a **＋** beside Save detaches from the rule being edited so a part with one animation can get a second; the pivot gizmo grew, renders through the mesh (it used to be buried inside the part), drags from any tool with a move cursor, and is anchored to the part's owning mesh — its position re-derives every frame through freshly updated matrices, where a one-shot placement read a stale (unscaled) transform right after a rebuild and otherwise froze at whatever pose the part held at that instant, which made the fulcrum appear to jump between reselects; Add part cancels a running selection session so a new part never inherits the old triangles; and the highlight boxes are refit every frame instead of hanging where a pose once stood. On-demand rules carry `effects: [{ at, se|animation|flash }]` in the sidecar — `at` a 0–1 fraction of the play. The sync loop fires each effect once as the action clock crosses its mark (`modelEffectsToFire`, pure and window-tested): SEs through `AudioManager`, database animations through `$gameTemp.requestAnimation` on the character (MV sheets and Effekseer both ride the stock pipeline), screen flashes through `$gameScreen`, and model flashes by tinting the instance's own materials — `cloneModelTemplate` now clones materials per instance so one tank flashes alone, rebuilding `userData.baseColor` as a real Colour because Material.clone's JSON pass degrades it to a hex number (which read as undefined channels and poisoned the flash; `updateModelFlash` also self-heals any degraded base). The card grows an Effects section on on-demand animations: per-row timing slider, ＋ Sound through the shared `RRAudioPickerModal`, ＋ Animation through `AnimationPickerModal`, ＋ Flash with an inline target/colour/strength/duration editor; the editor preview plays SEs via the project's audio files and shows model and background flashes at the authored moment (database animations play in game). The animation picker opened from the card now passes the section's own project shim — the global manager answered a different shape, `project` stayed null, and `startPlayback` bailed to a black canvas for sprite AND Effekseer animations alike; the picker's list also joins the `audio-scroll` accent-pill scrollbar treatment and its footer wears the header's `--color-bg-panel` (both improvements reach the Skills/Items/Weapons pages that share the modal). The Animations list highlight mirrors the card everywhere (editRule/select/deselect/＋/Add all sync `selectedRule`), every card-filling action clears `_cardCollapsed`, the panel's Add opens a neutral motionless animation (its old whole-model swing default rocked the entire model — invisibly, when the card was collapsed), the ＋ button reads "＋ New", and both latch-release paths (`_releaseLatches`, the sim bar's Reset pose) also cancel a matching in-flight `_sim.action`, because a hold whose action window was still open — Turn-Turret-Right runs 600 frames — re-latched on the next frame and quietly undid its own release. After a Preview of a return-to-rest pose the stage keeps the ending — the held working pose stands suppressed until the next slider touch, because it used to ease back in the moment the preview finished, which read as the cannon firing twice and "resting at the end instead of the beginning" (found on the owner's Fire Canon recoil; every edit path re-engages the pose via `_syncWorkRule`). Beyond the scripted flows, a seeded monkey harness (`scratchpad/db3d-monkey.mjs`) drives hundreds of random-order UI actions against invariants (no exceptions, card/state/sidecar consistency, finite transforms) on the plant and on the 35-part tank, and a directed scenario (`db3d-two-parts.mjs`) proves two parts' animations stay fully independent through play, resume, update, and delete. Verified over CDP in a live NW.js editor: docked card before any pick, occlusion counts (visible-only 3,428 vs 8,184 through on the 8,222-triangle plant), selection undo, carve on monster-plant, slider rotate/scale moving the carved mesh, ambient sway freezing while a different target is edited and resuming on release, preview timing, held poses latching and easing home, undo/redo/resume, sidecar write, sim-bar replay, and viewport picking. - **Four rig templates, a preset motion library, and keyframed animations complete the in-editor rigging suite.** The Rig tool's bar gains a template picker: **Humanoid** (17 bones), **Quadruped** (18 — spine chain, tail, four three-bone legs), **Plant/Tree** (base–trunk–crown, wind-ready), and **Vehicle** (body plus four point-like wheel bones, so wheels rig by dropping a marker on each hub instead of marquee-carving through geometry). Swing and bob rules take a **phase** offset, which is all a walk cycle is: the new **Motions…** button on a rigged model opens the **Preset Motions** library — Walk, Run, Breathe, Wave, Take a Bow, Nod, Shake Head, Sit, Overhead Strike for humanoids; Walk, Idle Sway, Pounce for quadrupeds; Wind Sway and Rustle for plants; Roll and Bounce for vehicles — and applying one drops plain, individually editable rules into the Animations list (reapplying replaces that preset's rules; hand-authored ones are untouched). Gestures ride the other new mechanic, **keyframes**: an on-demand pose can carry a timeline of captured slider stops the action interpolates through — rest, through each stop, back to rest — authored on the card with a per-stop time slider, capture, and delete, and multi-bone gestures compose by sharing one action name. The library also carries the action repertoire a game actually needs: **Jump** (real root motion through keyframes — crouch dip, launch, hang, land, all on the whole model while the limbs tuck), **Swim** and **Float** (a swimmer's whole mode: prone stroke cycle while moving, treading drift while idle — a model carries Walk or Swim on the moving trigger, not both), **Slash**, **Thrust**, and **Overhead Strike** for melee (torso coil driving the arm through the arc), and the held stances **Aim Rifle**, **Aim Pistol**, **Dual Wield**, and **Guard** — fire one and it stays until **Lower Arms** (or another held stance on the same bones) takes over, which is the existing latch mechanic doing exactly what it was built for. The sim bar shows one Play button per action name rather than one per rule, so a six-bone stance is one button. Verified end to end over CDP: the row on all five pages, picker open/cancel/resync, binding round-trip showing the model name, the rigged engineer walking as the player with 17 bones and Walk rules on the map, both goblins of troop 1 rendering as ready 3D battlers at 60 fps under the Demo's full 44-plugin battle stack, and marker labels on screen. New phrases (35 marker labels and Change Model) ship curated in the 17 non-English locales.

- **Static humanoid models rig inside the editor — no external tools.** Database > 3D grows a **Rig** tool: thirteen draggable joint markers (mirrored left/right, color-coded, with the derived 17-bone skeleton drawn live between them) fit the standard humanoid to any static model, and **Bind rig** solves skin weights right there — distance-to-bone falloff with a side gate that keeps a left thigh off the right leg, seam welding so UV-split duplicate vertices can never crack open when posed, and Laplacian smoothing over the mesh's own edges. The solve is fast enough to feel instant (218 ms for the 30,940-vertex Demo engineer) and the model reappears skinned on the spot. Every bone then **is a part on the pose card**: click the model and the dominant bone under the cursor is picked from its skin weights, the card's Pose/Swing/Spin/Bob sliders bend it live about its own joint, parent bones carry children exactly as a skeleton should (the same ancestry composition the tank's turret uses — a bone's local rotation simply *is* forward kinematics), and held poses, timed effects, previews, and undo all work unchanged because bones ride the existing rule engine rather than a new one. - **MP3, WAV, FLAC, and M4A are first-class audio formats alongside OGG.** Project data stays extensionless exactly as MZ stores it; the actual format resolves at load time. The Vorbis fallback decoder is now gated to `.ogg` URLs. Verified in a live NW.js boot: all four formats resolve from a plain `.ogg` request, decode, and report correct loop points and sample rates.

### Fixed

- **Event clipboard and undo carry the 3D model sidecar.** `EventManager` copy/cut attach `map.reactor3d.events[id]` to the clipboard payload (`ReactorClipboard` included, so cross-window paste works), paste writes the entry under the new event's id, delete purges the entry (`getNextEventId` reuses freed ids — a stale entry would attach its model to a future unrelated event), and `saveState`/`undo`/`redo` snapshot and restore `{ events, models }` together (old bare-array stack entries still restore). Covered by a behavioral test driving the real class through copy → paste → delete → undo → redo → cut → paste.

- **Light themes pass a real contrast audit.** A WCAG sweep of every text-on-background pairing across all seven palettes found the light modes leaning on accent tones picked for dark backgrounds — the default light theme's gold `--color-accent-hover` sat at 2:1 as text on white (track names, letter headers, link-colored labels were the "hard to read" spots), and several palettes put white button text on accents that only reach ~3:1 (creamsicle's orange was worst at 2.85). Light-block accents are darkened until accent-as-text and white-on-accent both clear 4.5:1 (`--color-accent`, `--color-accent-hover`, and dim placeholder text, per palette), with dark themes untouched. The toolbar's pixel-art icons — bright cyan drawn for dark button faces — get a light-theme-scoped `filter` pulling them toward their outline color so they read as ink instead of neon on cream. The About dialog also now credits Three.js alongside NW.js and PixiJS v8, in all 18 locales.

- **The map grid no longer loses lines as the view zooms out.** The grid is drawn in map space inside the zoomed container, so its width-1 stroke shrank with the view — at 50% zoom every line was half a device pixel wide and rasterized away (measured live: 0 of 50 expected lines at 50% zoom, 2 at 25%). The stroke now uses PIXI 8's `pixelLine`, which stays exactly one device pixel through any transform: the full line count renders at every zoom level, and the grid also stops fattening past 100%.

- **The tileset palette empties stale slots when the map's tileset changes.** `TilesetPaletteViewer.loadTilesetImages` skipped empty `tilesetNames` entries without clearing the per-slot texture cache, so creating or opening a map whose tileset leaves a slot blank (no A3, no C, ...) kept rendering the previous tileset's sheet in that slot. `loadTilesetForMap` now resets the cache and cached layer canvas on every load, clears the selection only when the tileset actually changed (map switches sharing a tileset keep the pick), and carries a load token so a slow superseded load can neither commit its sheets nor repaint the palette after a newer switch.

- **Asset filename casing resolves before the request instead of in the error handler.** The 0.98.2 recovery lived in `Bitmap._onError`/`WebAudio._onError`, which plugins may replace without calling the original — CGMZ_Fallback does exactly that, so on case-sensitive filesystems a Windows-authored case mismatch (`npc_female2` vs `NPC_female2.png_`) became the fallback placeholder forever plus perpetual `ERR_FILE_NOT_FOUND` console spam. `Utils.resolveFileCase` now corrects the URL at every request point (plain bitmap, encrypted bitmap, audio) with a single `existsSync` gate keeping the exact-match fast path to one stat; the `_onError` retry remains as a backstop. Verified live in Haven: the three mismatched NPC sheets load their real 624×576 art with zero console errors.

- **A `<3d>` map with no painted sidecar no longer logs a failed request on every entry.** `DataManager.loadMapSidecar` asked the network for `Map###.r3d.json` and treated the 404 as the normal "render flat" answer — correct behavior, but the browser logs `ERR_FILE_NOT_FOUND` at a level the page cannot suppress, so testing Star Shift Rebellion's Map596 spammed the console on each visit. Under NW.js the loader now stats the sidecar on disk first and skips the request entirely when the file is absent; a sidecar that exists is requested and parsed exactly as before (verified live against SSR's Map596/Map612 pair).

The modal's second slider authors the **Level 999 value** directly (label curated in all 17 locales), the readout reports Lv1/Lv99/Lv500/Lv999, and Apply writes every level per-level, so what the curve shows at 999 is authored rather than an accident of the slope at 99; HP/MP bounds rise to 99,999 and other stats to 9,999 to fit the taller domain. Legacy 100-entry arrays still open (the cap value seeds from the extrapolation, the shape infers from whatever domain is stored) and still play identically — the runtime reads exact stored values first and extrapolates only past the array, so no runtime change was needed. Verified live over CDP: the mini graphs ink the full width, and Apply commits a 1000-entry array whose Lv999 matches the modal.

- **Legacy pixi-filters (v5 era) run on the PIXI 8 runtime.** Plugins bundling the old filter pack (Kawase blur, Godray, DropShadow, MultiColorReplace, SimpleLightmap, ...) override `Filter.apply` with multi-pass bodies that call v5 FilterSystem APIs, which black-screened Haven/Project3 the first time a scene enabled one. The mv_compat bridge now covers the whole surface: `_frame`/`filterFrame` aliases on textures (assignable, matching v5), `getFilterTexture`/`returnFilterTexture` mapped onto the v8 TexturePool and sized from the running filter pass, array uniforms with literal or `const int`/`#define` sizes carried into the uniform group, extra `sampler2D` uniforms routed to shader resources through non-enumerable accessors (a texture key the uniform-sync generator can see but not type crashes it), a rename for shaders that use `finalColor` as their own local before PIXI 8 claimed that name, and v5 `(callback, scope)` ObservablePoint construction. Verified in the live NW.js runtime: all 41 filter classes in Project3's bundled plugin construct and render with no errors.
- **Web builds no longer crash on a 3D-bound actor's retired sprite sheet.** `Database.r3d.json` reads synchronously on NW.js but is an async fetch in a browser, so the first web frames didn't yet know an actor was 3D and requested the 2D walking sheet the project no longer ships — "Failed to load img/characters/...". `Scene_Boot` now waits for the sidecar answer (the fetch always settles with success or failure, so boot cannot hang), and a player or follower sprite never commits to a sheet while the answer is pending — it retries the next frame instead. Verified by booting the Demo with the sidecar artificially delayed two seconds: boot held, the stale sheet was never requested, and both bound actors reached the map as models.
- **Deploy audio compression keeps embedded cover art.** FFmpeg's demuxers surface embedded art (an Ogg `METADATA_BLOCK_PICTURE` comment, an ID3 `APIC` frame, a FLAC `PICTURE` block) as an attached picture stream and delete the tag it came from, so every audio re-encode shipped artless music while faithfully preserving loop tags. The optimizer now extracts the picture before encoding and writes it back — rebuilt as a `METADATA_BLOCK_PICTURE` comment for Ogg outputs (through an ffmetadata file, never argv, which Windows caps at 32K characters), or as a copied attached-picture stream for MP3 and M4A. - **The MV-compat stale-event guard no longer eats plugin-spawned events.** The guard drops save-restored events whose map data no longer exists — but it judged staleness by looking the event's id up in `$dataMap` directly, and action/spawner plugins (Hendrix Action Engine item drops, template events, DotMoveSystem companions) legitimately add runtime events at ids beyond the authored map. Every `Game_Map.refresh` deleted them and the console spammed "dropped N stale event(s)" while drops vanished off the ground. The guard now asks the event itself (`event()`, which dynamic-event classes override to serve their own data): an event whose own data comes back empty or throws is stale; one serving plugin data is alive. Verified in the Hendrix Action Combat project: a full boot–play–transfer run that previously warned continuously now runs silent with the spawned events intact.
- **Tilemap teardown no longer warns about a destroyed texture still bound to a shader.** PIXI 8's mesh pipe keeps the last-drawn texture in its shared shader after the final draw, so destroying the tile atlas on map transfer logged "[BindGroup] a 'textureSource' was destroyed while still bound to a shader" every time. The atlas release now points those shader slots at the empty texture before destroying the source — guarded so a renderer without that private shape simply keeps the harmless warning.

- **Render-guard warnings now say which resource died.** The SpritePipe guard that skips destroyed/orphan sprites (instead of letting PIXI 8 crash the render pass to a black screen) warned with the sprite's class and parent chain but not the cause. Verified live in the Haven test project: labels resolve to real asset paths on every scene sprite.
