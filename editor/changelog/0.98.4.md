Separately, 161 `console.log` progress lines across the tileset/animation/weapon/armor/system editors, EventManager, ProjectManager, and the database shell moved to `console.debug` (DevTools' Verbose level), and the runtime's `Reactor3D: 3D scene built.` report did the same.
- **Three Demo tracks no longer jump to the start when you seek.** The cover-art restoration pass remuxed audio with stream copy, and on Battle Of The Abyss, Darkstream Runner, and Pixel Party the remux wrote Ogg pages whose granule position carried a stray 2^32 samples: a four-minute song reported a duration of 24 hours 55 minutes, so seeking a minute ahead landed "past the end" and the player looped back to zero (or stopped with loop off), identically on desktop and web because the corruption is in the files. The three tracks are regenerated from their originals through the optimizer's single-pass encode (art embedded in the same pass, no copy remux), verified in a live browser: exact durations, and a seek to 60% keeps playing. The optimizer now reads the Ogg clock — last granule position over the Vorbis sample rate — of input and output on every re-encode and refuses a result whose duration drifts more than 2%, so this class of corruption can never ship silently again.
- **The web editor's 3D suite works: previews render, clips list, rigs bind.** Four layers deep: the 3D library loader's web branch checked `RPGReactorHost` while the host registers as `RPGReactorWebHost` — one word that kept three.js from ever loading in a browser, invisible to the suite because its test stubbed the same wrong name; the test now stubs the real global. Editor model reads (DB previews, embedded clips, the picker, rig weight binaries) go through a new async asset reader — synchronous on desktop, a fetch of the served file on web — because a synchronous XHR fallback deadlocks against the service worker (it reads the same IndexedDB store the page writes mid-transaction). The `3d/**/model.json` sidecars join the web build's preloaded files so synchronous sidecar reads keep working, and a `Buffer` polyfill covering the editor's exact API surface unblocks every binary writer: rig binaries, PNG and zip exports, the Forge generators. Verified in a served web build driven end to end: the Database 3D preview renders, Carol lists her 20 embedded clips, and Bind rig on both actors solves, writes model.json + model.rig.bin through the web filesystem, reads them back, and persists to browser storage — matching desktop behavior exactly.
- **Two more PIXI 8 compat gaps closed from live plugin reports.** Hendrix_Animation_Solution crashed calling `PIXI.utils.string2hex` for its bloom tint — the v5 color helpers (string2hex, hex2string, hex2rgb, rgb2hex) are reimplemented in the utils shim. And action combat could crash the whole GL pass ("reading 'addressModeU'") when a plugin destroyed a bitmap mid-animation on a non-Sprite renderable the SpritePipe guard doesn't see — GlTextureSystem now substitutes the empty texture for any dead source at bind, the last line of defense under every render pipe. A live audit of every `PIXI.*` path the Hendrix and Haven plugin packs touch (24 distinct) resolves clean against the shimmed runtime, and a scripted fresh playthrough of Haven — nine maps of intro, fast-forwarded dialogue, a battle fought and exited — runs with a silent console.
- **Loading a save from a map-based title no longer risks a soft lock.** Haven's title screen is itself a map scene; DataManager.loadGame replaces $gameMap instantly while the old scene still updates through its fade-out frames, so every plugin sprite keyed by map id (GALV layer graphics) read the wrong map's store and threw a TypeError per frame — a storm that stalled the scene transition and left the first battle soft-locked with no visible error. Spriteset_Map now stamps the map it was built for and holds still once $gameMap moves on; verified on a real Haven save: clean load, and a battle started through the engine's own Battle Processing command reaches Scene_Battle and plays turns with a silent console.
- **A quieter console.** PIXI's one-shot deprecation nags for the v5 Graphics API (beginFill, drawRect, endFill...) are burned off at compat load with warn muted — MZ plugins use that API forever, the shims work, and nobody can act on the nag — and the runtime's leftover Effekseer overlay/lifecycle and animation-anchor debug diagnostics are removed from the play path (the console-invoked helpers like $reactorAnimWatch stay).
- **PIXI 8's new `origin` accessor no longer hijacks engine bookkeeping.** Newer PIXI Containers claim `origin` as a live transform input; MZ semantics store scroll bookkeeping Points there (Tilemap, TilingSprite, Window, Weather — and MOG_Weather_EX, which warned "Setting both a pivot and origin" sixty times per map). Harmless while nothing rotates (origin cancels out of an identity transform) but wrong the moment a weather sprite spins with a large origin. The accessor joins `name` in the pre-boot deletion list, so assignments become plain instance properties again; verified against the Demo (plain origin, live scroll values, clean console) and a real Haven save (weather plugin active, zero warnings).
- **Benign window-chrome churn no longer warns every playtest.** The render guard's report for a live sprite whose texture source died distinguished nothing about the source — but a destroyed CANVAS source is the churn pattern plugins use for drawn window chrome (SelectableWindow destroys and recreates its gradient bitmap every geometry pass; the part sprites hold the dead canvas for one frame before reassignment). The skip covers that frame and the plugin heals itself, so the canvas case now reports on console.debug (visible at Verbose); a destroyed sprite, nulled GPU data, or a dead file-backed texture is a real leak and stays a warning.
- **The Database 3D panel behaves on first open.** On a fresh editor, `_readEmbeddedClips` ran before the 3D libraries had ever loaded — `Reactor3D` was still undefined, so a model's embedded clips came back empty and every clip rule looked unresolved until the model was visited a second time (the libraries load inside the preview draw; the clips now read after it). And on rigged models the Animations header packed a differently-styled Motions… chip beside Add and Delete into the fixed-width panel, pushing Delete past the dialog edge where it clipped; Motions… now sits on its own full-width row below the header, styled like every other button.
- **The web editor renders 3D.** Database model previews were black in the browser — the running game was fine — because editor previews read model bytes, sidecars, and rig binaries through synchronous `fs` calls the web build only honored for preloaded data files. The web filesystem shim now fetches any bundled file on demand through a synchronous request (cached after first read), which lights up the Database 3D section, the actor/item mini previews, and the model picker with no call-site changes.
