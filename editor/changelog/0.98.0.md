# RPG Reactor 0.98.0 - 2026-08-10

### Added

- **An event can decline to join the object painted over its cell**, with `<3d ground>` in its note — or `<no 3d object>`, which says the same thing the other way round. Painting a group on the map takes everything standing on those cells and makes it one object, which is exactly right for the things that *are* the building: an animated sign, a lit window, a swinging shop door. They ride the building's plane and so hold still against it as the camera comes round, which is the whole reason grouping exists. It is wrong for anything merely passing through — a character walking behind a shop crosses its cells, and the moment they stop walking they are pinned to the shopfront and carried up it, because "is this part of the building?" and "is this standing on the building's square?" are the same question to everything except the author. A walking townsperson was already excluded by having left home; this is for the ones that stand still somewhere a building was painted. Honoured in the running game, in the pass that bakes events into the map, and in the editor's preview, so none of the three can disagree.

- **A parallax is chosen by looking at it.** Map Properties offered a dropdown of filenames, which is a poor description of a picture — parallax names run to things like `!Aeheri-Leader-Room`, enough to tell two apart only if you already know both. A **Browse…** button opens the editor's own image picker: the whole folder, searchable, with the current choice highlighted and scrolled to, and a full-size preview of whatever is selected. `(None)` is an entry in that list rather than a separate button, because clearing the parallax is the same kind of choice as picking one.

  The dropdown stays, since it is the fastest way back to a name you already know, and a thumbnail of the current parallax now sits under it with the image's pixel dimensions — which answers "is this the one?" without opening anything. Clicking the thumbnail opens the picker too. A name whose file has since gone hides the thumbnail rather than showing a broken image.

  The picker itself moved above the other dialogs. It sat at a z-index of 1001 and everything that had opened it until now happened to sit below that; the map properties dialog is at 10000, so the picker opened *behind* the dialog that asked for it — plainly triggered, with no way to tell.

### Changed

- **The language globe is a global control at the far right of the menu bar.** Its short code (`EN`, `JA`, `ES` and so on) shows which locale is active even when the translated menu labels are unfamiliar, updates immediately when the language changes in Options, and yields the code but not the globe on a narrow Web layout.

### Fixed

- **3D water moves in-game, mountain ranges keep their coverage, and mixed standing/flat objects meet cleanly without duplicate support meshes.** The geometry already carried animated A1 UVs and the editor advanced them, but the runtime render loop never passed its tilemap animation frame into the 3D scene. Runtime water and waterfalls now use the same clock as the 2D tilemap, while the editor uses elapsed time so 60, 120, and 144 Hz displays all advance at the intended rate.

  A repeating multi-cell foliage stand-in is one picture at its authored footprint rather than one complete object per constituent tile. Every source quadrant retains its physical map plane, and an incomplete stamp reconstructs the absent quadrants so a ragged fill edge cannot turn the lone mountain variant into half a mountain. A separate underlay at 0.6 opacity fills transparent silhouette gaps without contributing opaque depth. Declared structures preserve one composition frame and pivot across source layers and incomplete rows; missing cells can be reconstructed from that frame, standing rows and flat apron rows keep their roles, and the `edgeHinged` path prevents a declared facade from being shifted half a cell into its own footing.

  The lower and starred passes contain only their authored pieces: `_supportMeshes` and the runtime-only lower copy are gone. Fully opaque texels draw colour and write depth together in an exact-alpha core (`alphaTest = 1.0`); alpha from 1 through 254 stays in the depthless blended pass. This gives the depth buffer stable ownership without cutting soft edges or punching colourless holes into flat shadows. Source map layer remains the coplanar tie-breaker, and the editor renders lower geometry with events before clearing depth and drawing the starred pass, matching the runtime's lower/character/upper sequence.

- **The running game now batches its visible map into native PIXI 8 meshes.** The v8 compatibility path had restored tile rendering with one pooled Sprite per tile rectangle, which was correct but made every scroll repaint detach and reattach thousands of objects. Each physical `Tilemap.Layer` now emits its ordered commands into one typed geometry over a shared 4096×3072 nearest-neighbour atlas; shadows use a reserved atlas texel, animated autotiles rebuild with the same cadence as RPG Maker, and plugin-added tile layers receive both the tileset and the per-frame synchronization pass. Plugin children that are not tile layers survive clears and bitmap changes untouched, and Ultra Mode 7 still owns tile visibility while active.

  This is compatibility-safe rather than mesh-or-nothing. A layer automatically returns to the pooled Sprite path if atlas creation, GPU limits or geometry updates fail, and `window.$reactorTilemapBackend = "sprites"` forces that path for comparison (`"mesh"` requests the new path and `"auto"` is the default). `window.$reactorTilemapStats` reports builds, vertices, allocations, pool hits and fallback reasons. On a live WebGL run of Star Shift Rebellion map 596, a forced 180-frame scroll held mesh p99 at 5.7ms with 15.1ms total geometry-build work; the sprite path reached 22.2ms p99 and performed 222,234 pool operations. Both paths rendered with `glError: 0`.

- **Map dimensions are bounded before they can become an allocation.** The Map Properties fields advertised 999 as their maximum but never enforced even that: typing 10,000×10,000 proceeded to a 600-million-entry tile array, 5,000×5,000 could mutate resize state before failing to save, and 500×500 eventually asked PIXI to cache a 24,000px-wide layer. PIXI rounds cache dimensions to powers of two, so that became a 32,768² RGBA framebuffer, four GiB for one of as many as eight static layers, and WebGL discarded its contexts rather than throwing a useful JavaScript exception.

  Reactor now supports 1×1 through **512×512**, four times MZ's maximum map area. Larger maps use the viewport culler as an actual residency boundary instead of lazily materializing every offscreen tile a few seconds after load. The resident rectangle is aligned to 32-tile chunks with a one-chunk halo: ordinary movement consumes geometry already prepared around the screen, crossing its edge builds only the entering chunks and destroys leaving chunks as units, and unchanged meshes survive. Zoom and pan prepare destination coverage before changing the transform, so a frame cannot expose a missing chunk.

  Static tiles, autotile quadrants and animated A1 water are emitted as typed vertex, UV and index buffers grouped by source sheet and chunk, then drawn through PIXI 8's native WebGL mesh pipeline. A1 animation changes only mesh UV buffers every 30 frames, and painting rebuilds only affected chunks. This replaces hundreds of thousands of JavaScript display objects with a few hundred GPU meshes without allocating map-sized framebuffer caches. It also removes the visible-cell zoom restriction: minimum zoom is again the integer-pixel scale that fits the complete map. On Star Shift Rebellion's exact 200×200 map 596 data, which would expand to an estimated 312,141 tile sprites, true full-map zoom now builds in 147ms and leaves 461 display objects (219 meshes and 48 shadow sprites); twelve complete A1 updates average 2.05ms each and returning to a smaller resident window takes 5.6ms. A headless WebGL render with the project's real tileset PNGs completed at 0.0625 scale with all 40,000 cells resident, no context loss and no GL error; the previous all-sprite path did not complete the same full-map check within 15 seconds. Tile-layer caches independently reproduce PIXI's power-of-two allocation, query the active GPU limits, and decline anything over a conservative byte budget both when first cached and when painting expands a sparse cache.

  Typed sizes above 512, fractions and nonpositive values are rejected before new-map allocation, resize analysis or project mutation. Pasted maps and loaded files must have valid integer dimensions and exactly six complete data planes; imported files over 64 MiB are declined before JSON parsing. Full-map canvas previews and exports have their own pixel budget, and large-map undo depth scales down to keep whole-map snapshots within a bounded memory allowance.

- **Map JSON keeps its tile data inline, as RPG Maker does.** Ordinary saves expanded every tile ID onto its own indented line, paste compressed the entire map onto one line, and resize-reference updates used a third layout. The formats parse to the same object, so games were not functionally wrong, but the expanded tile plane roughly doubled real map files and added avoidable serialization, disk and parse work precisely where large maps already cost most. Every `Map###.json` writer now uses one hybrid layout: readable two-space properties and events, with only the top-level `data` array compact. The bundled Demo map falls from 145,984 to 70,981 bytes without changing one parsed value.

- **Event mode now outlines the cell under the pointer before it is clicked.** Empty ground and cells holding events use the editor's golden-yellow selection outline, so both creating and selecting have a visible target. Moving onto the cell already selected leaves its stronger persistent mark alone, leaving the map hides only the hover, and the first click on empty ground no longer clears its own selection while waiting for the double-click that opens a new event.

  The arrow keys move the persistent target one cell at a time and stop at the map edges. Crossing an occupied cell selects its event; crossing empty ground keeps the cell itself selected, so Ctrl+V puts a copied event exactly where the outline says it will and selects the new event afterwards. A map switch or Escape clears that target, and no target means no paste rather than an invisible fallback to `(0, 0)`.

- **Map shadows are composited where RPG Maker puts them.** The editor placed the shadow plane immediately after map layer 0, so an authored base tile on layer 1 could cover a shadow that RPG Maker draws above both base planes. Shadows now follow layers 0 and 1 and precede decoration layers 2 and 3, including in chunked large-map rendering.

- **PIXI 8 filter lists remain mutable through the legacy plugin API.** PIXI 8 freezes the array returned by `Container.filters`, so the common plugin sequence `this.filters = this.filters || []; this.filters.push(filter)` threw before an encounter transition could start. Reactor returns a cached mutable proxy and commits every push, splice, index assignment, deletion, or length change through PIXI's native setter, preserving PIXI 8's internal representation and its filter-effect attach/detach bookkeeping.

- **PIXI v4 geometry `copy` methods are restored with their original directions.** Point, ObservablePoint, and Rectangle copy their argument into themselves through `copyFrom`; Matrix retains the legacy opposite direction through `copyTo`. Existing native implementations are left untouched. This restores MV-era callers such as MVNovaLighting without silently reversing Matrix copies.

- **MV window padding follows plugin overrides again.** MZ's `updatePadding()` reads `$gameSystem.windowPadding()` directly, bypassing the `standardPadding()` method MV plugins replace. The MV semantics layer restores the original call so a zero-padding autosave window keeps its complete client area while ordinary windows still use the game system value.

- **MV font families declared in `fonts/gamefont.css` load under Reactor.** MV relied on a stylesheet to register names such as `GameFont`, while the modern runtime uses `FontManager` and previously registered no legacy family. Reactor reads valid local `@font-face` declarations and loads them through `FontManager`; browser-only play falls back to linking the stylesheet. When an imported MV project carries MZ's default font filenames but does not ship them, its declared game font is used instead.

- **A `ParticleContainer` draws the sprites put into it again.** v8 kept the name and changed what it renders: only `particleChildren`, which are `Particle` objects handed to `addParticle()`. Ordinary children are ignored outright, so a plugin written against the old API adds a hundred sprites, gets no error and no warning, and sees nothing on screen — the weather, the particles or the damage numbers simply never appear. It is now an ordinary container, which draws them. Nothing is given up: v8's batching needs `Particle` instances that no MZ-era plugin constructs, so those call sites could never have reached it. v8's own class remains available as `PIXI.__v8ParticleContainer`, and the MV spelling `PIXI.particles.ParticleContainer` points at the same place for MZ projects, where the MV compatibility layer is switched off.

- **A tile layer that a plugin added to the tilemap can draw again.** Through PIXI v5, v6 and v7 the tile textures belonged to the shared renderer plugin — one atlas, uploaded once, addressed by set number — so a layer drew from it whether or not it had ever been handed the tileset. That is what made it reasonable for plugins to add tile layers of their own, which billboard and overpass plugins have done for years. v8 has no shared tile renderer: each layer builds its tiles out of its own image list, and a layer that was never given one drops every tile it is asked to draw, with no texture to make and nothing to report.

  TF_Billboard moves every ☆ tile that *also* carries passage flags onto a layer of its own, so it can stand it up as a billboard. On a wooded map those are the trees, and each one lost exactly the tiles that plugin had taken — solid holes in the shape of the tiles themselves, a clean console, and an editor that looked perfectly correct, because the editor runs no plugins at all. The tileset now reaches every tile layer on the tilemap rather than only the two it built itself.

- **A tileset image that has not decoded is never made into a texture source.** The source is cached on the image element and lives as long as the session, so one built from an image measuring nothing stays 1×1 for good: every tile drawn from that sheet afterwards samples a single pixel and arrives as one flat colour, and the sheet finishing loading invalidates nothing. Painting runs every frame, including the frames before the tileset has arrived, so this was reachable in ordinary play — it turned a forest into plain green squares. Such a tile is now skipped and drawn on the repaint that follows the tileset actually being ready. Every window puts its contents inside a client area carrying an alpha filter, and hands that filter a rectangle so a scrolling list is clipped to the inside of the window instead of spilling over the border. Through PIXI v5, v6 and v7 the rectangle was screen-space and used exactly as given; v8 reads it as *local* to the container and applies the container's world transform itself. Handed the screen-space rectangle the engine has always documented, v8 transforms it a second time, and the region it captures lands about twice as far from the origin as the window — off the edge of the screen entirely for any window past the middle. The filter then resolves to nothing and everything inside the client area vanishes: the text, the cursor, the scroll arrows. The panel and its border are not in the client area, so they keep drawing, and the window renders as a correct, empty box with no error and nothing in the display tree measuring wrong.

  Reactor's own copy of that method had been changed to write the local rectangle v8 wants, which is why this was only ever seen under plugins — windows are a favourite thing to reimplement, and a plugin's version was written against the documented screen-space rectangle years before v8 existed. VisuStella's Core Engine has one, so a title screen built on its event title scene showed its frame and none of its six commands. Obfuscated releases cannot be edited in any case. The rectangle is now written in world space on every version, as it always was, and converted for v8 in a separate step afterwards — so whichever version ran last, ours or a plugin's, ends up clipped to the right place.

- **No plugin's `WindowLayer.render` runs on PIXI v8, and none of them throws either.** That method masks each window with raw GL stencil calls, flushing a global batcher between them; v8 has no global batcher — each render pipe defers its own — so the calls never bracket the draws they were written for, and the stencil test is simply left switched on across everything drawn afterwards. Reactor's own copy returns early on v8 for that reason. A plugin that replaces the method does not know to, and VisuStella's Core Engine does, so it failed on the first missing call with a `forceStencil is not a function` on every frame. Shimming that call so it could run to completion was worse than the error: the whole masking dance then took effect and every window it was meant to reveal was rejected. The rule is now the class rather than the call — nothing deriving from `WindowLayer` has its replacement `render` bridged to v8 — and the missing framebuffer calls are stubs for the plugins that reach for them elsewhere.

- **A bitmap whose canvas has been freed is no longer uploaded to the GPU.** MZ releases a bitmap's canvas once it has an image to draw from, and a plugin calling `update()` afterwards asked v8 to send pixels it no longer holds: `texSubImage2D` received no canvas, WebGL raised `INVALID_VALUE`, and it repeated every frame for the life of the map. A source with no picture — no resource, or a detached canvas measuring zero — now declines the upload instead.

- **A plugin whose annotations were stripped out shows its saved parameters, in sections.** A plugin's parameter schema lives entirely in the `/*:` comment block at the top of its file, and obfuscated releases ship without it — of the forty-six VisuStella plugins in one protected distribution, not one still has an `@param`, an `@plugindesc`, or the comment block itself. There is nothing left to parse, here or in RPG Maker's own Plugin Manager, so the plugins carrying the most configuration are exactly the ones that appeared to have none.

  The values survive in `plugins.js`, and their shape says most of what the annotation would have: an object is a struct, a list of objects is a list of them, `true` is a checkbox, a number is a number, and a string that was stored JSON-encoded has to be written back that way. Read like that, one project's plugins produce 198 nested editors from 306 recovered struct definitions, so the settings open as the sections their author laid out rather than as one wall of JSON. VisuStella also writes each parameter's type into its own key — `QoL:struct`, `ActorHPColor:func` — for its own loader rather than for anyone reading the list; the suffix is dropped from the label.

  Reading a shape is a reading, and can be a misreading: an `:eval` parameter holding the source text `[255, 255, 0, 160]` looks exactly like a list and is an expression, and RPG Maker writes its own `__collapsed` bookkeeping into a struct as a bare array where every real field is a string. So each reading is checked by performing it — a parameter is offered as structured only when saving it reproduces the stored text byte for byte, and anything else falls back to a text box, which is what it would have had anyway. Across that project, 198 parameters round-trip exactly and 23 decline. What cannot be recovered at all is naming: which field is a colour, a switch, a file. Those stay plain text, and merely offer no picker.

- **A parameter declared `multiline_string` gets a text area.** RPG Maker 1.5's multi-line text type was rendered as a single-line box, which is a poor way to edit a paragraph. Unlike `note`, which is stored JSON-encoded, this one is an ordinary string and is written back exactly as typed.

- **Object designations can be painted again after switching project or map.** The 3D object overlay is built around the map's tilemap, and that is rebuilt per project — but the editor was handed the new one only when the Objects tab was *clicked*, and a tab that is already open is never clicked. Open a project with that tab selected, which is where the last session left it, and the editor was still holding the manager built for the previous project, or none at all. The paint path checks for one and returns quietly when it is missing, so a click produced no mark, no error and no clue it had been received. Every surface the editor paints through is now bound in one place, called both when the surfaces are rebuilt and when the editor arrives, so neither end has to remember the other.

  The Regions and Objects tabs also do their setting up when they are *selected* — building their panel, making their overlay layer, showing it — and nothing selects a tab on a project switch. An already-open tab is now re-opened, so the rebuilt surfaces arrive with a panel and a layer to draw on rather than neither.

- **An event can say which layer its animations play on**, with `<animation z: 6>` in its note, or `<animation over>` for the layer RPG Maker uses. Where an animation belongs is a question about the scene rather than about the engine — a spell cast over a character belongs in front of the furniture, a glow on a console set into a table belongs behind the table's own top — and one map will want both, so it is written on the event the animation is played on, which is the only thing that knows. The layers are the tilemap's own: 0 the ground, 3 the characters, 4 the tiles drawn over characters (the star-flagged pass, in 3D), 8 where an animation goes by default; a half above a layer sits clear of everything on it. Read in 2D as well as 3D, which had no way to place an animation below anything at all. Saying nothing keeps exactly the behaviour that was there before.

- **A tile samples inside its own square of the sheet at every zoom.** The half-texel inset added earlier fixes the boundary case — it moves the sample off the fence between two tiles — and cannot fix the far case: zoomed out, one screen pixel covers many texels and the sample can land in the next tile along. The inset would have to grow with the zoom, and the zoom is not a constant. So every quad now carries the rectangle it is entitled to and the fragment shader clamps to it, which is correct at any distance by construction. Mipmaps would have made this worse rather than better: a mip level of an unpadded sheet is built by averaging *across* tile boundaries, so the bleeding would be baked into the texture instead of merely sampled from it.

- **The 3D camera looks at the middle of the view.** It was given the exact centre point of the display, and the aiming code adds half a tile to whatever it receives — to turn the corner of a character's cell into the middle of it — so the camera looked half a cell past the middle and everything sat slightly left of where it belonged, by a margin just small enough to doubt.

- **An animation takes its place on the frame it appears.** The tilemap sorts its children in its own update and MZ creates animation sprites after the spriteset has updated its children, so a sprite added this frame stayed wherever it was appended — last, which means in front of everything — until the frame after. One frame is enough to see, and a looping animation restarts every few frames: three of them on a table flickered continuously between in front of it and behind it, and no amount of getting the layer right could settle it.

- **An event that is part of a 3D object sits on it, not half a tile above it.** The shader steps every cut-out half a cell towards the camera, because a thing standing on a cell fills it front to back and what the eye reads as "where it stands" is the near edge of that circle rather than its centre. Sprites were placed without that step, so an event pinned to a painted object was half a cell further from the camera than the art it belongs to — and under a pitched camera, further away reads as higher up the screen. A sign floated above its own board and took its animation with it. Only things standing on art take the step; anything on the ground is where it always was.

- **A parallax the 3D ground was built from is no longer also pasted flat over it.** A parallax plugin adds a layer per parallax to the tilemap, and the 3D ground sits in the tilemap too, sorted above them so a backdrop stays a backdrop. That is right for a starfield and wrong for the layer the ground was made from: the same picture was then on screen twice, once laid on the world and once pasted flat across it. Only the layers the ground actually took are put away — the map-pinned ones — so anything that scrolls or loops keeps drawing exactly as it did.

- **A new event can be made in the 3D view.** Right-clicking stopped at the event cube: a click that hit nothing returned, so the only cell you could open a menu on was one that already had an event on it — and *New Event…* lives on the menu for a cell that does not. Existing events could be edited and none could be created, which reads as the tool half working rather than as a case nobody had written. Bare ground now gets the same menu the 2D map gives it, on the cell the hover outline is pointing at, routed through the same calls so the cell is selected and the events panel follows. It still refuses outside event mode, and still stands down at the end of a right-drag pan.

- **One click of the shadow pen paints.** It did not: the pen paints a *quadrant* of a cell and worked out which one from the last position `pointermove` had recorded — a field the press handler never set. A press with no move before it therefore had nothing to read, and the pen took a missing position as "cannot tell which quarter" and declined. Dragging worked perfectly, because the drag's first move filled the field in, which makes this a strange thing to report and an easy one to dismiss as a slip of the hand. The press records where it landed now, which is the position that was always meant.

- **The editor's 3D preview draws the map's parallax.** The runtime asks ImageManager for it and there is no game running in the editor, so a parallax-mapped map previewed as its bare tile layers — which on a parallax map is very close to nothing at all. The editor loads them off disk instead. More than one is honoured: the map's own parallax and any `<MultiParallax>` block in its note, stacked in the author's `z` order, each map-pinned layer treated as ground and anything that scrolls or loops left alone as the backdrop it is. Layers added by a plugin *command* cannot appear — they do not exist until an event runs, so there is nothing for the editor to read.

- **A plugin that renders somewhere else and hands the picture to PIXI as a canvas now shows it.** This is the whole of MZ3D, which draws the world in babylon.js and passes the result through as a texture; under Reactor it drew nothing, and the map was the parallax sky it had been laid over. Two v5-era behaviours were quietly gone in PIXI 8, and neither leaves a mark.

  `Texture.update()` used to mean "push this to the GPU" — it called the resource's own update, which is where a canvas's *current* dimensions are read back off the element. In v8 it only recomputes UVs; the source has to be updated separately, and v8's own documentation says so. A plugin that builds its texture before sizing its canvas — which is the natural order, since the canvas is sized to the game and the game is not up yet — is therefore pinned to whatever the canvas measured at the time, and for a bare `document.createElement` that is the HTML default of 300×150. Reactor restores the v5 meaning: updating a texture updates its source, so the size catches up and the pixels arrive.

  The second half is that a Sprite used to track its texture, and in v8 it only subscribes when the texture is flagged `dynamic` — a v8 concept no MZ-era plugin knows to set. So the picture would have arrived correctly and been drawn into a 300×150 corner of the screen. A texture built from a canvas is now flagged, because a canvas handed to `Texture.from` is one the caller means to draw into. Textures from anything else keep v8's default, and Reactor's own `Bitmap` does not go through this path at all.

  Both are applied to the textures Reactor hands out rather than to every texture, which is not fastidiousness. PIXI's own Texture listens for its source's resize with `update()`, and a canvas source emits that *before* it has resized the element — so a blanket version reads a stale canvas mid-resize and puts the source straight back. The renderer's own view is a texture over a canvas, so the effect of getting that wrong is that `Graphics.resize` silently does nothing and the game draws into the bottom-left corner of its own canvas, with every measurement in the page still reading correctly.

- **A 3D map lit by PSYCHRONIC_RaveLighting is no longer hidden behind its own darkness.** A lighting plugin draws in two parts, and only one of them is the lights. Reactor was putting away `_lightContainer`, which holds the glow sprites, and leaving `_toneSprite` — a full-screen bitmap filled with the screen tone, with light-shaped holes punched through it. On a night or interior map that tone is `[-255,-255,-255]`, so the sprite is opaque black across the whole screen, over a 3D world that had already been lit for real.

  It also has to be told more than once. The plugin rewrites `_lightContainer.visible` from the options setting on *every* frame of its own `Spriteset_Map.update`, so a one-shot `visible = false` was undone before it was ever drawn. Reactor takes `renderable` instead and re-applies it each frame: `visible` is the plugin's, and writing it back would overrule a player who turned lighting effects off. Walking from one lit 3D map to another never crosses the on/off boundary either, so the second map's freshly built overlay used to arrive un-suppressed.

- **RaveLighting's lights are found where they are kept.** They were read out of the spriteset's `_lightContainer`, which holds additive glow sprites the plugin builds *from* the real configs — pooled, created lazily, left invisible when unused, and not built at all on a map whose overlay pass returns early. So a map with five lit braziers presented an empty container and Reactor put no lights in the scene at all. A light belongs to a *character*, on `_lights`, and that is now the only place it is looked for — the player and its followers included, each shape reading its reach from its own field, since a pulsating light records where it is rather than how far it gets.

- **The audio player's track list fills the dialog.** It was a flat 475px — the height of the A-Z strip standing beside it, 26 tabs at 17px plus padding — so the list was sized to fit the alphabet rather than the window, and everything below it was an empty grey band that could have been holding twice as many track names. The dialog is a column now and the list is the part that grows.

- **Verified candidate artifacts attach to the source release without replacing its notes.** The tag workflow normally creates the release body from the root changelog first. Artifact publication now detects that release, updates its title, and uploads all verified manifests and archives with `--clobber`; if source publication was interrupted, it can still recover by creating the release. The release workflow continues to verify all four manifests against the tag commit and sends the same bytes to GitHub and, when requested, itch.io.

- **The Web editor no longer begins with avoidable missing-file requests.** The editor page now declares its application icon, and the bundled MZ starter explicitly sets `$reactorMvCompat = false`, preventing the runtime from probing for an MV project marker or requesting MV-only `fonts/gamefont.css`. A served archive was verified through service-worker control, IndexedDB persistence across reload, and in-page Playtest reaching `Scene_Title`.
