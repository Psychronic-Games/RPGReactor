# RPG Reactor 0.96.0 - 2026-07-27

Cycle overview: [RPG Reactor 0.96.0: A Deep Correctness Audit](../../docs/devlogs/2026-07-25-rpg-reactor-0.96.0.md).

0.95.1 was an internal development version and was never published; its changes ship in 0.96.0.

### Added

- `runtime/reactor_3d.js`: the HD-2D renderer. A map opts in with `<3d>` in its note; `Map###.r3d.json` beside it carries elevation and camera, so no 2D project gains a file and a 3D map's `Map###.json` stays valid RPG Maker data describing its 2D footprint. The grid stays authoritative — `Game_Map`, `Game_Character`, passability, regions and the interpreter are untouched, and nothing in the 3D view feeds back into game logic. three.js (vendored to `runtime/libs/three.js` by `build-scripts/vendor-three.js`, absent from `scriptUrls`) loads on first entry to a 3D map, so a project with no 3D maps never fetches it. Compositing is by stacked canvases, the arrangement the runtime already ships for Effekseer: the 3D canvas takes z-index 0 under the PIXI canvas, so windows, pictures, weather and plugin sprites draw exactly as in 2D. `Reactor3D.Geometry` is pure — no THREE, no DOM — and produces one merged buffer per tileset sheet, which holds a 200x200 map to a handful of draw calls; autotile cells emit four quadrant quads picked from the same shape tables the 2D renderer uses. Upright tiles are collapsed into north-south runs so a building becomes one facade rather than a stack of per-tile panels. Coverage in `reactor-3d-foundation.test.cjs` and `reactor-3d-geometry.test.cjs`.

- Per-tile 3D classification, `Tilesets.r3d.json`. No heuristic over 2D flags separates buildings from terrain — on a real city map, flag-guessing produced facades fifty-one tiles tall — so it is authored, per tileset rather than per map since a tile is the same kind of thing wherever it is painted. `src/utils/Tileset3DClass.js` holds the store; `Reactor3D.CLASS_*` mirrors its values and a test pins the two together, as the editor cannot load the runtime module. `AUTO` is the *absence* of an entry, so clearing a tile deletes it and an emptied tileset drops out entirely: a fully cleared file equals a fresh one instead of accumulating husks. `keyFor`/`Reactor3D.classKey` fold autotile ids to their kind base, so one entry covers all 48 shapes — the difference between a few hundred lines and tens of thousands for a single tileset. Unclassified tiles fall through to the flag heuristic, capped by `AUTO_MAX_FACADE`, so an untouched map still shows something recognisable. The database loads and saves it either side of `Tilesets.json` and reports it through `getDirtyKeys`, since it sits outside `dataFiles` and would otherwise be lost on close without a prompt; the file is only written when non-empty. Authoring is a `tile3d` mode in the tileset editor that draws instead of the flag markers rather than alongside them, a tile already carrying up to seven glyphs. Coverage in `tileset-3d-class.test.cjs` and `tileset-3d-authoring.test.cjs`.

- The build preflights now require `reactor_3d.js`. It is in `scriptUrls`, so a project without it hangs at load waiting for a script that 404s — but `validateProjectRuntime` in `build.js`, `build-worker.js` and `dist-editor-worker.js` never listed it, so such a project passed validation and failed later. A test now derives the expected list from the manifest itself, so a future addition to `scriptUrls` cannot be missed the same way. `libs/three.js` stays out of both, deliberately: `Reactor3D.ensureLoaded` fetches it on demand and a project with no 3D maps should not pay for it.

- Painting in the 3D viewport, through `MapEditor` rather than beside it. `tileAt` raycasts the merged ground meshes and floors the world position into map coordinates — the map is one unit per tile, so a hit on a mesh shared by thousands of tiles still names one — and hands `MapEditor.beginEditState`/`paintTile`/`resetDrawingState` the same arguments the 2D canvas does, including a synthetic `lastMousePos` in tile-pixel space for the quadrant-sensitive tools. A left drag paints when `tilesetPaletteViewer.selectedTiles` is non-empty or a stamp/shadow pen is active, and orbits otherwise; Ctrl forces orbit. `resetDrawingState` commits the undo entry and fires `rr-map-edited`, which is what rebuilds the geometry, so a stroke needs no special path back. The cursor's tile is reported through `updateMapCoordinates` as in 2D.

- `applyAtmosphere` gives the scene a background and `THREE.Fog` scaled to the map's longest side (fading from 0.9x to 2.2x), taken from `--color-bg-base` — not `--color-bg-deep`, which is pure black on the dark themes and gives fog nothing to fade into. `MeshBasicMaterial` respects scene fog, so this needs no material change, and the runtime sets no fog of its own.

- Facade footprints get an apron. Every cell of a run is added to `consumed`, and those cells typically hold only the building's own art, so filtering out upright tiles left them with no ground quad: a fifteen-tile facade rendered a fifteen-cell hole to the sky. `nearestGround` walks south from the run — the direction it faces, so the first floor found is the street in front of it — then north, then along its row, and the result backfills every cell of the footprint. It takes `stack[0]`, the bottom of the layer stack: taking the top returned whatever decoration was drawn over the floor, which alpha-tests away to nothing and leaves the hole it was meant to close. On Moletown this drops the cells rendering as sky from 1,748 to 38, and those 38 are cells whose artwork is genuinely transparent — the 2D editor shows its own background there too.

- The 3D wheel handler calls `stopPropagation`. The 3D canvas is a child of `#canvas-container`, which carries `TilemapManager`'s wheel-zoom listener, so every scroll zoomed the 3D camera *and* the hidden 2D view, re-cropped its canvas, updated its scrollbars and overwrote the zoom readout with the 2D scale. `updateZoomReadout` now reports camera distance against `LABEL_REFERENCE` as a percentage while 3D is on, and teardown calls back into `updateMapZoom` to restore the 2D figure.

- Facade depth is a crossing plane, not a box. `uprightDepth` used to add two side faces and a cap; for alpha-tested cut-out art both are wrong — a side stretches one texel column across the depth, and the cap draws the tile horizontally over the full cell, which gave every spire and jagged roof a flat shelf the size of its footprint regardless of silhouette. The depth quad now runs at right angles through the cell centre, so both planes are ordinary billboards. Culled where either neighbouring column continues the run, so a wide building is still one flat wall. Two quads per level instead of four.

- Wall faces take the autotile's quadrants. `faceQuads` subdivides any face — cliff, rim or facade — by bilinear interpolation of its corners when the tile is an autotile, so the same four quadrants land on a vertical surface as on the ground. Walls previously used `sheetRectFor`, the block's whole top-left tile, which patched raised terrain with corner fragments of unrelated artwork.

- `Reactor3D.CLASS_SCENERY` (3) and `Geometry.build`'s `isScenery`. Upright collapses a run of cells into one facade as tall as the run, which is correct for a building drawn as a single perspective prop — Moletown's towers reach fifty-one tiles — and wrong for terrain, which is one tile repeated over an area. Classifying the Infernis world tileset's A2 terrain as upright produced 391 runs over eight tiles and a longest of 58; as scenery it produces 690 facades capped at 16 (the towns and towers, which really are pictures) and 7,979 single standing cells. Scenery raises its cell through `surfaceAt` rather than emitting geometry: a billboard per cell was tried first and turned a mountain range into rows of cardboard with daylight between them, because terrain covers an area and a picture does not. Raised ground takes its cliff faces from the existing wall code. `uprightPredicate` now returns false for *any* explicit class other than upright rather than falling through to the guess, which had let a scenery tile both stand on its cell and weld into a facade behind itself. Coverage in `reactor-3d-geometry.test.cjs`; the editor cycle is Auto -> Flat -> Upright -> Scenery -> Auto.

- The autotile shape tables ship inside `reactor_3d.js`. `Geometry.autotileTables` read them off the global `Tilemap` and returned `null` when there wasn't one — the situation the editor viewport and the offline preview renderer are always in, since both load the module alone. `autotileQuads` then returned null and `build` fell back to a whole-tile blit, stamping each autotile block's bordered top-left corner over every cell: on a world map, 63,620 shape-0 interior tiles that should have been seamless rendered as a grid of squares. A running game's `Tilemap` still wins, so a plugin that replaces the tables governs the 3D view too. The embedded copy is extracted from and pinned against `reactor_core.js` by test. The old test asserting the whole-tile fallback was pinning this bug as the contract; it now pins the four-quadrant path, and the fallback is pinned separately for a caller that supplies an incomplete table.

- `MapEditor3D.loadClassification` reads `Tilesets.r3d.json` off disk. The runtime fetches it by XHR relative to the running game, so in the editor `Reactor3D._classification` stayed null: every tile fell back to the flag guess, the facade cap then rejected anything over eight tiles, and `topTileAt`'s fallback laid the rejected wall art flat as ground texture. A classified city rendered as building facades painted on the floor.

- `Geometry.groundStackAt` replaces the single `topTileAt` call for ground, so all four planes of a cell are drawn bottom-up, each lifted `LAYER_LIFT` (0.001 tiles) above the last to keep the author's order without z-fighting. On Moletown 260 cells were dropping a layer. Wall skirts take the topmost ground tile's art. A facade's footprint now also draws the floor under the building — skipping it left a hole visible from above, since a facade is one plane at the run's southern end — and gets no wall skirt of its own, which would z-fight with the facade.

- `opts.uprightDepth` (default 0.5 tiles) extrudes facades into shallow boxes with a capped top. A single plane is paper: a chimney or a mast disappeared to a line when the camera came round. Side faces are culled where the adjoining column carries a run to the same level, so a wide building stays one flat wall and only its outer corners are boxed. The editor's default camera pitch dropped from 52° to 34°, since from overhead a standing facade is edge-on and the 3D view looked identical to the 2D one.

- 3D event picking: `MapEditor3D.eventAt` raycasts against the event cubes only — ground and facades are one merged mesh per sheet, so a hit there names a sheet rather than a tile. A pointer-up within 4px of its pointer-down counts as a click and selects; a drag orbits and selects nothing. Double-click calls through to `EventManager.editEvent`, the same entry point the 2D map uses. Coverage in `map-3d-viewport.test.cjs`.

- `Geometry.build`/`uprightRuns` take `isAuthored`, and `AUTO_MAX_FACADE` now judges guesses only. The cap was documented as never overriding an explicit `CLASS_UPRIGHT`, but `isUpright` reaches the builder as a plain boolean, so an authored tile was capped identically to a guessed one. On Moletown, 155 of 397 vertical runs exceeded the 8-tile cap and were dropped to ground — the tileset draws each building as one perspective prop up to 51 tiles tall — which is why a classified city still rendered flat. A run is now kept if any tile in it was authored, since a run is a single object and classifying its base classifies the thing. `MapScene.build` supplies the predicate from `Reactor3D.isClassified`. Coverage in `reactor-3d-geometry.test.cjs`.

- 3D events carry their sprite, name and the interactions the 2D map has. `eventSprite` crops the character frame into its own canvas rather than addressing it by UV, since `$` sheets are a single 3x4 block and normal sheets a 4x2 grid of them; sheets load once each per map (37 sheets for Moletown's 354 events). Sprites and labels billboard on yaw only — pitching them would lay a character flat when you looked from above. Labels rescale with camera distance so they hold their size on screen, and hide past `LABEL_DISTANCE` where they overlap into a band. Picking runs against `pickables`, which excludes labels: they are overlays, and selecting one fought with that rescale. Right-click routes through `onEventContextMenu` to `EventManager.showContextMenu` with the same arguments the 2D canvas passes. Selection is bidirectional via a new `rr-event-selected` announcement from `EventManager.selectEvent` — the single funnel the map, the events panel and the editor already share — so neither side needs to know who made the selection. Coverage in `map-3d-viewport.test.cjs`.

- `src/MapEditor3D.js`: the editor's 3D viewport, toggled by a checkbox beside the A1 toggle and stored as `map3DView`. three.js and `reactor_3d.js` are read off disk from `ProjectManager.getRuntimePath()` and injected as classic scripts at first use — the editor is packaged separately from `runtime/`, so a relative `<script src>` would resolve in the source tree and break in a distributed build, and a viewport with its own copy of the geometry would drift from the runtime the first time either changed. The 2D canvas is hidden, never destroyed: `TilemapManager` owns it and has sized and cropped it for the open map. Events become boxes coloured by trigger, the one thing a view of tile data cannot otherwise show. `MapScene.build` gained `options.flags`/`options.tilesetId` and `$gameMap` reads moved behind `typeof` guards, since in the editor it is not merely null but never declared. A completed stroke dispatches `rr-map-edited`, debounced to one rebuild, so the view follows edits instead of freezing on whatever was open. The toggle reflects what actually happened rather than what was asked: a missing runtime directory leaves the box unticked with the reason in the status bar. Coverage in `map-3d-viewport.test.cjs`.

- Tileset sheets F and G, in the tile-ID band `1024-1535` that RPG Maker leaves unallocated between E (ending at 1023) and A5 (starting at 1536). No MV- or MZ-authored project can contain an ID in that band, so the addition cannot collide with imported data, and `$dataMap.data` is unchanged — map files stay structurally identical. The band needs no new address arithmetic: `setNumber = 5 + Math.floor(tileId / 256)` already resolves it to slots 9 and 10, and that one expression backs both `Tilemap._addNormalTile` and `Sprite_Character.tilesetBitmap`, so tile rendering and event tile-graphics both work unmodified. The stock 8192-entry `flags` array already covers `1024-1535`, so passability, star, ladder, bush, counter, damage and terrain tags need no format change either. Sheets F and G behave exactly like B-E: 16x16 grids stored as two 8-wide halves, non-autotile, default to map layer 3, and participate in auto-layer stacking. Slot 11 is deliberately left unused — the pre-v8 renderer packs sheets four to a 2048px texture with `MAX_GL_TEXTURES = 3` and UltraMode7 reimplements that packing as `setNumber >> 2`, so slots 0-11 stay inside those assumptions while slot 12 would break them. Stored `tilesetNames` arrays are never migrated: an MZ-authored tileset keeps its nine entries and grows only when a slot beyond it is actually assigned, so a project that does not use F/G writes byte-identical `Tilesets.json`. Assignment goes through `RRTilesetSheets.setNameAt`, which fills any skipped slot with `''` rather than leaving a hole, because `JSON.stringify` emits holes as `null` and the runtime hands every entry of that array to `ImageManager.loadTileset`. The slot table, band bounds and sheet-base map live in the new `src/utils/TilesetSheets.js` and replace four duplicated `['A1'..'E']` literals; the map editor's four copy-pasted B/C/D/E tile-ID cases collapse into one case driven by that table. Coverage in `tileset-extended-sheets.test.cjs`, including a sweep asserting no authored map in the bundled Demo already uses the band.

- Collapsible event block structures: `Conditional Branch` (111/412), `Show Choices` (102/404), and `Loop` (112/413) render a fold arrow in the same slot and with the same affordance as the existing plugin-command expander. `findBlockEndIndex` matches the terminator on indent rather than by counting openers, so it agrees with the indent-aware structure parsing the rest of the editor uses, and a nested branch closing first cannot be mistaken for the outer one's end. Collapsed state is held in a `WeakSet` keyed on the opening command **object**, not its index: inserting or deleting commands earlier in the page shifts every later index, so an index key would leave the fold behind on an unrelated command. `collapsedHiddenIndices` scans outermost-first, so an inner block nested inside a folded one keeps its own state for when the outer reopens. A folded row carries a badge with the hidden line count so it is never mistaken for an empty branch, and a malformed structure with no terminator stays expanded rather than swallowing the remainder of the list. Coverage in `event-command-collapse.test.cjs`.
- Persisted event fold state: `EventCollapsePreferences` stores folds in `localStorage` under `rpg-reactor.eventCollapsedBlocks`, scoped by project path, map, event, and page index, so pages do not share state. Only deliberate folds are recorded and a fully expanded page deletes its record rather than storing an empty list, which keeps "everything open" the default for pages that have never been touched. Command objects are rebuilt from JSON on load and cannot be the persisted key, so entries are `index:code:indent`: pinning the code and indent alongside the position makes a stale entry self-correcting, since a page edited since the fold was saved simply fails to match and renders expanded instead of folding whatever unrelated command moved into that slot. Hydration runs once per page rather than per render — the live `WeakSet` remains authoritative within a session, tracking commands through edits, while the positional keys are rewritten from current indices on every toggle. Malformed or non-object storage degrades to fully expanded. `clearProject` drops a deleted project's pages. Coverage in `event-collapse-preferences.test.cjs`.

- Destructive map resize confirmation: `analyzeMapResize` reports the populated tiles falling outside the new bounds and the events that would be deleted, and `saveMapProperties` aborts without touching the map unless the listed loss is confirmed. Events outside the new bounds are now removed rather than left at coordinates the map no longer has, where they were invisible to the editor.
- Anchored map resize: a nine-cell picker in Map Properties chooses which corner or edge existing content keeps, so a map can grow from the top or left. `computeResizeOffset` turns the anchor into a tile offset and `resizeMapData` walks the destination, letting one expression serve every anchor; `top-left` yields a zero offset and is byte-identical to the previous top-left-only behavior, and remains the default on every open. Tiles and events move together, direct-designation Set Event Location commands on the map are shifted, and `System.json` player/boat/ship/airship starts on that map are updated. A non-zero offset also scans every other map file and Common Events for direct-designation Transfer Player (201) and Set Vehicle Location (202) commands targeting the resized map and offers to shift them, listing where they were found and naming any map that could not be read. Variable-designation commands resolve at runtime and are left alone. A live hint under the picker shows the offset and pending loss as the size fields change; `countTilesOutsideResize` short-circuits when the old rectangle lands wholly inside the new one, so the common grow case does not rescan six planes per keystroke.
### Removed

- The unreachable standalone tileset editor. `main.js` carried a `showTilesetEditor`/`closeTilesetEditor` pair that constructed `new TilesetEditor(...)` — a class that does not exist in `editor/src` and is loaded by no script tag, so the call would have thrown `ReferenceError` had anything invoked it. Nothing did: the two callbacks were passed into `DatabaseEditorUI`, which reads `updateStatus`, `getTilemapManager`, `showTypesEditor` and `showTermsEditor` from that bag and never the tileset pair. That dead entry point was the only route into `DatabaseTilesetEditor.initializeUI` and everything below it, so 19 methods — 1,220 lines, roughly 39% of the file — were reachable from nowhere. Among them was `drawFlagOverlays`, whose flag-offset table disagreed with the correct one in `getTileIndexForImage` on **every** sheet (A1 at 0 rather than 2048, A5 at 5888 rather than 1536, B at 6144 rather than 0) and which ignored the 48-slot stride autotile kinds occupy; had that UI ever been revived it would have drawn every passability marker from the wrong tile. A second pass removed `renderTilesetList` and `loadTilesetPreviews`, which survived on paper but queried `#tileset-list`, `.image-preview`, `.image-filename` and `.clear-image-btn` — elements only the deleted UI ever created, so both could only no-op — along with the `#tileset-name-input` fallback that the compact UI's own field had superseded. Reachability was recomputed from the three entry points `DatabaseEditorUI` actually calls (`constructor`, `cleanupListKeyHandler`, `showTilesetEditorDetail`, the last of which reaches `initializeCompactUI` through a nested instance of the same class): 35 methods remain and every one is reachable. Two tests were pinning the removed duplicates — a second tileset-only copy of the 250-row lazy-list batching that `DatabaseEditorUI` already provides generically for every database type, and the second of two terrain-tag readers — and now pin the single surviving implementation.

### Changed

- Bumped the current development version to RPG Reactor 0.96.0.
- Tileset layer list density and the empty-tab affordance. Eleven slots did not fit the left column: rows carried a 32px thumbnail with 6px padding and margin, and the list took a `flex: 1` half share of a column it split with the Flags panel, so it scrolled while the panel below had room to spare. Rows are now ~32px (22px thumbnail, 3px margin) and the list is `flex: 0 0 auto`, sizing to its contents and leaving the remainder to Flags. The "Normal (B-E)" heading became "Normal (B-G)", which the localization source audit correctly rejected as an untranslated phrase; the key and its letter range were updated across all seventeen non-English locales, with the Greek entry's transliterated `Β-Ε` corrected to the Latin `B-G` the tabs themselves are labelled with. An unassigned tab rendered nothing but a line of text, leaving double-clicking a row in the left column as the only way to assign a sheet; it now offers a **Choose Image** button in that dead space, using the existing translated phrase rather than introducing one. B-G are single-slot tabs and get one button; the A tab spans A1-A5 and gets one per sublayer rather than guessing which was meant.
- The tileset image picker uses the shared `rr-modal-*` chrome and the shared searchable browser. It was a hand-rolled overlay with an inline header, a red Close button matching nothing else in the editor, and a file list built one `div` at a time with its own hover handling and no search. It now composes `rr-modal-overlay`/`-header`/`-title`/`-close`/`-body`/`-footer` and delegates the list to `RRPickerIndex.createBrowser`, gaining live name search, Unicode section rails, sticky headers and keyboard selection for free. It opens on the layer's current sheet and scrolls it into view; Escape, the close button, Cancel and a backdrop click all dismiss it, and the document-level key handler is removed on close. Assignment funnels through a single `confirm()` reachable from a row double-click, a preview double-click, or the footer button, which starts disabled and cannot fire without a selection. A pinned **(None)** row sits above the browser rather than inside it, so clearing a slot cannot be filtered out of reach by the search box; because `''` is a legitimate selection meaning "clear this slot", the no-selection sentinel is `null` and the guard is an explicit null check rather than a falsiness test, which would have made (None) silently do nothing. The list column is a flex column holding that pinned row plus the browser, and the browser's own `height: 100%` is cleared before it is given a flex basis — the two rules cannot share a column, and leaving both in place stops the inner list scrolling and takes the section rail with it. The **+** button on each layer row is no longer gated on the slot being empty, since swapping an assigned sheet wants the same affordance. The (None) row's selected state uses `--color-accent-tint-15` and `--color-accent-border-strong` rather than `--color-selection-deep`, which is a fixed `#094771` that does not track the active palette and so read as generic blue against the gold accent text.
- Tileset passability markers are legible over any artwork. They are painted directly onto the tile art, so a pale glyph on pale ground — or the red X over red brickwork — vanished into it. `drawFlagGlyph` strokes each marker in near-black before filling it, with `lineJoin: round` so the corners of X and the star do not spike, and restores `strokeStyle`/`lineWidth`/`lineJoin` because the caller keeps drawing afterwards. All five markers (O, X, star, damage, terrain tag) route through it, and the O and X fills go from 0.6/0.8 alpha to 0.95 now that the outline supplies the separation rather than the wash. The remaining markers are shapes rather than text and get explicit edges through three primitives: `drawFlagDot` rims a filled circle, `drawFlagArrow` traces each chevron dark-and-wide before laying the colour over it, and `drawFlagRect` borders a filled rectangle. That covers the four blocked-direction dots, the four passable-direction arrows, the ladder stile, the bush berry and the counter bar; the ladder rungs and the bush centre stay unoutlined because they sit inside an already-edged shape and rimming them at 10x2px would be noise. A first attempt gave the shapes a soft `shadowBlur` instead, which proved too weak against busy or same-hued tile art — the hard edge is what makes them legible, and dropping the shadow also removes a per-tile canvas state change. `drawFlagArrow` restores `lineCap`/`lineJoin` for the same reason `drawFlagGlyph` restores its stroke state: both run inside a per-tile loop that keeps drawing afterwards. Coverage in `tileset-image-picker.test.cjs`, including a guard that `PickerIndex.js` and `AssetFiles.js` load before this file.
- Tileset edits reach the map and palette without a reload. `TilemapManager.currentTileset` is captured when a map opens, so a sheet assigned afterwards was absent from the array `loadTilesetImages` walks and its texture never loaded. `refreshTilesetImages` diffs the incoming record against the held one, reloads only the slots whose filename changed, drops only the `textureCache`/`a1AnimationCache` entries keyed to those slots, and repaints only when `mapUsesSheets` finds a tile currently on the map drawn from one of them — so assigning a sheet to a previously empty slot, the common case, costs one image load and no repaint. A first attempt called `renderMap()` unconditionally on every tileset save, which froze a 200x200 map; that is what this avoids. `ProjectController.refreshTilesetSurfaces` drives both surfaces and ignores saves against a tileset the open map does not use, and the `rr-tileset-saved` listener is installed once and debounced by 150ms because the tileset editor announces a save on every flag edit as well as on an image assignment. Coverage in `tileset-refresh-on-save.test.cjs`.
- `MapEditor.previewLayer` is a `PIXI.Container` with a `previewGraphics` child, rather than a `Graphics` doing both jobs. It is parented to on every pointer move, and PIXI v8 deprecated parenting to a Graphics, so each `addChild` ran a deprecation path on a node that does not batch like a container. Three sites also allocated a fresh `PIXI.Graphics` per tile — per pointer move, for every tile in a stamp or circle radius — purely to get draw ordering; `previewGraphics` is the layer's first child and already renders behind the sprites added after it, so they draw into it instead. `_resetPreviewLayer` replaces the old `clear()` plus `removeChildren()` pairs, which would now remove the graphics child and silently kill every rectangle drawn afterwards; it clears the vectors, and destroys the discarded sprites rather than detaching them, explicitly preserving their textures since those are shared with the tileset caches. Coverage in `map-preview-layer.test.cjs`.
- Map Properties identifies the map it is editing. The heading composes as `<base> | <id>: <name>` — `Map Properties | 0211: Canite City`, or the New Map heading with the id the map will take, which creation has already reserved. The name is read from the live `map-name-input` rather than the map record, so renaming in General Settings retitles the modal as you type while Cancel still discards the edit and the heading never claims an unsaved rename. It is written through `textContent`, so a project-authored map name containing markup cannot reach the editor's own interface as HTML. The heading is composed after `populateMapPropertiesForm` has filled the field, since composing earlier would read an empty name. The input is static in the document and outlives the modal, so its listener is rebound by stored reference — `removeEventListener` then `addEventListener` — rather than by the clone-and-replace the modal's buttons use: cloning restores the element's value attribute and would discard the name written into it moments earlier, and re-adding blind would stack a handler per open. A map with no id degrades to the name instead of printing a padded `000`. Coverage in `map-properties-title.test.cjs`.
- Map Properties tileset dropdown entries lead with the tileset id, `0211: Canite City`, so an entry can be matched to its numbered row in the database. Padding is four digits to match the Change Tileset command's picker, which already labelled tilesets that way; the two list the same database and would otherwise number the same record differently, and a test pins them together. The option `value` remains the bare id, so the prefix is presentation only and cannot reach the saved `tilesetId`. A tileset with no name now shows its id plus the shared "unnamed" label rather than the old `Tileset 7` fallback, which would have read as `0007: Tileset 7`.
- Map Properties sizing and layout density: the dialog was a fixed `height: 85vh` regardless of content, so short configurations reserved a band of empty space beneath them while expanding BGM, BGS, and Battleback overflowed and forced scrolling. It is now `width: min(96vw, 1400px)` with `max-height: 92vh` and an auto height, so it shrinks to its contents and scrolls only on genuine overflow. Map Name/Display Name and Tileset/Scroll Type each collapse into a two-column row. The hand-built left/right wrappers are gone: the panels are direct children of a `.map-props-columns` container using CSS multi-column (`columns: 340px auto`) with `break-inside: avoid`, so they pack and balance into two columns, dropping to one below roughly 700px. The count is capped at two deliberately: General Settings is a single indivisible tall panel, so a third column cannot balance against it and instead strands a short panel on its own beside a full-height gap. Grid was the wrong primitive here — it aligns rows, so the tall General Settings panel reserved matching dead space beside every shorter one. The Note textarea no longer derives its height from a stretched parent and gained `resize: vertical`. `map-properties-layout.test.cjs` pins each control appearing exactly once, the sizing rules, and the packing behavior.

- Standing geometry in 3D is billboarded rather than fixed. `Reactor3D.Geometry.build` now emits cut-outs into their own groups, flagged `billboard`, whose `positions` hold the object's anchor repeated per vertex and whose `offsets` hold each corner in tiles; `Reactor3D.billboardMaterial` assembles the quad in the vertex shader on the camera's own right and up axes, read back into world space from the first two columns of `viewMatrix`. The up axis is `mix(worldUp, cameraUp, Reactor3D.BILLBOARD_TILT)`, and `BILLBOARD_TILT` is 0 — upright, yaw only, matching what `faceCamera` has always done for the event sprites. Any lean displaces a cut-out's art horizontally from its anchor by `height * |up.xz|`, which swings with the azimuth: at 0.75 and a 45 degree camera, a six-tile object's top sits 3.4 tiles out and moves 4.8 tiles through a quarter turn, which reads as the object drifting off its own cells and as everything sitting above the ground. At 0 that displacement is identically zero. The degenerate overhead case that leaning was meant to solve is handled by clamping `orbit` to 72 degrees instead. `polygonOffset` handles the coplanar case that creates, where a flat-lying cut-out shares a plane with the ground under it. This replaced a fixed south-facing plane plus a second plane crossing it at right angles, which existed only so an object did not vanish edge-on and which showed as a seam through the art at intermediate angles. Hinging at the ★ flag was tried first and does not work: on the Infernis gantry only the top of three rows is starred, since that is the only row that must overlap a character behind it, so ★ is a lower bound on height and not a partition of the prop.

- A3 and the A4 wall rows derive as `CLASS_SCENERY` rather than `CLASS_UPRIGHT`. As cut-outs they were built per column on the run's southern face, so on Map564 (a 79x111 labyrinth, 4,800 A3 cells) the overhead view showed bare floor with slivers where the maze should be, and obliquely a wall block eight cells deep stacked into an eight-unit tower. Raised, the walled area is solid, the corridors are carved from it, and the vertical faces come from the wall pass — which takes `stack[0]`, the wall autotile itself, since a dungeon paints walls on layer 0. The fixed-plane path in `Geometry.build` is kept for a tile an author classifies upright by hand.

- Declared 3D objects in `Tilesets.r3d.json`: an `objects` list per tileset, each `{tile, w, h, roles}`, where `tile` is the top-left of a rectangle on the sheet and `roles` is `w * h` characters of `S` (stands) or `F` (lies flat). `Tileset3DClass` gains `objectAt`, `roleOf`, `defineObject`, `clearObject` and `cycleRole`; `Reactor3D` mirrors `objectAt`/`tileRole` and `uprightPredicate` returns false for an `F` tile, so a role overrides a class. `Geometry.uprightObjects` takes a `declaredAt` lookup and groups declared tiles by instance origin — a cell's map position minus its position within the object — which is exact, before falling back to the adjacency guess for anything undeclared. A synthetic case shows why: tiles 8-9 and 10-11 painted side by side group as one four-wide object by adjacency and as two by declaration. The generator seeds a declaration per solid rectangular block of standing prop art. Shift-click two corners in the 3D Shape editor to declare, shift-click a declared tile to clear, alt-click to flip a role; declared objects draw as a yellow outline with a bar on flat cells. Coverage in `tileset-3d-class.test.cjs` and `reactor-3d-geometry.test.cjs`.

- 3D authoring is tool-based and applied by dragging a rectangle. `tile3dTools`/`tile3dToolbar` render a palette into the key panel, `attachTile3DDrag` owns the pointer on every sheet canvas, and `applyTile3DTool` applies the selected tool across `dragBounds`. `handleCompactCanvasClick` no longer handles `tile3d` at all — a click is a 1x1 drag. Cycling on click left no way to inspect a tile without altering it, and counting corners was the wrong shape for declaring a rectangle. The drag scales the pointer by `canvas.width / rect.width`, since the sheet is laid out at a different size from its backing store. `select` changes nothing, `object` declares, `erase` undeclares, `role` decides once for the whole rectangle rather than toggling per tile so a mixed selection is not scrambled.

- A5 is treated as a picture sheet rather than an autotile throughout: `Tileset3DClass.isPictureTile` and `Reactor3D.isPictureTile` admit 1-2047, `sheetCell`/`tileAtCell` address A5 as an eight-wide grid at `setNumber` 4 with no half-sheet split, `Geometry.samePicture` and `uprightObjects` group it with B-G, and the fixed-plane wall path narrows to `>= 2048`. The old `< 1536` cutoff put A5 with the autotiles, so an A5 wall could not be declared as an object at all.

- `previewArtSource` reads an autotile's cell from `cachedBaseCanvas` — the entry in `imageCache` the tab canvas is composed from — rather than the tab canvas itself, which has the flag overlay drawn onto it; the preview was showing the class chevron as part of the art. `drawTile3DPreview` derives its cell size from the object's extent instead of a fixed 22px.

- `applyTile3DTool` refuses a 1x1 `object` drag over a tile that is already declared, refuses `object`/`erase`/`role` on autotile indices with a reason on the console, and sets `selected3dRect` to the declared object's rectangle when the selection falls inside one — the overlay draws that rather than the clicked cell. Coverage in `tileset-3d-authoring.test.cjs`, including that a class painted on an A tab lands on the kind's base id and reads back from every shape of it.

- An upright object's anchor is the centre of its footprint in x *and* z, not the middle of its southern row. The anchor is the axis the billboard rotates about, so an off-centre one makes the object orbit that point: a six-deep object swung two and a half tiles around its own front edge through a quarter turn. Height stays separate — `base` is still `surfaceAt` at the southern row, the ground the object faces — and conflating the two is what made the southern row look correct for a while. `drawTile3DPreview` had the same bug and the same fix.

- `Geometry.build` computes a `roofLift` pass before `surfaceAt`: connected regions of A3/A4 art that are not themselves raised, and that touch a raised cell, take that cell's height. Walls raise into a mass through `CLASS_SCENERY`, and the roof behind them is ordinary flat terrain, so a building rendered as a block with its roof lying on the ground beside it. Coverage in `reactor-3d-geometry.test.cjs`.

- `drawTile3DPreview` projects a slanted, gridded ground plane that rotates with the drag, and `previewArtSource` reads an autotile's art from the rendered A-tab palette rather than from a sheet — the A tabs compose one cell per kind, so sheet addressing drew nothing. A cut-out's own picture cannot change as the view turns, which is why the ground had to carry the rotation.

- `drawTile3DPreview` no longer foreshortens or column-reverses as it turns. A yaw-billboard presents the same picture from every azimuth, so only the ground plane and the flat-role pieces rotate; treating the object as solid mirrored its columns and produced a broken silhouette from behind.

- `Tileset3DClass.defineObject` rejects tile 0, which is the engine's "no tile". `objectAt` already refused it, so a declaration anchored there could be created and never found again.

- Key rows are canvases drawn by `drawKeyMark`, which reuses `drawFlagDot`/`drawFlagArrow`/`drawFlagRect`/`drawBushMark` — the same helpers the tile overlay calls. The first version used tinted `<span>`s and came out blank for Ladder, Bush and Counter, whose overlays are glyphs rather than tints, and it could have drifted from the overlay without anything noticing. `drawBushMark` replaces the bush's `drawFlagDot`, since a green dot was indistinguishable from the direction dots.

- The 3D class marker draws only on a declared object's top-left cell (`markHere`); the tint still covers every cell. Drawn per cell, a 2x2 mountain read as four separate mountains — exactly what the declaration exists to deny.

- `DatabaseTilesetEditor.flagKey` renders a per-mode key into `#flag-mode-key`, and `refreshTile3DPreview` draws the selected tile or declared object into `#tile3d-preview` — both in the margins the centred sheet was already leaving empty, so nothing the author was looking at moves. The preview is an oblique diagram drawn on a 2D canvas from the tile's own art rather than a real render: showing one tile through the actual renderer means loading three.js, the sheets and a scene, and what needs checking is which parts stand and which lie flat. Both panels are English for now — routing them adds nineteen phrases across seventeen locales and the wording is still settling. Coverage in `tileset-3d-authoring.test.cjs`.

- `DatabaseTilesetEditor.flagIcon` draws an inline SVG for each flag mode, replacing the ASCII prefixes that only three of the eight buttons had. One 24-unit grid, `currentColor` so a selected button's icon follows its label, and each drawn as a few strokes because these render at 16px where anything finer smudges — checked by rasterising at 16 and 96. `tileset-3d-authoring.test.cjs` asserts every mode has one and that each button renders it.

- Cut-outs are grouped into whole objects. `Geometry.uprightObjects` replaces the per-column runs: cells join an object when they are adjacent on the map *and* adjacent the same way on the sheet, which is what makes a stamped picture a picture. Plain 4-connectivity was tried first and merged 408 cells of unrelated props across 44x27 tiles into one anchor on the world map; each object turns about a single axis through the middle of its southern row, so a wide structure holds together instead of fanning into one card per column. The anchor is what the object's position reads as, and both other candidates were visibly wrong: on the southern *edge* a five-wide structure sat over its cells from the south and a tile clear of them from the east, and on the footprint centre its base hung above the ground in front of it at a low camera. Autotile uprights are excluded and keep the fixed-plane path — a wall belongs to a building and has a real facing, and swinging it to the camera would rotate the building.

- B-E props derive as `UPRIGHT` when `standsUp` holds — impassable on all four sides, or starred — instead of requiring the star flag alone. On Map596 that flag test left tile 28 (a lone tree, 147 cells), 40 and 48 (mountains), 112 and 122 (landed ships) and 92 (scrub) lying flat while the canopy beside them stood: ★ is set only where a character walks *behind* something, so it is a lower bound on height and misses every object a character walks in front of. The test runs per block of art via `sheetBlocks`, so one qualifying piece raises the whole picture — the Infernis gantry is three rows tall and only its top row is starred, and per tile that stood its head up and left its legs on the floor. Pits and craters are the known false positive: the art blocks the way like an object and is a hole in the ground, so it wants `Flat` set by hand, once per tileset.

- A fourth 3D class, `CLASS_FOLIAGE`, for terrain that is a repeated object rather than a mass. It stands cut-outs on the cell taken from the terrain's lone variant — `classKey(id) + 46` for an autotile, since shape 46 is what MZ draws for a single isolated cell, and a recorded `standIns` entry for a B-E tile, which the generator guesses as the same-sized block directly above the tiling art on the sheet. Stand-ins are stored as `[topLeftTile, width, height]`: a lone variant is usually drawn over a block, and sampling only its first tile stood up the top-left quarter of each tree. `foliageDensity` cut-outs per cell (1 by default — a cell is one instance of the terrain, so it gets one object; several per cell multiplied the geometry to break up a grid the position hash already breaks up), each scaled 0.75-1.25 and displaced by up to `foliageSpread` from the centre through a position hash, so a wood is scattered but rebuilds identically; `foliageLift` raises the cell 0.3 so the wood has a visible edge; and `foliageFloor` is off, so the tiling art is not laid flat as well — it is the same terrain seen from above, so drawing both draws each cell twice and shows as a mat of canopy at the feet of the trees. Two alternatives were built and rejected against renders: keeping the floor art matched 2D from overhead and produced the mat, and capping the interior of a mass with the tiling art while standing cut-outs only on its border — `Geometry`'s `foliageBorder`, kept — was ideal overhead and made forests into flat terraces with a tree fringe from the ground. The 3D Shape editor cycles Flat → Upright → Scenery → Foliage → Auto. Coverage in `reactor-3d-geometry.test.cjs` and `tileset-3d-class.test.cjs`.

### Fixed

- Billboard cut-outs rendering dark and unfogged. `Reactor3D.billboardMaterial` was a `ShaderMaterial` whose fragment shader wrote the texel straight to `gl_FragColor`, skipping three.js's `colorspace_fragment` conversion from the texture's colour space to the renderer's output — so a tree was visibly darker than the same art lying flat beside it — and skipping the fog chunks, so the editor's `THREE.Fog` never reached it. It is a `MeshBasicMaterial` with an `onBeforeCompile` that replaces `#include <begin_vertex>`, keeping every other chunk the flat tiles use; `customProgramCacheKey` stops three.js compiling a program per material, since it cannot see the injected code.

- Vertical faces in 3D sampling the wrong layer. `Geometry.build` took a cliff face's art from `stack[stack.length - 1]`, the topmost layer of the cell, and above a step that is normally a decoration whose art is transparent everywhere the decoration is not — so the face alpha-tested away to nothing and a raised region stood on a rim of holes. Faces take `stack[0]` now, which is the terrain.

- 3D tile classification derived from the tileset flags standing terrain on end. `Reactor3D.uprightPredicate` treats an explicit `CLASS_UPRIGHT` as authored and `uprightRuns` therefore exempts it from `AUTO_MAX_FACADE` — deliberately, since a tileset may draw a tower fifty tiles tall as one prop — so a `Tilesets.r3d.json` filled in from `flag & 0x10 || (flag & 0x0f) === 0x0f` had no ceiling at all. On Map596 (200x200) that produced 685 facades, 64 of them past the cap and the tallest sixteen tiles, and connected-region analysis put 1,587 of the 2,337 standing cells inside regions of 4x4 or larger — terrain, not props. `build-scripts/derive-tileset-3d-classes.cjs` derives the file from map usage instead. Each B-E placement is judged in a 5x5 neighbourhood: covered ground whose tiles repeat is terrain (`SCENERY`), sparse or non-repeating company is a prop, and a tile reading as terrain in a quarter of its placements is terrain everywhere, since a misjudged prop rises a tile while a misjudged forest becomes a wall. The neighbourhood replaced a connected-region test that let a crater painted at a forest's edge inherit the forest's verdict and rise on a plinth. `0x10` alone decides height for props — impassable covers craters and rubble too, and honouring it put the map on stilts — and autotiles are read off the sheet: A1 flat whatever its flags, A3 and the A4 wall rows upright, blocked A2 and A4 roof rows raised as a mass. Only painted tiles are written. Coverage in `tileset-3d-derivation.test.cjs`.

- A tile selection surviving a palette layer switch. `selectLayer` reassigned `currentLayer` and re-rendered, but never touched `selectedTiles`, so the entries — sheet coordinates tagged with the layer they were taken from — stayed live. The redrawn palette had nothing to highlight, since the selection belonged to a sheet no longer on screen, while a click still resolved those entries against their original layer and painted its tiles. The selection is now cleared when the layer actually changes, the readout is reset to "No tiles selected" to match, and any hover preview built from it is dropped, since nothing rebuilds one until the pointer moves again. Re-asserting the current layer leaves the selection alone, and the clear is guarded on the outgoing value, so it has to run before `currentLayer` is reassigned or every switch would read as a no-op. Coverage in `palette-layer-switch.test.cjs`.

- Tileset sheets F and G erasing instead of painting. `MapEditor` carries two routines that turn a palette position into a tile id — `getTileIdFromPalettePosition` and `getBaseTileIdFromPalettePosition` — and only the first was extended when F/G landed. The second fell through its `switch` default and returned `0`, which is the empty tile, so committing a placement wiped the cell. Everything that merely *displays* a tile resolves its texture separately, which is why the palette and the hover preview both looked correct and only painting failed. Both routines now share one case driven by `RRTilesetSheets.baseTileIdForSheet`, and `tileset-extended-sheets.test.cjs` asserts every sheet key is handled in both, so a future sheet cannot be added to one and forgotten in the other.

- Newly created database records missing fields the runtime reads unconditionally. `getDefaultTemplates` was diffed against the field sets of every record in the bundled RPG Maker-authored projects, and four types were short. **Skills** lacked `requiredWtypeId1`/`requiredWtypeId2`, and `Game_Actor.isSkillWtypeOk` opens with `wtypeId1 === 0 && wtypeId2 === 0` — `undefined === 0` is false and `undefined > 0` is false, so every clause failed and a skill created in Reactor could never be used by any actor. **Weapons** lacked `etypeId`, which `changeEquip` compares against `equipSlots()[slotId]`, so a new weapon never appeared in the equip list and equipping it silently did nothing. **Items** lacked `tpGain`, and `applyItemUserEffect` computes `Math.floor(item.tpGain * tcr)`, so using one set the user's TP to `NaN` for the rest of the battle. **States** lacked `motion` and `overlay`, which `stateMotionIndex`/`stateOverlayIndex` return directly to the battler sprites, so a new state produced no pose and no overlay. The skill template also invented `message3`/`message4`, which no authored skill carries, and omitted `messageType`. This reached existing projects too: `createBlankDatabaseEntry` backs both the Clear action and the repair pass for null slots. The derived field and command shapes are vendored in `tests/helpers/authored-data-shapes.json` (regenerate with `helpers/derive-authored-data-shapes.cjs`) so the check runs in CI without the private project fixtures. Coverage in `database-record-templates.test.cjs`.

- Scroll Map dropping Wait for Completion: `command204` reads `params[3]` to decide `setWaitMode("scroll")`, but `ScrollMapEditor` had no control for it, read only `params[0..2]` when opening a command, and emitted a three-element array. The option could therefore never be turned on, and opening an imported command that had it set and pressing OK silently discarded the flag. The editor now carries `wait` through load and save and offers the same checkbox the Tint Screen, Flash Screen, and Shake Screen editors use. A sweep comparing every command editor's emitted parameter count against the highest `params[n]` the matching `Game_Interpreter.commandNNN` reads found this to be the only editor writing an array the interpreter reads past the end of; that sweep now runs as a test. Coverage in `event-command-parameters.test.cjs`.

- The window title showing the bundled demo's name for every project. `installCompatibilityTitlebar` built its label from the literal string `RPG Reactor | Reactor One` and nothing ever wrote to it again, so the title was frozen at the demo project's name no matter what was open. `updateWindowTitle` composes the correct `app.title | gameTitle` and sets `document.title` and `nw.Window.get().title`, but the compatibility titlebar is a `<div>` — neither of those reaches it. The titlebar is now seeded from the live title at construction and rewritten by `updateWindowTitle`, so it follows project open, close, save and language change like the native one. It reproduces only under frameless compatibility mode (`?rrFrameless=1` / `?rrWineFrame=0`), which is the self-relaunch used for Wine/Proton — a normal framed window keeps the native titlebar and was never affected, which is why this showed up for packaged users and not in development. Coverage in `window-title.test.cjs`.

- Set Event Location's "Exchange with another event" reading and writing the wrong slots. `command203` uses `params[2]` as the **other character's id** — there is no map id in this command form — and `params[4]` as the direction. The editor parsed `params[2]` as a map id and invented an event id from `params[3] || 1`, labelled them "Map ID" and "Event ID", and emitted only four parameters, so the direction slot was truncated away on every save. Both authored instances in the bundled projects are `[charId, 2, otherCharId, 0, direction]`; the editor now loads and rebuilds them byte-identically, and offers a direction control in place of the invented map id.

- A1 waterfall kinds 9 and 11 drawn from the wrong table in map-image export. `drawAutotileToCanvas` gated the waterfall table on `Math.floor(tx / 4) === 1`, which is false for exactly those two kinds — they fell through to the floor table and sampled a different 96px band of the sheet. The engine (`reactor_core.js`) and all three sibling render paths select it unconditionally, and `renderAutotile` in the same file carries a comment saying so. Kind 9 appears **2,149 times across 21 maps** in the bundled projects, kind 11 **74 times across 5**. Affected Save Map as Image and the right-drag map-stamp preview.

- The eraser swallowing the bucket fill. The pointerdown dispatch let `eraserMode` claim the click ahead of the tool branches, so selecting eraser + bucket erased a single cell like the pencil. `eraseFillArea` — 37 lines, fully implemented and correct — was unreachable from the UI. The eraser is now treated as a modifier on the active tool rather than a tool of its own, matching how the rectangle and circle tools already handled it.

- The web editor had no keyboard shortcuts at all. `setupKeyboardShortcuts` opened with `if (typeof nw === 'undefined') return;`, but only the F5, F11 and F12 branches need NW.js — the early return also removed Ctrl+S, Ctrl+Z/Y, Ctrl+C/X/V and Delete. - Sidebar divider positions saved and then always discarded. `loadSavedSizes` runs once from `initialize()` — before any project is open — and skips `display: none` sections, which every id-bearing section is at that point. `refresh()`, which runs when sections become visible, never re-applied them. - Imported character sheets getting a different cell size per frame. The 3x4 crop loop rounded every cell boundary independently, so any sheet whose dimensions are not divisible by 3x4 produced adjacent cells differing by a pixel — and `RR_CG_drawTemplatePart` right-pads short rows rather than centring them, so the character shifted horizontally on the middle walk frame. The origin is still rounded per cell but the width and height are now shared, which makes every checked import uniform. Where the source image genuinely runs out of pixels on the last row, the normalizer below repairs the residue.

- "Normalize All Templates" reporting success while leaving frame heights unequal. `_padSheetInPlace` computed one sheet-wide `padTop`/`padBottom`, so a frame with fewer rows than the sheet maximum stayed short of the target while widths — which are padded per row — came out correct. Padding is now derived per frame. The 279 shipped part descriptors were already uniform; this only ever bit the user-import path.

- Map window culling parking windows that were still on screen. `_rrWindowDormant` tested only `child.x`/`child.y`, but `Window.prototype.move` assigns those as the **top-left corner** with `width`/`height` extending right and down — so a window wider than the 384px margin still overlapped the viewport while its corner sat outside it. Culled windows are *detached from the display tree*, not merely hidden, so the result is disappearance rather than a paint glitch. The character-sprite branch of the same method, sixty lines above, already carried exactly this correction with a comment explaining it; the window branch never got it. The predicate now culls on the drawn extent. Coverage in `window-culling.test.cjs`, which lifts the shipped predicate rather than restating it.

- A window stepped twice on the frame it was parked. `Spriteset_Base.update` cascades `update()` to every child before `updateOffscreenCulling` runs, and the catch-up loop then re-reached the window the first loop had just appended to the holder. - **Party-wide actor commands collapsed onto Actor 0001.** `Game_Interpreter.iterateActorId` branches on `param === 0` to mean *the entire party*, and nine command editors loaded that slot as `params[1] || 1` — 0 is falsy, so every party-wide command was rewritten to the first actor the moment it was opened, and the edit path writes the loaded value straight back. The actor dropdowns also started at index 1, so the value could not be expressed at all. In the bundled projects this covers **284 of 284** Change HP commands, **376 of 379** Recover All, 94 of 114 Change State and 3 of 7 Change Skill: open the inn's "Recover All → Entire Party" event, press OK, and from then on only Actor 0001 is healed. Opening one and pressing OK moved the message window to the bottom, and the dropdown showed the wrong value while open. - Fadeout BGM/BGS authored in frames while the engine reads seconds. `AudioManager.fadeOutBgm(params[0])` reaches `WebAudio._fadeOut`, which calls `linearRampToValueAtTime(0, currentTime + duration)` — a Web Audio API that takes **seconds**. `AudioCommandEditor` defaulted to `[60]` "= 1 second", divided by 60 on load and multiplied by 60 on save. Inserting the command with its default therefore produced a **60-second** fade, and a 5-second setting produced a five-minute one; conversely an imported MZ command reading `5` displayed as `0.083 s`. Every authored 242/246 in the corpus holds a small seconds count. The conversion is gone from the editor and from the command-list label, which had repeated the same assumption.

- Event graphics taken from the right half of a B–E tileset page saved the wrong tile. `TilesetPaletteViewer` presents those sheets as a 16-wide split and reports `x` in 0..15; `MapEditor.getBaseTileIdFromPalettePosition` folds `x >= 8` into `y += 16`, but `EventManager.convertToTileId` did not. Palette B (8,0) became tile 8 instead of 128 — a different tile entirely, written into `Map###.json` and shown wrongly in both the editor and the game. Right-half tiles are ordinary authoring territory: **132,054** placements against 214,715 left-half across the corpus. Verified by feeding both conversions through the engine's own `sx/sy` frame math.

- Plugin command metadata overwriting plugin parameter defaults. `parsePluginParameters` walked the annotation block without resetting on `@command`/`@arg`, so every `@default` belonging to a plugin **command argument** landed on the last real `@param`. `parsePluginParameterMetadata` has carried that guard all along, making this a two-parser divergence. Adding an affected plugin through the Plugin Manager wrote the wrong default to `js/plugins.js` — `debugMode: "1"` where `false` was declared (neither value the runtime's boolean check accepts), `"Gold Icon Index": "true"` where `163` was declared. A `resolveMusicSlot` helper now maps each row to the slot the engine reads, for both display and save.

- A newly created animation left `displayType` unset. `Spriteset_Base.isAnimationForEach` tests `animation.displayType === 0`, so an absent value is false and the animation plays **once at the centroid of the target group** instead of once per target — while the editor's own dropdown, which marks no option selected, displays the first entry and claims per-target. All **648** MZ-format authored animations carry the field. The record-template guard now separates MZ-format animations from MV-format ones, which had been diluting the required field set down to just `name`.

- The Traits and Effects tables in the Skill, Item, Weapon, Armor and State editors never refreshed after an edit. - Event page conditions written with the wrong type. `attachConditionListeners` decided how to store a value from the *element* type — `if (e.target.type === 'number') value = parseInt(value)` — which describes the control, not the field. Two consequences. A `<select>` reports type `select-one`, so **Actor** and **Item** conditions were stored as strings (`"3"`), where all 49,371 authored pages in the bundled projects hold numbers; the stock runtime tolerates this because JS object keys are strings, but any plugin comparing `page.conditions.actorId` strictly sees a mismatch, and the project no longer round-trips. More seriously, **clearing the variable-threshold field** stored `parseInt('')`, i.e. `NaN`, which `JSON.stringify` writes as `null`; the runtime's check is a bare `$gameVariables.value(c.variableId) < c.variableValue`, so `< null` is `< 0` and the page began meeting a condition it never had before. Coverage in `event-page-conditions.test.cjs`, including a check that every field the form exposes and authored data holds as a number is on the numeric list.

- Silent IndexedDB write failures in the web host: `createFileSystem` queued each `put`/`delete` promise into `pending` and attached only `.finally(() => pending.delete(operation))`. `finally` passes a rejection through rather than handling it, so a failed write produced an unhandled rejection **and** removed itself from `pending` before `flush()` awaited the set — `flush()` then resolved successfully with nothing written, while the in-memory `contents` map still held the new data.
