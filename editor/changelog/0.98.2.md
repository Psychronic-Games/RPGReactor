# RPG Reactor 0.98.2 - 2026-08-16

### Added

- **3D models animate through authored rules, and the Database has a 3D section to author them.** A model folder carries `model.json` naming its animation rules — spin (wheels roll with distance travelled and hold their angle at rest), swing (a hinge about a named part's own pivot), and bob — triggered always, at idle, while moving, or on demand by name. The readers preserve named-part ancestry and pivots (GLB before its hierarchy is baked flat; OBJ by splitting named groups into their own meshes), so one rule like `DEF-Wheel` turns all four wheels of a car about their axles. Database → 3D lists every model folder in the project, discovers its part names from the mesh — scene-graph plumbing (root/rig/scene wrappers that grab every mesh at once) and exporters' anonymous "Object" bucket are kept out of the list, and numbered siblings collapse into one group option (DEF-Wheel drives all four wheels) — edits the rule list with a live animated preview (Walk simulation, a Play button per action), and writes each model's own sidecar on every change, no hand-written JSON. Selecting a rule draws a box around exactly the meshes it drives with a live affected-part count, edits restart accumulated spin from rest, and a GLB's embedded clip count is surfaced. **Embedded clips play.** A GLB that carries animations keeps its node hierarchy live instead of being baked flat: joints stay real objects, skinned meshes ride a GPU skeleton, every instance rebinds to its own cloned bones, and each embedded clip is parsed into a playable animation. A "Clip" rule type in the 3D section plays a chosen clip through the same trigger system — always, at idle, while moving, or on demand from the Play Model Animation command — with crossfades between states; one-shot actions return to the ambient clip when done. A model whose clips are static poses (common in ripped character models — sas blue's 394 are an eye-test pose library) gets a pose system from the same rules. Sizing an animated model measures a CPU-skinned sample of its rest pose, the only size matching what renders — bone positions undersized a Source-style rig to a speck. The model list in the 3D section now uses the standard database list styling with a search box. A new Play Model Animation event command (under a fourth Reactor tab in the command picker, where Reactor-only commands will grow) triggers an action on this event, the player, or any event; it is stored as an MZ plugin command for "RPGReactor", so the data stays loadable everywhere and a stock MZ runtime simply ignores it. In the Demo, the Buick's wheels roll as it drives, and the monster-plant sways, pecks at idle, and bites on command.

- **Event Image can author a 3D model into the map sidecar.** Checking 3D opens `ModelGraphicPicker`: folder names under `3d/<folder>/source`, a WebGL orbit preview with the same rotation gizmo as the Animation Generator, size in tiles, and four placeable facing dots rather than snap-yaw buttons. Apply writes `map.reactor3d.events[id][page]`; the Event editor preview fills the leftover left column and turns with the page's Down/Left/Right/Up. Runtime `characterModelSpec` prefers that sidecar over `<r3d>` notes. Models occupy their ground AABB, do not block themselves, refuse a turn that would hit the player, and draw other characters as upright billboards so they pass in front or behind the mesh. A model collides as its true rotated rectangle at the yaw the mesh actually stands at — the authored spec rotation plus the front-mark aim, not the facing alone — so a character walks right up to an angled vehicle's body instead of being stopped tiles away at a bounding-box corner, and a model posed with an authored yaw no longer collides crosswise to its visible body. A gliding model keeps its trailing tiles occupied, a step that implies a turn is collision-tested in both body orientations against the player and other solid events, the mesh eases through turns at `MODEL_TURN_SPEED` instead of pivoting instantly — and a turn must clear the disc the body's corners sweep, in both swing directions, with the footprint covering the arc while the easing plays out — and character billboards draw right side up (three's default `flipY`, not the glTF convention). Leaned billboards — character sprites and tile cut-outs alike — write the depth of a vertical twin at their anchor (`straightenBillboardDepth`), so front/behind against real meshes settles per pixel by ground row instead of the lean tipping a sprite's head into the model behind it. On such maps the star-flagged tiles render inside that same depth buffer rather than as a flat composite pass, so a character in front of a tall structure occludes its top and one behind it is hidden; a stationary event on a facade cell — any priority — snaps to that wall's plane and is pulled just ahead of the coplanar wall art, so a console screen shows whole over its machine while a genuinely nearer character still occludes it by real depth, in front winning and behind hiding exactly as the camera sees it. A walking character standing on a facade's own footprint — pressed against a console, crossing a machine's apron rows — has their depth pushed just in front of that wall's plane, since the art on their cell draws under them in 2D; off the footprint, genuinely behind still means hidden. Character billboards also take the tile cut-outs' half-cell step towards the camera, and an above-characters event whose cell was stood into a facade anchors on that wall's recorded plane (`facadeAt`), lifted along the same leaning axis its quads use — so an event's art keeps the alignment it was authored with over tile art from every camera position instead of drifting off it towards the screen edges.

- **Looking around the model picker no longer edits the pose, and posing happens through rings around the model.** A plain drag used to rotate the model itself about camera-relative axes, so inspecting a model quietly baked pitch and roll into its authored angles and it stood crooked in game — which read as the face marks depending on the viewing angle; worse, once any roll existed a straight drag bled into all three angles at once and the model fought the hand. Left-drag orbits now, and the pose controls are three colour-coded rings wrapped around the model: grab a ring and the model follows the pointer around that one axis, the others untouched. The rings nest like a gimbal so each always matches the axis it will change, arcs passing behind the model hide behind it (a faint twin keeps the circle traceable), and they whisper until touched: dim at rest, brighter under the pointer, full only while held — when the other two fall away so the turn reads clearly. Placing a Front/Back/Left/Right dot hides the rings entirely, since the dots share the same colour palette — and an armed dot lands on a stationary left click again (making plain drags orbit had silently killed placement, since the old gate required the drag state that no longer exists). A near miss lands too: sparse meshes — foliage, struts — let the ray slip between triangles at spots the eye reads as on the model, and swallowing that click kept the mode armed with the rings away, so placement looked refused; the ray's entry into the model's bounds stands in, and a click past the bounds entirely — out where the rings circle — still lands on the model's side in the clicked direction. An armed canvas click is never swallowed — the dot lands the moment the button goes down, on the pressed pixel, so hand wobble can no longer turn a placement into an orbit. A drag that slips past the modal's edge also no longer cancels the picker outright (a browser click targets the common ancestor of press and release, so escaping the preview "clicked" the backdrop and threw away the dots); closing by backdrop needs the press and the release both out there. The floating gizmo ball and controls strip no longer stand between the pointer and the scene: the strip's transparent gaps pass clicks through, and while a side is armed the gizmo ball goes inert and dim so a dot click lands on the model behind it — in a small window those widgets sit right over the model's base, and they were catching the very clicks that looked like placement refusing to work. A grab also lands on the ring the eye sees: rings are picked by screen distance to the drawn line, tie-broken at crossings by whichever ring is drawn on top, where fat invisible grab tubes previously sent a third of direct clicks to a ring visibly away from the pointer. Ctrl-/right-drag keeps a turntable nudge (horizontal turns, vertical tips — never a camera-axis tumble), the X/Y/Z fields still take typed angles, and new Upright / Reset buttons rescue a drifted pose — Upright keeps the turn and stands the model up.
- **OBJ models render with their textures.** The OBJ reader now keeps texture coordinates (welding position/uv corners into one attribute), the picker names a colour map from the model's `textures/` folder — preferring the colour pass over normal/emissive companions — and the sidecar carries that choice to the runtime, so a plant that shipped as OBJ + JPG stands textured in the picker, the event editor's preview (which also derives the map for specs saved before the sidecar carried one), and the game. STL/FBX/DXF/3MF/USDZ gain the same texture path where their readers produce UVs.
- **Model files keep whatever extension case they shipped with.** Exporters write `Plant_001.OBJ`; the picker's lowercase-only listing rule hid such files and the folder read as empty, so OBJ models seemed unsupported. The model picker now lists any-case extensions and the sidecar records the real filename; a note-based spec with no extension also probes upper-case variants at load.
- **A 3D object spanning both palette halves selects and extends as one.** A B–G sheet is sixteen columns shown as two stacked eight-column halves, so a prop crossing column eight — a full-sheet reactor — is authored as two drags. Ctrl and Cmd now arm the extend gesture alongside Shift, the merged object's selection is stored in sheet coordinates and drawn as both display pieces, and after an extend the whole object stays highlighted instead of only the piece just added.
- **Arrow keys step through asset picker file lists.** In the character graphic picker — and every picker built on the shared file browser — Up/Down move the selection one file at a time with the preview following, scrolling the list only when the selection reaches its edge, instead of scrolling the pane out from under the reader. Home/End jump to the ends, and the keyboard is armed the moment the picker opens.
- **The tileset 3D preview turns when dragged and fits its pane.** Standing art is drawn as an upright plane that shears with the turning ground line, so a drag visibly swings the object instead of only sliding a parallelogram beneath a fixed picture; near edge-on it holds a readable width, as the in-game billboard does. The scale now answers to the pane's width, the ground's depth, and the slab's height at once — a fixed ten-pixel floor previously let a sixteen-row object tower off the top of the pane and read as off-centre.
- **The flag Key stays on screen while a tall sheet scrolls.** The Key column — and the passability brushes and 3D tool palette it hosts — is sticky within the sheet's scroll pane, so painting the bottom rows of a 32-row F sheet no longer means scrolling back up to switch marks.
- **The tileset passability Key doubles as a paint palette.** Clicking O, X, or ★ in the Key arms that mark: a click on the sheet writes it directly and a drag paints every tile the pointer crosses, with autotiles still mirroring across their 48 shapes. Clicking the armed mark again returns to the classic click-to-cycle. Re-crossing a tile mid-drag is idempotent, so a wobbly sweep cannot flip anything back.

### Fixed

- **Tiles no longer show crawling horizontal seams when the camera pans zoomed or at fractional positions.** The PIXI 8 tile mesh inset every tile's texture rect by half a texel, compressing 48 texel rows into a 47-row span — invisible at integer alignment, but the moment a camera plugin panned the map at fractional screen positions or any zoom was in play, one texel row per tile duplicated or dropped, and its position crawled with the pan ("warbly" seams). The inset is now a whisker (1/128 texel), just enough to keep a quad edge from sampling the neighbouring atlas row: at 2× zoom every texel row now doubles exactly, and integer-aligned rendering is pixel-identical to before.

- **A menu-background snapshot survives the next snap for plugin windows still showing it, and setting `blur` on a filter is quiet again.** MZ destroys the previous screen snapshot the moment a new one is taken; menu-background plugins cache it into their own window sprites (a game's save screen hit this), and under PIXI 8 the destroyed texture drops that sprite from the render with a destroyed/orphan console warning. Retired snapshots now pass through a three-deep trail before dying, so a cached background keeps drawing and memory stays bounded. PIXI 8 also kept `BlurFilter.blur` only as a deprecation wrapper that warns on use — VisuStella's picture effects set it every frame — so the compat layer replaces the accessor with a silent passthrough to `strength`.

- **The Web editor bundle fits browser storefronts' 1000-file upload cap again.** The zip had grown past it, and the bulk was library stock the bundled project never touches: battle-hud face skins for actors the project does not define, source .psd files, and a hundred unreferenced stock enemy battlers. The web packager now trims exactly those — the audio library, fog pack, and everything the sandbox browses stay — dropping the archive from over a thousand files to roughly 700. Extracted size comes down the same way: 3D model folders no map places (a 77MB rip among them) leave the web bundle, and the Character Generator's bulk-imported looseleaf style pack — 76MB of generated part data — stays out of the web editor bundle, which shrinks from 87MB to 11MB and parses at boot accordingly; the compact psychronic style ships, and the soundtrack is untouched. The extracted bundle lands near 426MB. Counts and sizes are a storefront's rule, not the build's: packaging always completes, reports its file count and extracted size, and warns past 1000 files or 500MB. Shipped templates also exclude any live project lock or playtest saves. The web editor also loads again at all: the desktop runtime-refresh check probed project files with synchronous reads the browser host reserves for preloaded files, and the uncaught throw froze the web editor on its splash screen — the web bundle bakes its runtime in at packaging time, so the check now stands down in the browser. And because browser-saved edits shadow the bundled project, a returning player kept seeing the OLD Reactor One after an update — its new content missing or broken; the bundle is stamped now, and when the stamp changes under stored edits the editor offers to load the new version up front instead of silently serving stale files.

- **A native-Windows GPU crash on the 3D map toggle now diagnoses and heals itself.** Checking 3D could take the whole editor down instantly on Windows proper (while fine under Wine/Proton) — a GPU-process death no error handler can see. Every activation stage is now breadcrumbed synchronously; a leftover breadcrumb at the next launch means 3D killed the last session, so the editor says so, records which rendering strategy was in flight, and the next attempt takes the other one — the PIXI-shared WebGL context and a dedicated context each dodge a different class of Windows driver crash. If both strategies have crashed on a machine, 3D refuses to arm rather than crash again. The breadcrumbs then caught the actual culprit on the first native report: the editor injected three.js as inline script text, which parses synchronously on the main thread — and V8's recursive parser overflows the ~1MB Windows main-thread stack on a 2MB bundle (STATUS_ACCESS_VIOLATION) while Linux's 8MB stacks never noticed. Libraries now load through Blob URLs with external-script semantics, compiled off the main thread; a library-stage crash also no longer blames a context strategy, since no context existed yet.

- **Effekseer effects no longer draw black squares and slabs — every blend mode lands on the real scene.** Effects drew on a transparent overlay canvas, and each blend mode broke its own way: additive layers wrote alpha into empty pixels so black-backed textures composited as opaque black squares, multiply and darkening layers darkened nothing into solid black, and distortion panes had no background to sample. While effects play, the overlay now carries a copy of the whole rendered scene and the effects draw ON that copy — the same shared-framebuffer semantics the stock runtime has; the copy is pixel-identical to what it covers, so it is invisible in itself. Distortion panes capture their backdrop from that copy, aligned to each effect's own viewport. Verified by playing all 120 Demo animations and grading screenshots for black growth: the black-square class is gone, and what remains dark is darkness effects doing their job.

- **Editing an event no longer strips its model's texture.** Opening the event editor rebuilt the model spec for its pending pages and dropped the `texture` field, so pressing OK after any change — movement, a switch, anything — rewrote the sidecar without the colour map and the model stood gray in game.

- **A plugin that replaces `Tilemap.prototype.update` no longer blanks the tile layer.** MultiTweaks' "Tilemap animation speed" option installs a copy of the stock MZ update body; PIXI v5 tolerated that because it invoked `updateTransform` itself during render, but the PIXI 8 runtime runs repaint from its update tail, so the replacement left `_addAllSpots` unreachable — a black map with sprites, windows, and a clean console. `Tilemap.initialize` now installs a v8 `onRender` fallback that runs the shared `_prepareV8Frame` when the frame reaches render unprepared; a frame stamp keeps preparation single-shot so the Project3 double-preparation seams cannot return.
- **Encrypted RPG Maker projects display their images and audio in the editor.** Deployed MV/MZ games ship `.png_`/`.ogg_` (or `.rpgmvp`/`.rpgmvo`) files, so an imported game opened as an empty checkerboard, the tileset palette threw drawing a 0x0 canvas, and character previews stayed blank. The desktop asset resolver now decrypts those files on the fly with the key from `System.json` — recovering the key from the constant PNG header when the entry is missing — and asset listings present encrypted files under their plain names. Filename lookups also fall back to a case-insensitive match, since Windows-authored projects freely reference `bell3` for `Bell3` and a Linux filesystem does not. The runtime gained the same case correction: a Bitmap or WebAudio load that 404s retries once with the on-disk casing before reporting an error.
- **The fading splash screen no longer swallows the first clicks on the map.** It kept intercepting pointer events while transparent until its display switched off; it now lets clicks through as soon as the fade begins.
- **Opening an existing Reactor project updates the runtime that Playtest and deployment actually execute.** Editor releases update the application, not the `js/reactor_*.js` files already copied into every project. That allowed the 0.98.1 editor to open and playtest a project still carrying 0.98.0's shader bridge: its translator removed the `filterArea` declaration and rewrote `.xy`, but left `.zw` references undeclared, producing the unchanged `Could not initialize shader` and invalid-program flood despite the fix being present in the editor's canonical runtime. `reactor_main.js` now carries the engine version. Before game data is loaded, an older Reactor project receives the current canonical runtime recursively, preserves `reactor_plugins.js` and unrelated plugin files, updates its Reactor metadata, and is not rewritten again on later opens at the same version. Raw RPG Maker projects remain untouched until the explicit Install Reactor Runtime action.
- **Learnable Skills, Effects, and Enemy Action Patterns are directly editable.** The Class learnings table was display-only, while Skill/Item Effects and Enemy Actions put Add behind an undiscoverable context menu. Each now has visible Add/Edit/Delete controls, row selection, double-click editing, and Enter/Delete handling. Class learning edits author level, skill, and note; enemy Add uses a transaction-safe draft instead of silently inserting Attack, and HP/MP action conditions are presented as percentages while retaining the runtime's fractional data.
- **Extended face sheets are selectable throughout the editor.** Four columns and 144px cells remain RPG Maker-compatible, but the row count now comes from the loaded image rather than a hard-coded two. Actor list/detail previews, the Actor face picker, both Show Text face pickers, message preview, and Change Actor Images can preserve and choose indexes above 7.
- **The Sprite-based animation type can author a new MV animation.** Format detection now follows the runtime and keys off the `frames` array rather than requiring Animation 1 to already have a filename. Switching from Effekseer creates one empty frame, leaves both sheet pickers usable, persists the conversion, maps MZ `color`/`duration` flashes to valid MV combined timings and back, preserves imported `pattern: -1` cells, and refuses a seventeenth cell that the MV runtime cannot draw. New records remain MZ-format until Sprite-based is selected.
- **Troop Plugin Commands use `PluginCommandEditor`.** Insertion and editing of both MV code 356 and MZ code 357 now expose the same plugin, command, annotation, and argument controls available on map and Common Event pages instead of raw JSON.
- **Map event creation exposes the interactions that were already intended.** Event-mode double-click accepts the browser's click count and a 500ms fallback instead of requiring two presses inside 300ms. Enter creates on the selected empty cell or edits its event; context-menu rows show shortcuts; Ctrl/Cmd+F opens event search; and event copy, cut, paste, undo, and redo support Command on macOS. The Conditional Branch selector groups the complete stock MZ set separately from Reactor Advanced input conditions while preserving all existing command shapes.
- **Quick Event Creation builds the four stock MZ conveniences from an empty Event-mode cell.** Transfer opens Reactor's visual map/location picker and authors direction and fade. Door and Treasure use the project character picker, automatically suggest matching project assets and sound effects when available, and generate stock movement-route animation. Treasure can award gold, an item, a weapon, or armor before enabling an opened-chest self-switch page. Inn authors the offer choices, gold condition and deduction, fade/wait/recover sequence, and insufficient-funds branch at the chosen project currency price. The modal owns only a draft: Cancel or Escape performs no map mutation, commit revalidates the map and cell, and the complete event is one Undo step.
- **Simplified Chinese no longer lets generated guesses override reviewed terminology.** The deep catalog now fills only missing phrases. Reviewed forms restore terms including `职业`, `会心`, `注释`, `公共事件`, HP/MP commands, quantity, and Close; Turkish text accidentally copied into Chinese toolbar keys is removed; and `zh_CN`, `zh-CN`, `zh-SG`, `zh-TW`, `zh-HK`, and `zh-MO` aliases resolve to the matching script locale.
- **Database layout responds to the detail pane, not the outer window.** Container queries collapse generic section grids and form rows when navigation and the record list leave too little room. Translated labels wrap instead of ellipsizing, and the specialized Actor, Class, and Enemy compositions now reflow too; Class parameter curves use intrinsic columns rather than forcing four narrow graphs into half the workspace.
- **One-line plugin annotations no longer glue `@text` and `@desc` into the parameter name.** MZ3D writes `@param spacer|graphics @text<bidi>@desc ===` on a single line so RPG Maker can treat the bidi marks as a blank label. Reactor took everything after `@param` as the name, so the Plugin Manager showed `spacer|graphics @text @desc` and could not match the saved `spacer|graphics` key. The header, struct, and default parsers now split every known annotation on a line and strip format characters from values. Those spacer rows render as a rule, not as an empty field labelled with the internal `spacer|graphics` name. Section titles such as Map Settings that only exist to parent other parameters no longer show an empty box either.
- **MZ3D keeps imported character models and hides the 2D sheet from `pixi_compat`.** Cropping GLB materials to a walk frame smashed the authored UVs into a solid blob. `installMz3dCompat` only hides the 2D map sprites MZ3D already turned off via `_tilemap.visible`.
